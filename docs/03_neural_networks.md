# 03 · 신경망 기초와 대체모델 설계

> **선수 지식**: [01 문서](01_power_flow_and_opf.md)의 조류계산·뉴턴-랩슨.
> 신경망 지식은 **하나도 필요 없습니다.** 여기서 처음부터 시작합니다.
> **읽고 나면**: 신경망이 무엇이고 어떻게 학습되는지, 왜 조류계산을 대신할 수
> 있는지, 그리고 우리가 정확히 무엇을 학습시킬 것인지 알게 됩니다.

---

## 1. 신경망은 "모양을 바꿀 수 있는 함수"입니다

### 1.1 함수부터 시작합시다

$f(x) = 3x + 1$ 은 함수입니다. 숫자를 넣으면 숫자가 나옵니다.
여기서 3과 1을 **파라미터**라고 부릅시다. 파라미터를 바꾸면 함수 모양이 바뀝니다.

이제 이런 질문을 해 봅시다.

> 데이터 점들이 흩어져 있다. 이 점들을 가장 잘 지나가는 직선 $f(x) = ax + b$ 의
> $a, b$ 는 얼마인가?

이게 **선형회귀**이고, 이미 기계학습입니다. "데이터를 보고 파라미터를 정하는 것"이
곧 학습입니다.

### 1.2 직선으로는 부족합니다

조류방정식은 직선이 아닙니다. [01 문서](01_power_flow_and_opf.md) §6에서 봤듯이
$|V_i||V_k|\cos(\theta_i - \theta_k)$ 같은 곱셈과 삼각함수가 들어 있습니다.
직선으로는 절대 못 맞춥니다.

그래서 **직선을 여러 개 쌓고 사이사이에 구부러뜨리는 장치**를 넣습니다.
그게 신경망입니다.

### 1.3 뉴런 하나

$$
y = \delta(w_1 x_1 + w_2 x_2 + \cdots + w_n x_n + b)
$$

| 부분 | 이름 | 하는 일 |
|---|---|---|
| $w_i$ | **가중치(weight)** | 각 입력을 얼마나 중요하게 볼지 |
| $b$ | **편향(bias)** | 기준선을 위아래로 이동 |
| $\delta(\cdot)$ | **활성화 함수(activation)** | **구부리기** — 이게 없으면 아무리 쌓아도 직선 |

> [!IMPORTANT] 활성화 함수가 없으면 신경망은 의미가 없습니다
> 선형변환을 아무리 여러 번 겹쳐도 결국 하나의 선형변환입니다
> ($A(Bx) = (AB)x$). **비선형성은 오직 활성화 함수에서만 나옵니다.**
> 그래서 활성화 함수 선택이 생각보다 중요합니다 — §7.2에서 다시 다룹니다.
> (우리는 SiLU로 확정했습니다. `models.py` 기본값입니다.)

### 1.4 층으로 쌓기 = 다층 퍼셉트론(MLP)

뉴런을 옆으로 여러 개 늘어놓으면 **층(layer)** 이고, 층을 여러 개 쌓으면
**다층 퍼셉트론(MLP)** 입니다. 행렬로 쓰면 한 줄입니다.

$$
h_1 = \delta(W_1 x + b_1), \quad
h_2 = \delta(W_2 h_1 + b_2), \quad \cdots, \quad
y = W_L h_{L-1} + b_L
$$

`hidden dim 256, 4층` 같은 표현은 "각 층에 뉴런 256개, 층 4개"라는 뜻입니다.

#### 코드로 보면 다섯 줄입니다

위 수식을 PyTorch 로 옮기면 이렇습니다. 우리 코드에서 그대로 쓰는 부분입니다.

```python
# src/nnopf/models.py — PowerFlowMLP.__init__ 안
act = _ACT[spec.activation]                      # 활성함수 클래스 (기본 nn.SiLU)
dims = [layout.in_dim] + [spec.hidden] * spec.layers   # 예: [161, 256, 256, 256]

body = []
for a, b in zip(dims[:-1], dims[1:]):            # 층을 하나씩 이어 붙인다
    body += [nn.Linear(a, b), act()]             # W x + b  그리고  δ(·)
    if spec.dropout > 0:
        body.append(nn.Dropout(spec.dropout))

body.append(nn.Linear(dims[-1], layout.out_dim)) # 마지막 층엔 활성함수를 안 붙인다
self.net = nn.Sequential(*body)
```

**마지막 줄 앞의 `nn.Linear` 에 `act()` 가 없는 것**이 위 수식의
$y = W_L h_{L-1} + b_L$ 과 정확히 대응합니다. 출력층에 활성함수를 붙이면
값의 범위가 그 함수에 갇혀 버립니다.

`nn.Linear(a, b)` 하나가 $W$ 와 $b$ 를 함께 들고 있고, 두 값 모두 학습으로
바뀝니다. `spec.hidden=256, spec.layers=3` 이면 은닉층이 셋, 그 뒤에 출력층
하나 — 합쳐서 `nn.Linear` 가 네 개입니다.

> [!NOTE] 보편근사 정리 — 왜 이게 통하는가
> 수학적으로 증명된 사실이 있습니다: **충분히 넓은 은닉층 하나만 있어도
> 신경망은 임의의 연속함수를 원하는 정밀도로 근사할 수 있습니다.**
>
> 조류방정식은 (해가 존재하는 영역에서) 매끄러운 연속함수입니다.
> 따라서 **원리적으로 신경망이 근사할 수 있다는 보장이 있습니다.**
> 다만 정리는 "존재한다"만 말하고 "어떻게 찾는지"는 말해 주지 않습니다.
> 그게 학습입니다.

## 2. "학습"이란 무엇인가

### 2.1 세 단계

```
① 손실 정의   지금 얼마나 틀렸는지를 숫자 하나로
② 기울기 계산  각 파라미터를 조금 바꾸면 손실이 얼마나 변하는지
③ 파라미터 수정 손실이 줄어드는 방향으로 조금 이동
                                        └── ①로 돌아가 반복
```

### 2.2 ① 손실함수 — 틀린 정도를 숫자로

가장 기본은 평균제곱오차(MSE)입니다.

$$
\mathcal{L} = \frac{1}{N}\sum_{i=1}^{N} \left( y_i^{\text{예측}} - y_i^{\text{정답}} \right)^2
$$

| 손실 | 성질 | 우리 문제에서 |
|---|---|---|
| **MSE** (제곱오차) | 큰 오차에 크게 벌점 | 기본값. 전압 오차에 무난 |
| **MAE** (절대오차) | 이상치에 둔감 | 발산 근처 표본이 섞였을 때 |
| **Huber** | 둘의 절충 | 안정성이 필요할 때 |

> [!TIP] 4단계에서 우리는 손실을 하나 더 더합니다
> $$\mathcal{L} = \underbrace{\mathcal{L}_{MSE}}_{\text{정답과 얼마나 다른가}} + \lambda \underbrace{\mathcal{L}_{phys}}_{\text{물리 법칙을 얼마나 어겼나}}$$
>
> 두 번째 항이 **물리정보 신경망(PINN)** 의 핵심입니다. 예측한 전압을 조류방정식에
> **다시 넣어서** 남는 오차(잔차)를 벌점으로 씁니다. 정답 라벨이 없어도 계산할 수
> 있는 손실이라는 게 강력한 점입니다. §6.3에서 자세히 다룹니다.

#### 우리 MSE 는 교과서 그대로가 아닙니다 — 표준화 공간에서 잽니다

```python
# src/nnopf/train.py
def supervised_loss(model, Vm, Va, Vm_true, Va_true) -> torch.Tensor:
    """**표준화 공간**의 지도 손실.

    오차를 모선별 학습 표준편차로 나눈 뒤 MSE 를 잰다.
    """
    dv = (Vm[:, model.pq_idx] - Vm_true[:, model.pq_idx]) * model.vm_w
    da = (Va[:, model.va_idx] - Va_true[:, model.va_idx]) * model.va_w
    return (dv**2).mean() + (da**2).mean()
```

`model.vm_w` 와 `model.va_w` 는 **학습 분할에서 잰 표준편차의 역수**입니다
(`vm_w = 1.0 / vm_train.std(0)`). 이 두 줄이 없으면 두 가지가 망가집니다.

| 없으면 | 왜 |
|---|---|
| 정규화(weight decay)가 학습을 죽입니다 | 원단위 MSE 가 $10^{-4}$ 규모라 정규화 기울기가 과제 기울기와 맞먹습니다 ([06](06_surrogate_training.md) §7.2) |
| Va 가 손실을 지배합니다 | 라벨 분산이 Vm 8.1e-05, Va 8.1e-04 로 **10배** 차이입니다 |

`pq_idx` / `va_idx` 로 **예측 대상 모선만** 골라 재는 것도 중요합니다 — 예측하지
않기로 한 자리(슬랙 θ, PV·슬랙 |V|)는 항상 정확하므로 손실에 넣으면 분모만
키웁니다 (§5.1).

### 2.3 ② 역전파 — 사실 여러분은 이미 압니다

**역전파(backpropagation)는 연쇄법칙(chain rule)을 효율적으로 적용하는 알고리즘일
뿐입니다.** 합성함수 $f(g(x))$ 의 미분이 $f'(g(x))\cdot g'(x)$ 인 그것입니다.

층이 $L$ 개면 $L$ 겹 합성함수이므로, 미분값을 **출력에서 입력 쪽으로 거슬러
곱해 나가면** 모든 파라미터의 기울기를 한 번에 얻습니다. "역"전파라는 이름이 여기서 옵니다.

> [!NOTE] 야코비안을 이미 손으로 유도해 봤습니다
> [01 문서](01_power_flow_and_opf.md) §8.3에서 조류방정식의 야코비안을 유도했죠.
> **역전파가 하는 일이 정확히 그것입니다** — 다만 손이 아니라 자동으로,
> 그리고 사람이 아니라 계산 그래프를 따라서 합니다.
> PyTorch의 `.backward()` 를 처음 쓸 때, 손으로 미분한 값과 비교해 보세요.
> 같은 값이 나오는 걸 확인하면 개념이 확 잡힙니다.

### 2.4 ③ 경사하강 — 뉴턴법과 비교하면 쉽습니다

여러분은 이미 뉴턴-랩슨법을 압니다. 둘을 나란히 놓으면 이해가 빠릅니다.

| | 뉴턴-랩슨 (조류계산) | 경사하강 (신경망 학습) |
|---|---|---|
| 목표 | $f(x) = 0$ 을 만족하는 $x$ | $\mathcal{L}(\theta)$ 를 **최소화**하는 $\theta$ |
| 쓰는 미분 | 1차 + 역행렬 ($J^{-1}$) | **1차만** ($\nabla\mathcal{L}$) |
| 갱신식 | $x \leftarrow x + J^{-1}f$ | $\theta \leftarrow \theta - \eta\,\nabla\mathcal{L}$ |
| 수렴 속도 | 2차 (4~5회면 끝) | 1차 (수천~수만 회) |
| 왜 그렇게 하나 | 미지수 수백 개 | 파라미터 **수백만 개** — 역행렬이 불가능 |

> [!IMPORTANT] 이 대비가 프로젝트 전체를 요약합니다
> 뉴턴법은 **빠르게 수렴하지만 매번 처음부터 다시 풀어야** 합니다.
> 신경망은 **학습이 느리지만 한 번 학습하면 이후 추론이 즉시** 끝납니다.
>
> 조류계산을 백만 번 풀어야 하는 상황이라면? 학습 비용을 한 번 치르고
> 백만 번을 빠르게 가는 쪽이 이깁니다. **그게 대체모델의 경제 논리입니다.**

**학습률 $\eta$** 는 한 걸음의 크기입니다. 너무 크면 튕겨 나가고, 너무 작으면
평생 안 끝납니다. 실무에서는 **Adam** 이라는 최적화기를 쓰는데, 파라미터마다
걸음 크기를 자동 조절해 줍니다. 배경 논문 P2도 Adam을 씁니다.

### 2.5 배치와 에폭

| 용어 | 뜻 |
|---|---|
| **배치(batch)** | 한 번에 처리하는 표본 묶음. `batch 256` = 256개씩 |
| **에폭(epoch)** | 전체 데이터를 한 바퀴 다 본 것 |
| **반복(iteration)** | 배치 하나를 처리하는 것 |

20,000 표본을 batch 256으로 500 에폭 학습하면 총 $20000/256 \times 500 \approx 39{,}000$
번 파라미터를 갱신합니다.

## 3. 과적합 — 신경망의 가장 큰 함정

### 3.1 무엇이 문제인가

파라미터가 충분히 많으면 신경망은 **학습 데이터를 통째로 외워 버릴 수** 있습니다.
그러면 학습 오차는 0에 가까운데, **본 적 없는 데이터에서는 엉망**입니다.

```
학습 오차  ↓↓↓↓↓↓↓↓  계속 내려감
검증 오차  ↓↓↓↑↑↑↑↑  어느 순간부터 올라감  ← 여기가 과적합 시작점
```

### 3.2 그래서 데이터를 세 갈래로 나눕니다

| 분할 | 비율 | 용도 |
|---|---|---|
| **학습(train)** | 70% | 파라미터를 실제로 갱신 |
| **검증(val)** | 15% | 언제 멈출지, 하이퍼파라미터를 어떻게 정할지 판단 |
| **시험(test)** | 15% | **딱 한 번만** 본다. 최종 성능 보고용 |

> [!CAUTION] 시험 세트를 보고 모델을 고치면 안 됩니다
> 시험 결과를 보고 하이퍼파라미터를 조정하면, 그 순간 시험 세트는 사실상
> 검증 세트가 되어 버립니다. 논문 숫자가 부풀려집니다.
> **시험 세트는 마지막에 딱 한 번.**

### 3.3 우리 프로젝트의 일반화는 더 엄격합니다

우리 목표는 단순히 "본 적 없는 부하에서 맞히기"가 아닙니다.
**본 적 없는 계통 구성(선로 고장 후)에서도 맞히기**입니다.

그래서 분할을 두 가지로 만들었습니다 ([05 문서](05_dataset_generator.md) §9).

| 분할 방식 | 어떻게 나누나 | 무엇을 측정 |
|---|---|---|
| **무작위 분할** | 표본을 섞어 70/15/15 | 표준적인 일반화 |
| **미지 N-1 분할** | **고장 유형**을 먼저 나눔 | 시험용 고장은 학습에 **단 한 번도** 안 나옴 |

미지 N-1 분할이 훨씬 엄격하고, "실제 운영에서 쓸 수 있는가"를 재는 유일한 방법입니다.

## 4. 6주 스터디 커리큘럼

전력계통 대체모델에 안 쓰이는 주제(RNN, Transformer, 생성모델)는 뺐습니다.
**필요한 것만** 순서대로입니다.

### 4.1 1~2주차 — 최소 필수 이론

| 주제 | 왜 필요한가 | 우리 문제에서의 의미 |
|---|---|---|
| 선형회귀 → MLP | 신경망은 "선형변환 + 비선형함수"의 반복 | 조류방정식도 결국 입력→출력 사상 |
| 활성화 함수 (ReLU, tanh, SiLU, Softplus) | 비선형성의 원천 | 조류방정식은 **매끄러운** 비선형 → tanh/SiLU가 ReLU보다 유리할 수 있음 |
| 손실함수 (MSE, MAE, Huber) | 무엇을 "잘함"으로 정의할지 | 전압 오차를 어떤 노름으로 잴 것인가 |
| 역전파 | 기울기 계산 원리 | 5단계에서 신경망을 OPF 제약으로 넣을 때 **그 미분값이 필요** |
| 최적화기 (SGD, Adam) | 학습이 실제로 굴러가는 방식 | 뉴턴법과 비교하면 이해가 빠름 (§2.4) |
| 과적합·정규화 | 학습 데이터 밖에서도 동작해야 함 | 우리 목표 자체가 "본 적 없는 조건에서 맞히기" |
| 입력 정규화 | 스케일 통일 | per-unit이라 이미 절반은 해결됨 |

## 5. 무엇을 학습시킬 것인가 — 설계 결정

여기서부터는 "신경망 일반"이 아니라 **우리 문제에 특화된 설계**입니다.

### 5.1 입출력 계약 — 이게 가장 중요한 결정입니다

$$
f_\theta:\;
\underbrace{\left(P^{spec}_{PV\cup PQ},\; Q^{spec}_{PQ},\; |V|^{set}_{slack \cup PV}\right)}_{\text{입력 (직접변수)}}
\;\longmapsto\;
\underbrace{\left(|V|_{PQ},\; \theta_{PV \cup PQ}\right)}_{\text{출력 (간접변수)}}
$$

말로 옮기면:

- **입력** = 우리가 **지정하는** 값들 (부하가 얼마, 발전기 출력이 얼마, 목표 전압이 얼마)
- **출력** = 조류방정식이 **결정하는** 값들 (그래서 각 모선 전압이 얼마가 되는가)

나머지 값들($P_{slack}, Q_{slack}, Q_{PV}$)은 예측된 전압에서 **닫힌 식**
$S = V\overline{YV}$ 로 바로 계산합니다.

> [!IMPORTANT] 설계 원칙: 닫힌 식으로 구할 수 있는 건 절대 학습시키지 않는다
> 이미 정확한 공식이 있는데 신경망 근사값을 쓰면 정확도만 떨어집니다.
> 이 원칙은 참고자료(Stanford ASL 툴킷)가 "직접변수/간접변수"로 정식화해 둔
> 것이고, 배경 논문들도 전부 이 구조를 따릅니다
> (→ [07 부록](07_appendix_reference.md) §2).

#### 입력 벡터를 만드는 코드

위 수식의 왼쪽(입력)이 코드에서는 이렇게 생겼습니다.

```python
# src/nnopf/models.py — IOLayout
def inputs(self, ds, idx=None) -> np.ndarray:
    """데이터셋에서 입력 행렬 (N, in_dim) 을 만든다."""
    sl = slice(None) if idx is None else idx

    # 선로상태: 기본이 전부 1(정상), 고장 난 선로 자리만 0 으로 내린다
    status = np.ones((len(np.atleast_1d(ds.outage[sl])), self.nl), np.float32)
    out = np.atleast_1d(ds.outage[sl])
    hit = np.flatnonzero(out >= 0)          # outage = -1 이면 정상 토폴로지
    status[hit, out[hit]] = 0.0

    return np.concatenate(
        [ds.Pd[sl], ds.Qd[sl], ds.p_ren[sl], ds.p_gen[sl], status], axis=1
    ).astype(np.float32)
```

case30 이면 `30+30+30+30+41 = 161` 차원입니다.

**여기에 넣지 않은 것이 있습니다.** 노드 특징 8개 중 정적인 4개 — 발전기
설정전압 `V_set`, 모선종류 원-핫 3개 — 는 빼 두었습니다. MLP 에서는 모선 위치가
곧 벡터 인덱스라 이 값들이 **모든 표본에서 똑같은 상수 입력**이 되고, 상수는
정보를 0 비트 줍니다. (그래프 신경망에서는 노드마다 붙여야 하므로 다시 들어옵니다.)

<br>

출력 쪽 계약이 코드 어디에 있는지는 [06 문서](06_surrogate_training.md) §1 에
`IOLayout.__init__` 과 `PowerFlowMLP.forward` 로 같이 실어 두었습니다.

### 5.2 표현 방식 — 확정된 것과 남은 것

| 항목 | 후보 A | 후보 B | 결정 |
|---|---|---|---|
| 좌표계 | 극좌표 $(\|V\|, \theta)$ | 직교좌표 $(e, f)$ | ✅ **극좌표** — P2와 동일, 물리 잔차식을 그대로 사용 가능 |
| 출력 | 절대값 | 기저 케이스로부터의 편차 | ✅ **절대값 + 입력→출력 선형 지름길** — [06](06_surrogate_training.md) §6 절제로 확정 (물리 잔차 1.8배) |
| 정규화 | 표준화 | min-max | ✅ **표준화** — 단 선로상태 열은 손대지 않고 상수열은 중심화만 ([06](06_surrogate_training.md) §7.1). 손실도 표준화 공간 (§7.2) |
| 손실 | MSE | MSE + 물리 잔차 | ✅ **둘 다** — 기준선은 MSE, 본 모델은 PINN |

**전압 출력 요령**: P2 는 전압 크기에 **1.0 pu를 더해서** 출력합니다 —
"정상 운전에서 전압은 1.0 근처"라는 사전지식을 구조에 넣는 것입니다.
우리는 그 대신 §5.3 의 **스케일링 인자 헤드**를 씁니다. 사전지식을 더 강하게
넣으면서(범위를 아예 벗어날 수 없게) 같은 효과를 냅니다. 위상은 양·음 모두
가능하므로 표준화만 하고 그대로 씁니다.

### 5.3 제약 위반을 구조적으로 0으로 만드는 트릭

배경 논문 P1에서 가져온 기법입니다. 구현 10줄이고 효과가 확실합니다.

$$
x^{min} \le x \le x^{max}
\quad\Longrightarrow\quad
x = \alpha\,(x^{max} - x^{min}) + x^{min},\qquad \alpha \in [0,1]
$$

신경망이 $x$ 대신 **$\alpha$ 를 예측**하게 하고 출력층에 sigmoid를 씁니다.
그러면 $\alpha$ 가 무슨 값이 나오든 $x$ 는 **항상 범위 안**입니다.

> [!TIP] 4단계 MLP 기준선에 바로 적용하세요
> 전압 출력에 이걸 씌우면 **박스를 벗어나지 않는 것**이 구조적으로 보장됩니다.
> 다만 그 박스는 계통 전압한계가 아니라 **학습 라벨 범위 + 여유**로 잡습니다 —
> 조류계산이 전압한계를 강제하지 않아 라벨 자체가 한계 밖에 있을 수 있기
> 때문입니다. 그래서 "계통 전압한계 위반 0%"가 되는 것은 아닙니다
> ([06 문서](06_surrogate_training.md) §2.3·§4).
> 발전출력·선로조류 상한/하한에도 똑같이 적용됩니다.

#### 구현은 정말 두 곳입니다

**① 박스를 정하는 곳** — 학습 분할의 라벨 범위에 여유를 더합니다.

```python
# src/nnopf/train.py — prepare() 안
vm_tr = ds.Vm[tr][:, layout.pq]        # 학습 분할의, PQ 모선 전압 라벨만

if spec.vm_head == "scaled":
    lo, hi = vm_tr.min(0), vm_tr.max(0)                  # 모선별 실제 라벨 범위
    pad = np.maximum((hi - lo) * spec.vm_margin, 1e-3)   # 기본 여유 5%
    vm_lo, vm_hi = lo - pad, hi + pad
```

`tr` 로 잘라 낸 것이 핵심입니다 — 검증·시험 라벨을 보고 박스를 정하면 성능이
부풀려집니다 (§3.2).

**② 씌우는 곳** — 한 줄입니다.

```python
# src/nnopf/models.py — PowerFlowMLP.forward
if self.spec.vm_head == "scaled":
    vm = self.vm_lo + torch.sigmoid(vm_raw) * (self.vm_hi - self.vm_lo)
```

`torch.sigmoid` 의 치역이 $(0, 1)$ 이므로 `vm` 은 `vm_lo` 와 `vm_hi` 사이를
**수학적으로 벗어날 수 없습니다.** 손실로 유도하는 것이 아니라 구조로 막는
것이라, 학습이 아무리 나빠도 이 성질은 유지됩니다.

## 6. 평가 — 기준선을 반드시 넘어야 합니다

### 6.1 지표

| 지표 | 정의 | 목표 |
|---|---|---|
| 전압 크기 오차 | 신경망 예측과 뉴턴-랩슨 해의 전압 크기 차이, 모선 전체 최댓값 | < 0.001 pu (0.1%) |
| 전압 위상 오차 | 같은 방식으로 잰 위상 차이의 최댓값 | < 0.001 rad |
| 전력 오차 | 예측 전압으로 계산한 $S$ 와 지정값의 차 | < 0.5% |
| 조류방정식 잔차 | 예측 전압을 조류방정식에 넣었을 때 남는 불일치의 최댓값 | < 1e-3 pu |
| 추론 시간 | 배치 1,000건 기준 | 뉴턴-랩슨 대비 100배 이상 |

### 6.2 비교군을 반드시 포함할 것

> [!IMPORTANT] 신경망이 선형근사보다 못하면 쓸 이유가 없습니다
> 참고자료가 제시한 선형근사의 오차 수준은 **전압 0.2% / 전력 1.5%** 입니다.
> 이걸 못 넘으면 논문이 성립하지 않습니다.
>
> 비교군: **DC 조류계산**, **고정점 선형화**(Bolognani 2015 형태),
> 가능하면 Bernstein 2017 LP.
> 기준선을 먼저 구현하고 숫자를 확보해 두면, 신경망이 그보다 못할 때
> **일찍** 알아챌 수 있습니다.
>
> **실제로 그렇게 됐습니다.** 최소제곱 선형 기준선을 먼저 재 뒀더니,
> case118 에서 선형 0.61% vs MLP 1.14% 로 **신경망이 졌습니다**
> ([06](06_surrogate_training.md) §5.3). 기준선이 없었으면 한참 뒤에야 알았을
> 것입니다. 덧붙여 그 기준선 자체가 수치적으로 망가져 있던 적도 있습니다 —
> **비교 대상도 검증해야 합니다** (§7.6).

### 6.3 물리 일관성과 점별 정확도는 다른 지표입니다

배경 논문 P2가 정직하게 보고한 중요한 사실입니다.

| IEEE 118 | 전압 MAE | 전력 불일치 [pu] |
|---|---|---|
| GCN | **0.000614** | 0.6427 |
| GAT | 0.000669 | 0.6043 |
| **PI-GAT** (물리손실 있음) | 0.000934 | **0.2319** |

> [!NOTE] 전압은 나빠졌는데 물리는 좋아졌습니다
> PI-GAT의 전압 오차는 다른 모델보다 **나쁩니다**(0.000934 vs 0.000614).
> 그런데 전력 불일치는 **62% 줄었습니다.**
>
> 즉 "점별 전압 정확도"와 "물리적 일관성"은 서로 다른 지표이고,
> **트레이드오프 관계**입니다. 물리 손실 가중치 $\lambda$ 를 키우면 물리는
> 좋아지고 전압은 나빠집니다.
>
> **우리 논문에도 이 곡선이 반드시 들어가야 합니다.** "λ를 얼마로 했더니
> 좋았다"가 아니라 "λ를 바꾸면 이런 곡선이 나온다"를 보여야 합니다.

## 7. 5단계 — 학습된 신경망을 OPF에 넣기

4단계가 끝나면 잘 동작하는 대체모델이 손에 있습니다. 이제 그걸 최적화 문제
**안에** 넣어야 합니다. 방법이 세 가지입니다.

### 7.1 (c) 웜스타트 — 여기서 시작하세요

```
부하 ──► 신경망 ──► 예측 전압/출력 ──► 기존 NLP 솔버의 초기값 ──► 정확한 OPF 해
```

| 항목 | 내용 |
|---|---|
| 장점 | **항상 정확한 해**. 신경망이 틀려도 최종 답은 맞습니다. 구현 하루면 됩니다. |
| 단점 | 속도 향상 폭이 제한적 (반복 수만 줄어듦) |
| 위험 | 낮음 — 실패해도 기존 OPF로 되돌아갑니다 |

> [!TIP] 이미 구조가 준비되어 있습니다
> `solve_acopf(warm_start=True)` 가 지금 뉴턴-랩슨으로 초기값을 만듭니다.
> **그 자리에 신경망을 넣기만 하면 됩니다.**
> 최악의 경우에도 논문에 쓸 결과가 남는 안전장치입니다.

### 7.2 (a) 제약 대체 — 논문의 본론

```
min  발전비용
s.t. NN_θ(x) = 0      ← 조류방정식 대신 학습된 함수
     상자 제약
```

| 항목 | 내용 |
|---|---|
| 장점 | 개념적으로 가장 깔끔. 참고자료 아키텍처와 정확히 일치 |
| 단점 | **신경망이 비볼록** → 국소해·수렴 문제. ReLU면 미분이 불연속 |
| 필요 기술 | 신경망의 야코비안을 솔버에 전달 (PyTorch `autograd.functional.jacobian`) |
| 요령 | 활성화 함수를 **매끄럽게**(tanh/SiLU/Softplus) 쓰면 수렴이 훨씬 안정적 |

> [!CAUTION] 순진하게 구현하면 아무것도 보장되지 않습니다
> 배경 논문 P3의 비교표에서 "일반 신경망을 OPF에 넣은 것"은 **최적성 ❌,
> 수렴 보장 ❌** 입니다. 신경망이 비볼록이라 경사법이 아무것도 보장하지 못합니다.
>
> 해결책이 두 갈래로 갈립니다:
> - **P3(ICNN)**: 신경망 자체를 **볼록하게** 설계 → 문제 전체가 볼록계획
> - **P4(MILP)**: ReLU를 이진변수로 **정확히 인코딩** → 혼합정수계획
>
> 자세한 내용은 [04 문서](04_paper_review.md) §3, §4에 있습니다.

### 7.3 (b) 종단간 예측 — 가장 빠르지만 가장 위험

```
부하 ──► 신경망 ──► OPF 해 (Pg, Vm) 직접 출력
```

| 항목 | 내용 |
|---|---|
| 장점 | 추론 한 번. 가장 빠릅니다 |
| 단점 | **제약 위반을 통제할 수 없음** → 사영/보정 단계 필수 |
| 연구 주제 | 실행가능성 복원, 위반량 상한 증명 |

## 8. 평가 프로토콜 — 2단 검증을 반드시

여기가 이 프로젝트에서 가장 중요한 방법론입니다.

```
1단: 신경망 OPF 를 푼다                      → 해 x*
2단: x* 의 발전지령을 진짜 뉴턴-랩슨에 재투입   → 실제 전압 V_real
3단: V_real 이 전압/조류 한계를 지키는가?      ← 이게 진짜 지표
```

> [!IMPORTANT] 1단만 보고하면 논문이 되지 않습니다
> 근사모델을 쓴 OPF는 **자기 근사모델 기준으로는** 항상 "제약 만족"이라고 말합니다.
> 그 답을 진짜 물리에 넣었을 때 어떻게 되는지가 유일하게 의미 있는 질문입니다.
>
> 우리 저장소에는 이 검사가 이미 들어가 있습니다:
> `tests/test_nnopf.py::test_opf_solution_is_a_true_power_flow_solution`
