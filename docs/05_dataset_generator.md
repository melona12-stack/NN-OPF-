## 1. 데이터가 왜 필요한가 — 그리고 왜 우리가 직접 만드나

신경망은 **(문제, 정답) 쌍**을 보고 배웁니다. 우리 경우 그게 무엇인지 봅시다.

| 구분 | 내용 |
|---|---|
| **문제 (입력)** | "부하가 이만큼이고, 발전기가 이만큼 내고, 3번 선로가 고장 났다" |
| **정답 (라벨)** | "그러면 각 모선 전압이 이렇게 된다" |

정답은 어떻게 얻을까요? **우리 뉴턴-랩슨 코드로 풀면 됩니다.**
[02 문서](02_validation.md)에서 기계정밀도로 검증해 뒀으니 믿고 쓸 수 있습니다.

```
시나리오 무작위 생성  ──►  뉴턴-랩슨으로 풀기  ──►  (입력, 라벨) 저장
   (부하, 발전, 고장)        (검증된 우리 코드)         수천~수만 건
```

> [!NOTE] 이게 이 문제의 큰 장점입니다
> 대부분의 기계학습 문제는 라벨을 사람이 손으로 붙여야 합니다(사진에 "고양이"라고
> 표시하는 식). 우리는 **정답을 컴퓨터가 무한정 찍어냅니다.**
> 데이터 수집 비용이 사실상 0이라는 뜻이고, 이것이 [00 문서](00_overview.md) §5에서
> "강화학습이 아니라 지도학습"이라고 한 이유입니다.

## 2. 왜 GPU가 오기 전에 만들었나

조류계산은 **순수 CPU 작업**입니다. pandapower도 우리 뉴턴-랩슨도 GPU를 쓰지
않으므로, 데이터 생성만큼은 RTX 5060을 기다릴 이유가 없었습니다.

| 작업 | 장치 | 지금 가능? |
|---|---|---|
| **데이터 생성 (조류계산)** | **CPU 전용** | ✅ 66초 |
| MLP 학습 | CPU도 되지만 느림 | ✅ 완료 (GPU) |
| GAT 학습 | GPU | ✅ case30 완료 — 미지 N-1 최고 2.53%. 다만 MLP + `lstsq`(1.46%)에 1.74배 짐 ([06](06_surrogate_training.md) §6.1) |
| PI-GAT 학습 | GPU | ⬜ 아직 |
| 배치 추론 벤치마크 | GPU | ⚠️ CPU 기준 완료, GPU 재측정 남음 ([06](06_surrogate_training.md) §8) |

게다가 데이터 생성기는 **설계 결정이 가장 많이 들어가는 부분**입니다 —
샘플링 분포를 어떻게 잡을지, N-1 고장을 어떻게 다룰지, 발산을 어떻게 기록할지.
이걸 검증하는 게 전부 CPU 작업이라 지금이 적기였습니다.

## 4. 시나리오를 어떻게 만드나

P2 §4.1 설정을 그대로 복제했습니다 ([04 문서](04_paper_review.md) §2.5의 표).
말로 풀면 이렇습니다.

### 4.1 순서

```
① 부하 흔들기      각 모선 P를 0.80~1.20배, Q를 0.85~1.15배 (모선마다 독립)
② 재생에너지 출력   지정된 재생 모선에 정격 × 0.65~1.35배
③ 캡 적용          재생 비중이 총부하의 95%를 넘지 않게 제한
④ 나머지 발전 배분  남은 부하를 급전가능 발전기에 비례 배분 + 0.95~1.05배 섭동
⑤ N-1 고장 (25%)   선로 하나를 무작위로 개방 (섬이 생기는 고장은 제외)
⑥ 뉴턴-랩슨 풀기    tol 1e-8, max 30 iter
⑦ 저장             수렴하면 (입력, 라벨), 발산하면 기록만
```

### 4.2 왜 재생에너지를 따로 두는가

발전기를 두 종류로 나눕니다.

| 종류 | 누가 출력을 정하나 | 변동성 | 모델 입력 채널 |
|---|---|---|---|
| **재생에너지** | 날씨 | 큼 (0.65~1.35배) | `P_ren` |
| **급전가능 발전** | 우리 (계통 운영자) | 작음 (잔여 부하를 배분) | `P_gen` |

두 소스의 성격이 근본적으로 다르므로 **별도 채널로 분리**합니다.
한 채널에 섞으면 모델이 그 구분을 스스로 학습해야 하는데, 그냥 알려주면 됩니다.

재생 모선은 슬랙을 제외한 PV 모선의 **60%** 를 시드로 뽑고, 정격 합은 기저
총부하의 **60%** 로 맞춥니다.

### 4.3 N-1 상정사고

"N-1"은 전력계통 용어로 **"N개 설비 중 하나가 고장 난 상태"** 를 뜻합니다.
운영자는 항상 "지금 아무 선로 하나가 끊어져도 괜찮은가"를 확인해야 합니다.

표본의 25%는 선로 하나를 개방한 상태로 만듭니다. 단, 조건이 있습니다.

> [!WARNING] 섬(island)을 만드는 고장은 제외해야 합니다
> 어떤 선로는 끊으면 계통이 두 조각으로 갈라집니다. 발전기가 없는 쪽 조각은
> 애초에 전기가 없으므로 조류계산이 성립하지 않습니다.
>
> 그래서 `scipy.sparse.csgraph.connected_components` 로 미리 검사해서
> 그런 고장은 후보에서 뺍니다. **case118은 186개 선로 중 177개만 유효합니다.**

## 5. 입출력 규격 (P2 §3.1 그대로)

### 5.1 노드 특징 8개

| 순서 | 특징 | 설명 |
|---|---|---|
| 0–1 | `P_load`, `Q_load` | 유효/무효 부하 |
| 2 | `P_ren` | **재생에너지** 발전 |
| 3 | `P_gen` | 기존 급전가능 발전 |
| 4 | `V_set` | 전압 설정값 |
| 5–7 | `isPQ`, `isPV`, `isref` | 모선 종류 원-핫 |

> [!IMPORTANT] 슬랙 모선의 `P_gen` 은 0입니다
> 슬랙 출력은 **조류방정식이 결정하는 종속변수**라 추론 시점에 알 수 없습니다
> ([01 문서](01_power_flow_and_opf.md) §7.2의 "닭-달걀" 이야기).
> 알 수 없는 값을 입력에 넣으면 **정답 유출(label leakage)** 입니다 —
> 학습할 때는 성능이 좋다가 실제로 쓸 때 무너집니다.
>
> 모델은 `isref` 원-핫으로 "그 모선이 슬랙"임을 알고, 슬랙이 얼마를 낼지는
> **스스로 추론해야** 합니다.

### 5.2 엣지 특징 7개

`r`, `x`, `sh`(충전 서셉턴스), `tap`, `status`, `g`, `b`

임피던스 `r, x` 와 그로부터 유도되는 어드미턴스 `g, b` 를 **둘 다** 넣습니다.
$y = 1/z$ 라는 비선형 변환을 모델이 따로 학습하지 않아도 되게 하려는 것입니다.

브랜치마다 **양방향 엣지**를 둡니다 — 물리 선로는 방향이 없지만
그래프 신경망의 메시지 패싱은 방향이 필요하기 때문입니다.

### 5.3 라벨

모선별 $(V_m, \theta)$. 위상은 라디안입니다.

### 5.4 N-1을 그래프에서 어떻게 표현하나

> [!TIP] 고장 선로를 그래프에서 제거하지 않습니다
> 대신 `status = 0` 이라는 **특징으로만 표시**합니다.
>
> 이유는 두 가지입니다.
> ① 그래프 구조가 고정되어 **배치 추론**이 가능합니다 (표본마다 그래프가 다르면
>    한 배치로 묶을 수 없습니다).
> ② 그래프를 매번 다시 만드는 오버헤드가 없습니다.
>
> P2의 설계이고, 우리도 그대로 따릅니다.

## 6. 만들면서 잡은 문제 두 가지

둘 다 기본 계통(case30/118)에서는 보이지 않고 **case300을 돌려 보고 나왔습니다.**
[02 문서](02_validation.md) §3.2의 교훈("작은 계통만 보고 판단하면 안 된다")이
여기서도 반복됐습니다.

### 6.1 float32로 저장했더니 $Y_{bus}$ 를 거치며 오차가 증폭

전압을 float32(단정밀도)로 저장했더니 조류방정식 잔차가 남았습니다.
원인을 재보니 정확히 $\max|Y| \times \epsilon_{32}$ 였습니다.
($\epsilon_{32} \approx 1.2\times10^{-7}$ 는 float32의 상대 정밀도)

| 계통 | float64 잔차 | float32 저장 후 | $\max\|Y\|$ | 예측 바닥 |
|---|---|---|---|---|
| case30 | 4.6e-09 | 3.2e-06 | 87.5 | 1.0e-05 |
| case118 | 1.3e-09 | 1.6e-05 | 388.9 | 4.6e-05 |
| case300 | 8.8e-09 | **2.5e-04** | 2438.6 | 2.9e-04 |

> [!CAUTION] 왜 이게 심각한 문제인가
> case300의 **2.5e-04는 우리가 측정하려는 신경망 잔차(P2 목표 ~1e-3)와 같은
> 자릿수**입니다. 이러면 "신경망이 낸 오차"와 "데이터 저장 오차"를 구분할 수
> 없습니다. **기준선이 무의미해집니다.**
>
> 신경망 성능이 데이터 정밀도보다 좋아질 수 없으니, 나중에 아무리 좋은 모델을
> 만들어도 이 바닥에 걸립니다. 그리고 그 사실을 모르면 "모델 한계"라고
> 오해하게 됩니다.

**해결**: 입력을 float32로 **내린 뒤 그 값으로 풀고**, 라벨만 float64로 저장합니다.
그러면 "저장된 입력"과 "라벨을 만든 입력"이 **정확히 일치**합니다. → 잔차 1e-9.

```python
# 저장할 때 내리는 게 아니라, 내린 값으로 푼다
f32 = lambda a: a.astype(np.float32).astype(np.float64)
return Scenario(Pd=f32(Pd), Qd=f32(Qd), ...)
```

| 배열 | dtype | 이유 |
|---|---|---|
| 입력 (`Pd`, `Qd`, `p_ren`, `p_gen`) | float32 | 이미 float32로 내려서 푼 값이라 손실 없음 |
| 라벨 (`Vm`, `Va`) | **float64** | $Y_{bus}$ 를 거치며 오차가 $\max\|Y\|$ 배로 증폭됨 |

### 6.2 발전 배분에서 잘린 몫이 전부 슬랙으로

발전기 출력을 부하에 맞춰 비례 배분한 뒤 상·하한으로 자르는데(`np.clip`),
**상한에 걸려 잘린 만큼이 슬랙 한 모선에 전부 떨어집니다.**

case300에서 재생에너지 비중을 낮춰 봤더니 **표본 100%가 발산**했습니다.

| 설정 | 재생E 41대 | 기존 27대 (Pmax 13,651) | **슬랙 부담** | 슬랙 Pmax |
|---|---|---|---|---|
| 재생E 60% | 14,637 MW | 8,178 MW | 0 MW | 2,399 MW |
| 재생E 30% | 7,536 MW | **13,651 MW (상한)** | 1,627 MW | 2,399 MW |
| 재생E 15% | 3,768 MW | **13,651 MW (상한)** | **5,395 MW** | **2,399 MW** ❌ |

슬랙 하나가 5,395 MW를 공급해야 하는데 상한이 2,399 MW입니다.
**물리적으로 불가능한 시나리오**를 만들어 놓고 풀라고 한 것입니다.

**해결 두 가지**

**① `allocate_dispatch()`** — 잘린 뒤 남은 부족/과잉을 **여유용량(headroom)에
비례해 재배분**합니다. 실제 급전이 하는 일과 같고, 몇 번만 돌면 수렴합니다.

```python
# src/nnopf/dataset.py
def allocate_dispatch(
    target: float,          # 채워야 할 총 발전량 [MW] = 총부하 + 손실 추정 - 재생E
    pmin: np.ndarray,       # 발전기별 출력 하한
    pmax: np.ndarray,       # 발전기별 출력 상한
    weight: np.ndarray,     # 배분 가중치 (보통 pmax 에 비례)
    jitter: np.ndarray,     # 표본마다 다르게 흔드는 난수 (1.0 근처)
    max_iter: int = 30,
) -> np.ndarray:
    """목표 발전량 target 을 출력 한계를 지키며 발전기에 배분한다."""
    if pmax.size == 0:
        return np.array([])

    # ① 가중치를 정규화하고 비례 배분한 뒤 한계로 자른다 (여기까지가 원래 코드)
    w = weight / weight.sum() if weight.sum() > 0 else np.full(pmax.size, 1.0 / pmax.size)
    alloc = np.clip(target * w * jitter, pmin, pmax)

    # ② 자르면서 잃어버린 몫을 여유용량에 비례해 다시 나눈다 (추가한 부분)
    for _ in range(max_iter):
        gap = target - float(alloc.sum())      # 아직 모자란(또는 남는) 양
        if abs(gap) < 1e-10:
            break                              # 다 채웠다

        # 더 낼 수 있는 여유. 모자라면 위쪽 여유, 남으면 아래쪽 여유를 본다
        headroom = (pmax - alloc) if gap > 0 else (alloc - pmin)
        total = float(headroom.sum())
        if total < 1e-12:
            break                              # 더 줄 곳도 뺄 곳도 없다 -> 슬랙이 받는다

        alloc = np.clip(alloc + gap * headroom / total, pmin, pmax)

    return alloc
```

**②의 for 루프가 추가한 전부입니다.** `np.clip` 한 번으로 끝내면 잘려 나간 몫이
갈 곳이 없어 슬랙 모선 하나로 전부 떨어집니다. 여유용량에 비례해 다시 나누면
**여유가 있는 발전기들이 나눠 받습니다** — 실제 급전이 하는 일과 같습니다.

`break` 가 세 군데인 것도 의도적입니다. 마지막 `total < 1e-12` 는 **용량이
정말로 모자란 경우**로, 이때는 전 발전기가 상한에 붙은 채 끝나고 잔여는 슬랙이
받습니다. 그래서 그 상황은 아래 ②번 사전 점검으로 걸러야 합니다.

**② `check_capacity_feasible()`** — 용량이 모자란 설정은 **데이터를 만들기 전에**
원인과 대안을 알려주며 막습니다.

```
case300: 발전 용량이 부족해 사실상 전 표본이 발산합니다
         (기저 부하 23,526 MW 대비 3,947 MW 모자람).
  재생E 41대 정격 3,529 MW + 기존 27대 상한 13,651 MW + 슬랙 상한 2,399 MW
  -> ren_capacity_frac(0.15)을 올리거나, ren_bus_frac(0.6)을 낮춰 급전가능
     발전기를 남기거나, p_load_hi(1.05)를 낮추세요.
```

검사는 **2단계**입니다.

| 단계 | 판정 기준 | 동작 |
|---|---|---|
| **오류** | 기저 부하 · 평균 재생출력에서도 용량 부족 | 생성 전 중단 |
| **경고** | 최악 조합(최대 부하 × 최소 재생출력)에서만 부족 | 진행하되 알림 |

> [!NOTE] 왜 2단계로 나눴나
> 처음엔 최악 조합만으로 판정했더니, **실제로 97% 수렴하는 case300 P2 기본
> 설정까지 막아 버렸습니다.** 최대 부하와 최소 재생출력이 동시에 오는 일은
> 드뭅니다. 지나치게 보수적인 검사는 사용자를 방해할 뿐입니다.

## 7. 물리 잔차 — 4단계 손실함수의 원형

`physics_residual()` 은 **"라벨이 진짜 조류해인가"를 검증하는 데** 쓰고,
동시에 `physics_torch.ACPhysics` 로 옮겨 **학습 손실 항으로도** 쓰고 있습니다
([06 문서](06_surrogate_training.md) §3).
하지만 `Vm, Va` 자리에 **신경망 예측을 넣으면 그대로 P2의 물리정보 손실**이 됩니다.

핵심은 **지정값이 있는 곳에만 잔차를 거는 것**입니다.

| 모선 | 잔차에 포함 | 이유 |
|---|---|---|
| **PQ** | $\Delta P$, $\Delta Q$ | P, Q 모두 지정값 |
| **PV** | $\Delta P$ **만** | Q는 조류방정식이 정하는 종속변수 |
| **슬랙** | **없음** | P, Q 모두 종속변수 |

```python
# src/nnopf/dataset.py
def physics_residual(sys, Pd, Qd, p_ren, p_gen, Vm, Va,
                     outage: int = -1, Ybus=None):
    """조류방정식 잔차 (ΔP, ΔQ) 를 모선 종류를 구분해 계산한다."""

    # ① N-1 이면 그 선로만 끊은 Ybus 를 쓴다
    if outage >= 0:
        status = sys.br_status.copy()
        status[outage] = 0
        sys = dataclasses.replace(sys, br_status=status)
    if Ybus is None:
        Ybus = make_ybus(sys)

    # ② 주어진 전압에서 실제로 흐르는 주입전력을 계산한다
    V = np.asarray(Vm, float) * np.exp(1j * np.asarray(Va, float))
    S_calc = V * np.conj(Ybus @ V)          # S = V ⊙ conj(Ybus V)

    # ③ 지정값. 병렬 소자는 여기 넣지 않는다 — Ybus 대각에 이미 있다
    P_sp = np.asarray(p_gen, float) + np.asarray(p_ren, float) - np.asarray(Pd, float)
    Q_sp = -np.asarray(Qd, float)

    # ④ 지정값이 있는 자리에만 잔차를 건다. 나머지는 0 으로 남긴다
    dP = np.zeros(sys.nb)
    dQ = np.zeros(sys.nb)
    non_slack = sys.bus_type != SLACK       # 슬랙은 P 도 종속변수
    pq = sys.bus_type == PQ                 # PV 는 Q 가 종속변수

    dP[non_slack] = P_sp[non_slack] - np.real(S_calc)[non_slack]
    dQ[pq]        = Q_sp[pq]        - np.imag(S_calc)[pq]

    return dP, dQ
```

**④의 두 줄이 위 표를 그대로 코드로 옮긴 것입니다.**

| 코드 | 뜻 |
|---|---|
| `dP[non_slack] = ...` | 슬랙을 뺀 모든 모선에 $\Delta P$ — 슬랙 P 는 조류방정식이 정하므로 지정값이 없습니다 |
| `dQ[pq] = ...` | PQ 모선에만 $\Delta Q$ — PV 는 발전기가 Q 를 알아서 내므로 지정값이 없습니다 |
| 나머지 자리 | `np.zeros` 그대로 **0** — 잔차를 걸지 않는다는 뜻입니다 |

이 구분을 놓치고 모든 모선에 잔차를 걸면 학습이 잘못된 방향으로 갑니다.
슬랙에 $\Delta P$ 를 걸면 "네가 정할 값이 아닌 것을 맞히라"고 요구하는 셈이고,
그 벌점이 다른 모선의 전압을 왜곡시킵니다.

> [!TIP] 4단계에서 실제로 그렇게 옮겼습니다 — `physics_torch.ACPhysics`
> 모선 종류별로 잘라 쓰는 구조를 이미 NumPy로 맞춰 놓았으므로,
> `np` → `torch` 로 바꾸고 미분 가능하게만 하면 됩니다.

**병렬 소자 주의**: 고정 병렬 소자는 $Q^{sp}$ 에 넣지 **않습니다**.
$Y_{bus}$ 대각에 이미 들어 있어 계산된 $\hat Q$ 쪽에 반영되므로, 양쪽에 넣으면
이중계산입니다. [02 문서](02_validation.md) §4.3에서 겪은 그 shunt 회계 문제와
같은 이슈입니다.

## 8. 재현성 — 데이터를 옮기지 않는 이유

### 8.1 시드를 표본별로 파생시킵니다

```python
rng = np.random.default_rng([seed, i])   # 표본 i 전용 난수 생성기
```

표본 $i$ 의 난수를 **독립적으로** 만듭니다. 그래서 **워커 수나 청크 크기를
바꿔도 표본 $i$ 는 항상 동일**합니다. (테스트로 고정해 뒀습니다.)

재생에너지 모선 지정, 상정사고 선택도 전부 시드에서 결정됩니다.

> [!IMPORTANT] 데이터 파일을 커밋하지도, 컴퓨터 간에 나르지도 않습니다
> 새 컴퓨터에서 한 줄이면 **똑같은 데이터**가 나옵니다.
>
> `.venv/bin/python scripts/s02_generate_dataset.py`
>
> **5060 머신으로 옮길 때 데이터를 들고 갈 필요가 없습니다.**
> `data/manifest.json` 에 "무엇을 어떤 품질로 만들었는지"만 기록으로 남깁니다.
> 47 MB짜리 이진 파일을 git에 넣으면 저장소가 금방 무거워지는데, 그럴 이유가 없습니다.

### 8.2 저장 형식 — 바뀌는 것만 저장

특징 대부분은 시나리오마다 바뀌지 않습니다(전압 설정값, 모선 종류, 선로 임피던스).
**바뀌는 것만 표본별로 저장**하고 나머지는 한 번만 저장합니다.

| 구분 | 배열 | 저장 |
|---|---|---|
| 표본마다 다름 | `Pd`, `Qd`, `p_ren`, `p_gen`, `Vm`, `Va`, `outage` | N개씩 |
| 계통 공통 | `v_set`, `bus_type`, `edge_index`, `edge_attr_base`, `edge_line` | 1개씩 |

case118 20,000 표본이 47.6 MB로 끝나는 이유입니다.

## 9. 분할 두 가지

| 분할 | 방식 | 목적 |
|---|---|---|
| **무작위** | 표본을 70/15/15로 섞음 | P2의 표준 분할 |
| **미지 N-1** | **고장 유형**을 먼저 나눔 | 본 적 없는 토폴로지 일반화 |

미지 N-1 분할에서는 시험용 고장이 **학습·검증에 단 한 번도 등장하지 않습니다.**
무작위 분할보다 훨씬 엄격하며, **"본 적 없는 계통 구성에서도 되는가"** 를 재는
유일한 방법입니다 (P2 §4.7).

> [!WARNING] 겹침이 0인지 자동으로 확인합니다
> 조용히 겹치면 실험 자체가 무의미해집니다 — 일반화를 측정한다고 해 놓고
> 실제로는 본 데이터를 시험한 셈이 되니까요. 생성할 때마다 검사하고
> 테스트로도 고정했습니다.

> [!CAUTION] 검증 분할에도 못 본 고장이 들어갑니다 — 학습을 멈출 때 주의
> 고장 유형을 train/val/test 셋으로 나누므로 **검증 분할도 외삽 시험**입니다.
> 그래서 검증 손실이 몇 epoch 만에 바닥에 닿고 그 뒤로 움직이지 않습니다.
> 그 상태에서 "최고 검증 시점" 으로 모델을 고르면 거의 학습되지 않은 초반
> 모델이 뽑힙니다. 실측에서 GAT 는 1,500 중 34 가 뽑혔습니다.
>
> 미지 N-1 학습에는 `--select phys` 를 씁니다
> ([06 문서](06_surrogate_training.md) §7.8).
