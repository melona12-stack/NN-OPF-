## 1. 무엇을 만들었나

```
부하·발전·선로상태  ──►  MLP  ──►  모선 전압 (Vm, Va)
   (case30: 161차원)          (53차원)
```

핵심 설계는 **무엇을 예측하지 않는가**입니다 ([03 문서](03_neural_networks.md) §5.1의 계약 그대로).

| 값 | 예측? | 이유 |
|---|---|---|
| 슬랙 θ | ❌ 계통의 기준값 그대로 | 위상 기준점 — **0이라고 가정하면 안 됩니다** (§7.4) |
| PV·슬랙 \|V\| | ❌ 설정값 그대로 | 데이터에서 확인: 오차 **7e-16** |
| PQ \|V\| | ✅ | 조류방정식이 결정 |
| 비슬랙 θ | ✅ | 조류방정식이 결정 |
| P, Q | ❌ 닫힌 식 | $S = V\overline{YV}$ |

case30이면 출력이 60개가 아니라 **53개**로 줄고, 줄어든 7개에는 근사가 아니라
**정확한 값**이 들어갑니다.

#### 코드로 보면 — 계약은 두 곳에 있습니다

첫째, **무엇을 예측할지 정하는 곳**입니다.

```python
# src/nnopf/models.py
class IOLayout:
    """어떤 모선의 무엇을 예측하는지 — 모델과 학습 코드가 공유하는 계약."""

    def __init__(self, sys: PowerSystem) -> None:
        self.nb = sys.nb                                  # 모선 수
        self.nl = len(sys.f_bus)                          # 선로 수

        self.pq = np.flatnonzero(sys.bus_type == PQ)          # |V| 를 예측할 모선
        self.nonslack = np.flatnonzero(sys.bus_type != SLACK) # θ 를 예측할 모선

        # 슬랙 기준위상. **0 이라고 가정하면 안 된다** — case118 은 30° 다 (§7.4)
        self.va_ref = np.zeros(self.nb)
        self.va_ref[sys.bus_type == SLACK] = sys.Va0[sys.bus_type == SLACK]

        self.in_dim  = 4 * self.nb + self.nl                  # Pd|Qd|p_ren|p_gen|status
        self.out_dim = len(self.pq) + len(self.nonslack)      # case30 이면 24 + 29 = 53
```

둘째, **예측하지 않기로 한 값을 정확한 값으로 채워 넣는 곳**입니다.
신경망 출력은 53개뿐인데 밖으로는 60개가 나가야 하니, 그 사이를 잇는 코드입니다.

```python
# src/nnopf/models.py — PowerFlowMLP.forward
def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
    """(B, in_dim) -> (Vm, Va) 각각 (B, nb)."""
    z = (x - self.in_mean) / self.in_std      # 입력 정규화 (통계는 학습 분할만)
    h = self.net(z)                           # MLP 본체
    if self.skip is not None:
        h = h + self.skip(z)                  # 선형 지름길 — 신경망은 잔차만 배운다

    vm_raw, va_raw = h[:, : self.n_vm], h[:, self.n_vm :]   # 53개를 24 + 29 로 쪼갠다

    if self.spec.vm_head == "scaled":
        # 시그모이드가 [0,1] 이므로 결과가 박스를 벗어날 수 없다 (03 문서 §5.3)
        vm = self.vm_lo + torch.sigmoid(vm_raw) * (self.vm_hi - self.vm_lo)
    else:
        vm = self.vm_lo + vm_raw * self.vm_hi
    va = self.va_mean + va_raw * self.va_std                # 표준화 해제

    # 여기가 핵심 두 줄이다.
    #   v_set  : PV·슬랙의 |V| 는 설정값 그대로 (오차 7e-16)
    #   va_ref : 슬랙 θ 는 계통 기준값 그대로
    # 그 위에 예측한 값만 index_copy 로 덮어쓴다.
    b = x.shape[0]
    Vm = self.v_set.expand(b, self.nb).index_copy(1, self.pq_idx, vm)
    Va = self.va_ref.expand(b, self.nb).index_copy(1, self.va_idx, va)
    return Vm, Va
```

**마지막 두 줄만 보시면 됩니다.** `expand` 로 정확한 값을 깔고, `index_copy` 로
예측한 자리만 덮습니다. 예측하지 않기로 한 7개는 **모델이 무슨 값을 내든 건드릴
수 없습니다** — 규칙이 손실함수에 있는 게 아니라 자료구조에 있습니다.

> [!NOTE] 물리 손실은 PyTorch로 옮겼습니다
> `physics_torch.ACPhysics` 가 [05 문서](05_dataset_generator.md) §7의 NumPy 잔차와
> **같은 식**을 미분 가능하게 구현합니다. 두 판이 기계정밀도(7.9e-15)로 일치하는지
> 테스트로 고정했습니다 — 물리 손실이 틀리면 학습이 조용히 잘못된 방향으로 갑니다.
>
> N-1은 $Y_{bus}$ 스택을 들고 있지 않고, 고장 선로가 기여하던 **4개 성분만**
> 빼는 방식으로 처리합니다. 정확히 같은 값이고 표본당 O(1)입니다.

## 2. 결과 — case30 (6,000 표본, 무작위 분할)

먼저 작은 계통부터. 더 큰 case118은 §2.3에 있습니다.

> [!IMPORTANT] "P/부하 %" 의 분모가 무엇인지 먼저 정해 둡니다
> $$\text{P/부하 \%} = \frac{\overline{\sum_i |\Delta P_i|}}{\overline{\sum_i |P^{spec}_i|}} \times 100$$
>
> 분모는 **모선별 지정 유효주입의 절댓값 합**입니다. 부하 모선에서는 $-P_d$,
> 발전 모선에서는 $+P_g$ 이므로 합치면 대략 "발전 + 부하" 가 됩니다 —
> 실측하면 case30 은 총부하의 **1.73배**, case118 은 **1.09배** 입니다.
>
> **같은 계통 안에서 모델끼리 비교하는 데는 문제가 없습니다** (분모가 같습니다).
> 이 문서의 모든 배수 비교가 그렇습니다. 다만 **계통 간 절대값**을 나란히 놓을
> 때는 분모가 다르다는 점을 기억해야 합니다 — case30 의 2.05% 와 case118 의
> 1.01% 는 서로 다른 것으로 나눈 값입니다.

시험 900표본. 잔차는 float64로 측정.

### 2.1 선형 기준선이 이렇게 강한 이유

조류방정식은 정상 운전 영역에서 **거의 선형**입니다. DC 조류계산과 고정점
선형화가 수십 년간 실무에서 쓰인 이유가 그것입니다. 실제로 최소제곱 선형모델이
$R^2 = 0.987$ 을 냅니다.

그래서 **순수 MLP는 선형 기준선을 못 이겼습니다** (Vm MAE 1.04e-4 vs 5.98e-5).
사상 전체를 처음부터 배우느라 선형 부분을 재현하는 데만 용량과 epoch을 씁니다.

해법은 **선형 지름길**입니다 — 입력에서 출력으로 가는 선형 층을 하나 더해
신경망이 **선형에 대한 보정만** 배우게 합니다. 편향을 0으로 초기화해 학습
시작점이 순수 선형모델이 되게 했습니다.

| 구조 | Vm MAE | Va MAE | ΔP [pu] |
|---|---|---|---|
| 순수 MLP (h128) | 1.04e-04 | 5.93e-04 | 0.1340 |
| + 선형 지름길 (h128) | 7.51e-05 | 4.34e-04 | 0.0778 |
| + 선형 지름길 (h256) | 6.26e-05 | 3.82e-04 | 0.0514 |

로드맵 M4의 "잔차연결 MLP"를 앞당겨 넣은 것이고, 이제 기본값입니다.
절제 실험은 §6에 있습니다.

### 2.2 ΔQ가 왜 나쁜가 — 야코비안으로 분해

> [!NOTE] "야코비안" 이 뭔지 먼저 — 이름만 무섭고 뜻은 **환율표**입니다
> 계통에서 전압을 아주 조금 흔들면 전력도 따라 흔들립니다. 그 **흔들리는
> 비율**이 야코비안입니다. $\partial Q/\partial|V|$ 라는 기호는
> **"전압 크기를 1 만큼 올리면 무효전력이 몇 만큼 따라 오르나"** 한 줄로
> 읽으면 됩니다.
>
> 환율이라고 생각하면 편합니다. 1,400원/달러라는 환율이 있으면
> "달러 오차 × 환율 = 원화 손해" 가 나오듯,
> **"전압 오차 × 야코비안 = 전력 오차"** 입니다.
>
> 중요한 것은 **환율이 모선마다 다르다**는 점입니다. 굵은 선로가 여럿 붙은
> 모선은 전압을 조금만 틀려도 전력이 크게 흔들립니다(환율이 높습니다).
> 외딴 모선은 같은 크기로 틀려도 별 탈이 없습니다.
>
> 그래서 아래 표는 **"오차가 얼마나 크냐" 가 아니라 "오차가 환율 높은 곳에
> 있느냐"** 를 묻습니다. 우리 손실 함수는 모든 모선을 똑같이 벌하니
> 환율을 전혀 모르는 채로 학습한다는 뜻이고, 그게 이 절의 결론입니다.

**어떻게 쪼갰나.** ΔQ 오차를 두 갈래로 나눕니다 — 위상($\theta$)을 틀려서
생긴 몫과, 전압 크기($|V|$)를 틀려서 생긴 몫입니다. 각 갈래는
**(그 변수의 오차) × (그 변수의 환율)** 입니다.

$\Delta Q \approx \underbrace{(\partial Q/\partial\theta)}_{\text{위상 환율}}\,\underbrace{\Delta\theta}_{\text{위상 오차}} + \underbrace{(\partial Q/\partial|V|)}_{\text{전압 환율}}\,\underbrace{\Delta|V|}_{\text{전압 오차}}$

로 나눠 PQ 모선에서 합산한 결과입니다 (case30 시험 표본, 정상 토폴로지).

| 모델 | ΔQ 실측 | **ΔV 기여** | Δθ 기여 | \|ΔV\| 평균 | \|Δθ\| 평균 |
|---|---|---|---|---|---|
| 선형 | 0.0110 | 0.0100 | 0.0088 | 3.13e-05 | 3.04e-04 |
| MLP | 0.0190 | **0.0171** | 0.0103 | 3.63e-05 | 1.12e-04 |

두 가지가 보입니다.

1. **ΔQ는 위상이 아니라 전압 오차가 지배합니다.** 무효전력이 전압에 강하게
   결합한다는 교과서적 사실(분리형 조류계산의 근거)이 그대로 나타납니다.
2. **오차의 크기보다 위치가 중요합니다.** MLP는 $|\Delta V|$ 가 1.16배 큰데
   ΔQ 기여는 **1.7배** 큽니다. 즉 오차가 $\partial Q/\partial|V|$ 가 큰 모선
   (강하게 연결된 모선)에 몰려 있습니다. 위상은 2.7배나 정확한데도 Q 기여는
   오히려 큽니다 — 같은 이유입니다.

> [!IMPORTANT] 균등 가중 MSE는 물리 지표와 정렬되어 있지 않습니다
> 모든 모선의 전압 오차를 똑같이 벌점하는 손실은, 그 오차가 전력으로 얼마나
> 증폭되는지를 모릅니다. **이것이 물리정보 손실이 존재하는 이유**이고,
> 다음에 시도할 것은 손실을 야코비안 민감도로 가중하는 것입니다.

> [!NOTE] 처음 세운 가설은 틀렸습니다 — 기록으로 남깁니다
> "무효전력은 이웃 모선 간 전압 *차이*에 민감하니, 오차가 공간적으로 함께
> 움직이면 상쇄될 것이다" 라고 짐작했습니다. 재 보니 MLP의 이웃 오차 상관이
> 더 낮은 건 맞았지만(0.527 vs 0.598), **차분 오차는 오히려 MLP가 작았습니다**
> (2.08e-04 vs 2.25e-04). 가설로는 설명이 안 됩니다.
>
> 그래서 짐작을 버리고 야코비안으로 직접 분해한 것이 위 표입니다.

### 2.3 더 큰 계통 — case118 (20,000 표본)

모선 118개, 선로 186개. 시험 3,000표본, 무작위 분할, 1,200 epoch(λ=0).
**기준선은 §7.6 수정 후 값입니다.**

| 모델 | Vm MAE | Va MAE [rad] | ΔP [pu] | P/부하 % |
|---|---|---|---|---|
| **선형 최소제곱** | 3.53e-05 | 2.82e-03 | **0.412** | **0.90** |

**전압은 신경망이, 물리 잔차는 선형이 앞섭니다.** 이 20,000 표본 설정에서는

> [!IMPORTANT] 이 문단은 한 번 통째로 틀렸었습니다
> 처음에는 여기에 "선형 30.80% vs MLP 1.56% — 신경망이 20배 이겼다"고
> 적었습니다. 그 30.80%가 **수치적으로 망가진 기준선**이었습니다 (§7.6).
> 상수열 239개가 설계행렬을 무너뜨려, 특이값 절단선이 어디 걸리느냐로 답이
> 30.80%와 0.90% 사이를 오갔습니다.
>
> 결과가 너무 좋으면 의심해야 합니다. §2.1이 말하듯 조류계산은 운전점 근처에서
> 거의 선형이라, 선형근사를 20배 이긴다는 건 애초에 나올 수 없는 숫자였습니다.

> [!TIP] 그런데 원인은 데이터였습니다
> 20,000 표본이 부족했던 것입니다. 60,000으로 늘리면 MLP가 1.30%까지
> 내려옵니다 — 아직 선형(0.61%)에는 못 미치지만 격차가 좁혀집니다.
> **§5.2에 학습곡선이 있습니다.** 표본 수를 P2 설정에서 그대로 가져온 것이
> 우리 설정에는 맞지 않았습니다.

> [!CAUTION] V위반 0.87%는 모델 탓이 아닙니다
> 선형과 MLP가 **똑같이** 0.87%인 게 힌트입니다. 시험 라벨 자체를 재 보면
> **0.8695%** 가 이미 $`[V_{min}, V_{max}]`$ 밖입니다 — case118의 일부 발전기
> 설정전압이 운전 한계를 살짝 벗어나 있습니다.
>
> 즉 대체모델이 만든 위반이 아니라 **데이터에서 물려받은 위반**입니다.
> 스케일링 인자 헤드가 보장하는 것은 "학습 라벨이 놓인 상자 안"이지
> "계통 운전한계 안"이 아니라는 점을 정확히 보여 줍니다.

## 3. λ 민감도 — P2의 곡선이 재현되지 않았습니다

P2 Table 9는 λ를 키우면 **전압은 나빠지고 물리 잔차는 좋아지는** 단조 트레이드오프를
보고합니다 ([04 문서](04_paper_review.md) §2.6). 우리 실험은 다릅니다.

λ를 **지도 항 대비 상대 가중치**로 제대로 정의한 뒤의 결과입니다 (§3.1).
λ=1이면 램프 시작 시점에 두 항이 같은 크기입니다.

| λ | Vm MAE | Va MAE | ΔP [pu] | ΔQ [pu] |
|---|---|---|---|---|
| **0** | 4.78e-05 | 3.37e-04 | **0.0369** | **0.0197** |
| 0.03 | **4.46e-05** | **3.23e-04** | 0.0416 | 0.0204 |
| 0.1 | 6.05e-05 | 3.67e-04 | 0.0620 | 0.0333 |
| 0.3 | 4.50e-05 | 3.29e-04 | 0.0539 | 0.0250 |
| 1 | 5.82e-05 | 4.01e-04 | 0.0662 | 0.0317 |
| 3 | 5.66e-05 | 3.75e-04 | 0.0617 | 0.0262 |

**물리 손실이 물리 지표조차 개선하지 못합니다.** ΔP·ΔQ 모두 λ=0이 최선이고,
전압도 λ=0.03에서 아주 근소하게 나아질 뿐입니다.

> [!IMPORTANT] 지금 시점의 해석 — 라벨이 이미 물리를 만족하기 때문으로 보입니다
> 우리 라벨은 조류방정식을 **1e-9 pu로 만족**합니다
> ([05 문서](05_dataset_generator.md) §3). 즉 물리 항의 최적점이 지도 항의
> 최적점과 **정확히 일치**합니다. 물리 손실이 새로운 정보를 주지 못하고,
> 최적화 지형만 어렵게 만드는 것으로 보입니다.
>
> 물리 손실이 값어치를 갖는 상황은 따로 있습니다 — 라벨이 부정확하거나,
> 라벨 없는 표본을 섞어 쓰거나(준지도), 데이터가 극히 적을 때입니다.
> P2에서 효과가 있었다면 라벨 정밀도나 모델 용량이 우리와 달랐을 가능성이 큽니다.
>
> 다만 §2.2가 가리키는 방향은 여전히 유효합니다. 문제는 "물리를 손실에
> 넣느냐"가 아니라 **"전압 오차를 민감도로 가중하느냐"** 입니다. 그건 아직
> 시도하지 않았습니다.

> [!NOTE] 여기까지 오는 데 정규화를 두 번 고쳤습니다
> 처음 스윕은 λ가 원단위라 λ=3e-3이 최악의 설정이 됐고, 두 번째는 잔차를
> 지정주입 RMS로 나눴는데 여전히 물리 항이 2000배 컸습니다. **크기를 직접
> 재 보고 나서야** λ를 비로 정의하는 지금 형태가 나왔습니다.
> "재현이 안 된다"고 말하려면 그 전에 정규화가 맞는지부터 확인해야 합니다.

### 3.1 원인 — λ는 두 손실 항의 *비*로 정의해야 합니다

두 항의 크기를 실제로 재 봤습니다 (60 epoch 학습 후, 학습 분할).

| 계통 | 지도 항 | 물리 항 | **물리/지도** | 라벨의 물리 항 (바닥) |
|---|---|---|---|---|
| case30 | 1.58e-02 | 3.42e+01 | **2.2e+03** | 1.06e-06 |
| case118 | 1.74e-01 | 3.69e+06 | **2.1e+07** | 1.57e-05 |

우리 지도 손실은 표준화 공간이라 $O(1)$ 인데 물리 항은 원단위 $\mathrm{pu}^2$ 입니다.
그래서 **λ=0.03이면 물리가 지도를 65배 지배합니다.** 학습이 망가지는 게 당연했습니다.

더 나쁜 건 **계통마다 이 비가 4자리씩 다르다**는 점입니다. 같은 숫자 λ가 case30과
case118에서 전혀 다른 뜻이 됩니다. P2의 λ=3e-3을 그대로 가져다 쓴 것이
가장 나쁜 설정이 된 이유입니다.

> [!IMPORTANT] 그래서 λ를 상대 가중치로 재정의했습니다
> 램프가 시작되는 epoch에서 두 항의 비를 측정해 나눕니다.
> **λ=1이면 그 순간 물리 항과 지도 항이 같은 크기**가 됩니다.
> 이제 계통 간·논문 간 비교가 가능한 값이고, 측정된 비는 결과 JSON에
> `phys_ref` 로 함께 남깁니다.
>
> 처음에는 잔차를 모선별 지정주입 RMS로 나누는 것으로 충분하다고 봤는데,
> 위 표가 보여주듯 **전혀 충분하지 않았습니다**. 크기를 직접 재 보기 전까지는
> 정규화가 됐는지 알 수 없습니다.

#### 코드 — 환산계수를 한 번 재서 계속 씁니다

```python
# src/nnopf/train.py — train() 안의 epoch 루프
phys_ref = 1.0     # 물리 항을 지도 항과 같은 크기로 맞추는 환산계수

for ep in range(cfg.epochs):
    lam = lambda_at(ep, cfg)          # 워밍업/램프 스케줄 (아래)

    if lam > 0 and phys_ref == 1.0:   # 램프가 시작되는 그 epoch 에 딱 한 번
        with torch.no_grad():
            k = tr[: min(1024, len(tr))]          # 학습 분할 앞쪽 1,024 표본
            Vm0, Va0 = model(b.X[k])
            s0 = supervised_loss(model, Vm0, Va0, b.Vm[k], b.Va[k]).item()   # 지도 항
            p0 = b.physics.loss(Vm0, Va0,
                                b.p_spec[k], b.q_spec[k], b.outage[k]).item()  # 물리 항
        phys_ref = max(p0, 1e-12) / max(s0, 1e-12)   # case30 2.2e3, case118 2.1e7

    for s in range(0, len(perm), cfg.batch):
        j = perm[s : s + cfg.batch]
        Vm, Va = model(b.X[j])
        sup = supervised_loss(model, Vm, Va, b.Vm[j], b.Va[j])
        loss = sup
        if lam > 0:
            # 여기가 재정의된 부분 — lam 을 phys_ref 로 나눠서 넣는다
            loss = loss + (lam / phys_ref) * b.physics.loss(
                Vm, Va, b.p_spec[j], b.q_spec[j], b.outage[j]
            )
```

**`lam / phys_ref` 이 전부입니다.** 이 나눗셈이 없으면 `lam=1` 이 case30 에서는
"물리를 2,200배 세게", case118 에서는 "2,100만배 세게"라는 뜻이 됩니다.
나누고 나면 `lam=1` = **그 순간 두 항이 같은 크기**로, 계통이 바뀌어도 뜻이 같습니다.

램프 스케줄은 이렇습니다.

```python
# src/nnopf/train.py
def lambda_at(epoch: int, cfg: TrainConfig) -> float:
    """λ 워밍업-램프 스케줄 (P2 §4.1).

    초기에는 전압 예측이 엉망인데 그 값을 조류방정식에 넣으면 잔차 기울기가
    폭주한다. 그래서 warmup 동안 λ=0 으로 지도학습만 하고, ramp 구간에서
    선형으로 올린다.
    """
    if cfg.lam <= 0 or epoch < cfg.lam_warmup:          # 처음 20 epoch: 물리 항 끄기
        return 0.0
    if epoch >= cfg.lam_warmup + cfg.lam_ramp:          # 70 epoch 이후: 최대값
        return cfg.lam
    return cfg.lam * (epoch - cfg.lam_warmup + 1) / cfg.lam_ramp   # 그 사이는 선형
```

## 4. 미지 N-1 일반화 — 아직 신경망의 근거가 되지 못합니다

시험용 고장이 학습·검증에 단 한 번도 나오지 않는 분할입니다
([05 문서](05_dataset_generator.md) §9). "본 적 없는 계통 구성에서도 되는가"를
재는 유일한 방법입니다.

| 계통 | 분할 | 모델 | Vm MAE | P/부하 % | 전압한계 위반 % |
|---|---|---|---|---|---|
| case30 | 무작위 | 선형 | 5.98e-05 | 1.33 | 0.40 |
| case30 | 무작위 | MLP | 4.78e-05 | **1.16** | 0.39 |
| case30 | **미지 N-1** | 선형 | 5.07e-04 | **2.24** | **0.00** |
| case30 | **미지 N-1** | MLP | 6.03e-04 | 6.75 | **0.00** |
| case118 | 무작위 | 선형 | 3.53e-05 | **0.90** | 0.87 |
| case118 | 무작위 | MLP | 3.22e-05 | 1.56 | 0.87 |
| case118 | **미지 N-1** | 선형 | 8.47e-05 | **1.30** | 0.85 |
| case118 | **미지 N-1** | MLP | 9.83e-05 | 5.16 | 0.85 |

> [!IMPORTANT] 이 표는 `--select loss` · 작은 표본에서 잰 값입니다
> 미지 N-1 두 줄은 선택 규칙이 망가진 상태에서 나왔습니다 (§7.8). 표본 수도
> case30 6,000 / case118 20,000 으로 §5 의 교차점보다 아래입니다.
>
> **확정 수치는 §7.8.2 의 표를 보세요** — 같은 규칙·충분한 표본으로 네 칸을
> 다시 채웠습니다 (case30 미지 N-1 선형 2.05 %, case118 미지 N-1 선형 1.01 %).
> 아래 §4.1 의 토폴로지 분해도 같은 이유로 옛 규칙 값입니다.

> [!CAUTION] 이 절의 결론이 정반대로 바뀌었습니다
> 처음에는 여기에 이렇게 적었습니다 — "본 적 없는 고장에서 선형이 완전히
> 무너진다(41.90%, 전압 한계 23.59% 위반). 신경망은 위반 0.00%. **이것이 이
> 프로젝트에서 신경망을 쓰는 근거다.**"
>
> **전부 §7.6의 망가진 기준선 때문이었습니다.** 제대로 푼 선형은 미지 N-1에서
> 2.24%(case30) / 1.30%(case118)이고 전압 한계를 **위반하지 않습니다.**
> 오히려 두 계통 모두 **MLP보다 낫습니다.**

지금 상태를 정직하게 요약하면 이렇습니다.

- **미지 N-1은 MLP의 약점입니다** — 무작위 분할 대비 case30 5.8배(1.16→6.75),
  case118 3.5배(1.46→5.05) 나빠집니다. 선형은 각각 1.7배, 1.4배만 나빠집니다.
- **스케일링 인자 헤드의 위반 0% 보장은 여전히 참입니다.** 다만 이 데이터에서는
  선형도 위반하지 않아, **이 실험이 그 장점을 보여주지는 못합니다.** 라벨이
  한계 근처에 몰린 계통에서 다시 확인해야 합니다.
- **신경망을 쓸 근거는 §5.1로 옮겨갔습니다** — 표본을 충분히 주면(case30
  21,000) MLP가 선형을 2.4배 이깁니다.

### 4.1 어디서 나빠지는가 — 토폴로지로 쪼개 보면 갈라집니다

case118 미지 N-1 시험 표본 3,016개를 **정상 토폴로지**(2,237개)와
**본 적 없는 고장**(779개)으로 나눠 잰 결과입니다.

| 표본 종류 | 선형 | MLP+지름길 | 어느 쪽이 나은가 |
|---|---|---|---|
| 정상 토폴로지 | **0.84%** | 1.26% | 선형 1.5배 |
| **미지 N-1** | **2.62%** | **16.38%** | 선형 6.3배 |
| 전체 평균 | **1.30%** | 5.16% | 선형 4.0배 |

> [!IMPORTANT] 열화가 퍼져 있지 않고 한 곳에 뭉쳐 있습니다
> MLP는 **정상 토폴로지에서 1.26%** — 무작위 분할(1.56%)과 사실상 같습니다.
> 부하·발전이 아무리 달라져도 문제가 없다는 뜻입니다.
>
> 그런데 **본 적 없는 고장에서만 16.38%**, 13배 나빠집니다. 상위 1% 오차 표본을
> 뽑아 보면 **100%가 N-1 표본**입니다. 같은 구간에서 선형은 0.84% → 2.62%로
> 3.1배만 나빠집니다 — **토폴로지 외삽은 MLP 쪽이 훨씬 취약합니다.**
>
> 즉 이 모델의 약점은 "정확도가 전반적으로 부족하다"가 아니라
> **"토폴로지 변화를 외삽하지 못한다"** 라는 한 가지로 특정됩니다.

이유는 구조에서 바로 나옵니다. MLP에게 선로 상태는 입력 벡터 끝에 붙은 **186개의
0/1 비트**일 뿐입니다. 그 비트가 계통 그래프의 어느 간선을 뜻하는지, 그 간선이
끊기면 조류가 어디로 우회하는지 — 모델에는 그 정보가 **없습니다.** 학습에서 본
고장은 통째로 외워서 처리하고, 못 본 고장은 손쓸 방법이 없습니다.

> [!TIP] M4에서 그래프 신경망을 쓸 근거가 여기서 나옵니다
> GNN은 계통 그래프 위에서 이웃끼리 메시지를 주고받으므로, **선로를 하나 지우는
> 것이 곧 메시지 경로를 하나 지우는 것**입니다. 못 본 고장이어도 구조가
> 자동으로 반영됩니다.
>
> 그리고 이 표가 **M4의 목표 수치**를 정해 줍니다 — **미지 N-1에서 선형의
> 2.62%를 넘는 것**입니다. 지금 MLP는 16.38%로 6배 뒤져 있습니다.
> 전체 평균만 보고 있었으면 이 목표가 안 보였을 것입니다.

> [!NOTE] 검증 손실만 보고 잘못 읽을 뻔했습니다
> 학습 중 검증 손실이 2.95에서 멈춰 있고 학습 손실은 0.013까지 떨어져서
> (**234배 차이**) "일반화에 완전히 실패했다"고 읽었습니다. 실제로는 위 표대로
> **선형에 4.0배 뒤집니다** (선형 1.30% vs MLP 5.16%).
> 검증 손실이 말해 주는 것과 실제 성능은 방향까지 다를 수 있습니다.
>
> 검증 손실은 **표준화 공간의 제곱 평균**이라 소수의 큰 오차가 지배합니다.
> 라벨 표준편차가 $10^{-5}$ 수준인데 최악 표본의 오차가 $6\times10^{-2}$ 이면
> 그 한 표본이 혼자 $10^{6}$ 을 기여합니다. **학습을 멈출 시점을 정하는
> 데는 맞는 지표지만, 성능을 읽는 지표로 쓰면 안 됩니다.**

## 5. 학습곡선 — 표본이 부족했던 것이 맞습니다

P1 §6.3이 요구한 "필요 표본 수를 실측으로 정하라"에 대한 답입니다.
**이 절이 이 단계에서 제일 중요한 결과입니다** — §2·§4의 결론을 바꿉니다.

### 5.1 case30 — 표본을 5배 늘리자 신경망이 앞섰습니다

30,000 표본으로 다시 만들어, 학습 분할 크기만 바꿔 가며 600 epoch씩 돌렸습니다
(RTX 5060, 배치 256, 선형 기준선은 §7.6 수정 후).

| 학습 표본 | Vm MAE | Vm 최대 | ΔP [pu] | P/부하 % |
|---|---|---|---|---|
| **선형 기준선** | 5.565e-05 | 1.705e-02 | 0.0319 | **1.00** |
| 2,000 | 3.818e-04 | 9.094e-02 | 0.2385 | 7.47 |
| 4,000 | 7.870e-05 | 1.505e-02 | 0.0811 | 2.54 |
| 8,000 | 3.031e-05 | 9.004e-03 | 0.0365 | 1.14 |
| 16,000 | 1.503e-05 | 2.569e-03 | 0.0176 | 0.55 |
| **21,000** | **1.192e-05** | **2.277e-03** | **0.0135** | **0.42** |

> [!IMPORTANT] 원인은 모델이 아니라 데이터였습니다
> 6,000 표본에서 MLP는 1.16%로 선형(1.00%)에 졌습니다. **21,000 표본에서는
> 0.42%로 2.4배 이깁니다.** 전압은 4.7배, 최대 오차는 7.5배 앞섭니다.
>
> 8,000 근처가 교차점입니다. P2가 case30에 쓴 6,000은 **그 아래**입니다.
> 논문 설정을 그대로 따르는 것이 항상 옳지는 않습니다 — 우리 입출력 계약과
> 모델 용량이 P2와 다르기 때문입니다.

16,000 → 21,000에서도 계속 좋아지므로 **아직 포화하지 않았습니다.** 어디서
멈추는지는 아직 모릅니다.

### 5.2 case118 — 아직 못 이겼습니다

60,000 표본으로 같은 실험을 했습니다.

| 학습 표본 | Vm MAE | ΔP [pu] | P/부하 % |
|---|---|---|---|
| **선형 기준선** | 3.481e-05 | 0.2777 | **0.61** |
| 7,000 | 8.477e-05 | 2.0460 | 4.48 |
| 14,000 | 8.755e-05 | 2.2780 | 4.98 |
| 28,000 | 4.202e-05 | 0.9812 | 2.15 |
| **42,000** | **3.208e-05** | 0.5951 | 1.30 |

전압은 근소하게 앞섰지만(3.21e-05 vs 3.48e-05) **물리 잔차는 선형이 2.1배
낫습니다.** case30과 같은 추세이므로 표본을 더 늘리면 뒤집힐 여지가 있지만,
**지금은 못 이긴 것이 사실입니다.**

> [!CAUTION] 7,000 → 14,000 구간이 오히려 나빠졌습니다
> 4.48% → 4.98%. 학습곡선은 단조 감소해야 하는데 한 번 튀었습니다. 같은
> 600 epoch을 썼으므로, 표본이 늘어난 만큼 갱신 횟수도 늘어 최적화 조건이
> 달라진 탓으로 보입니다. **한 점만 보고 결론 내면 안 되는 이유**입니다.

### 5.3 확정된 기준선 — M4는 이 표를 넘어야 합니다

§5.1·§5.2는 600 epoch 짜리 학습곡선이라 아직 덜 학습된 값입니다. 같은
데이터로 **1,500 epoch 까지 끝까지** 돌려 M4 비교표의 기준을 못박았습니다.

| 계통 | 학습 표본 | 선형 기준선 | **MLP + 선형지름길** | 승자 |
|---|---|---|---|---|
| case30 | 21,000 | 1.00% | **0.35%** | 신경망 2.9배 |
| case118 | 42,000 | **0.61%** | 1.14% | 선형 1.9배 |

세부 수치 (P/부하 외):

| 계통 | 모델 | Vm MAE | Vm 최대 | Va MAE | ΔP [pu] |
|---|---|---|---|---|---|
| case30 | MLP | 8.877e-06 | 1.788e-03 | 4.490e-05 | 0.0111 |
| case118 | MLP | 3.544e-05 | 8.022e-03 | 1.030e-03 | 0.5222 |

> [!IMPORTANT] 한 줄 요약 — MLP는 작은 계통에서만 이깁니다
> case30에서는 신경망이 **2.9배** 앞섭니다. case118에서는 **1.9배 뒤집니다.**
> 계통이 커질수록 불리해진다는 뜻이고, 이것이 M4의 문제 정의입니다.

case118은 **epoch 1,214에서 조기 종료**됐습니다(최고 1,014). 더 돌려도
나아지지 않는다는 뜻이므로, 1.14%는 **이 구조·이 데이터에서 MLP의 한계**입니다.
**더 돌려서** 넘을 수 있는 선은 아닙니다 — 표본을 더 늘리는 쪽은 아직
열려 있습니다 (§5.2·§10).

반면 case30은 1,500 epoch을 다 쓰고도 검증 손실이 아직 내려가는 중이었습니다.
작은 계통은 여전히 여유가 있습니다.

> [!TIP] M4의 목표
> **case118 무작위 분할에서 0.61%를 넘을 것.** 그리고 비교는 반드시 같은
> 표본 수(42,000)·같은 분할·같은 평가 코드로 해야 합니다. 하나라도 다르면
> 무엇 덕분에 좋아졌는지 알 수 없습니다.
>
> 부차 목표는 미지 N-1에서 선형의 2.62%를 넘는 것입니다 (§4.1).

## 6. 지름길과 손실을 파고든 실험 셋

같은 400 epoch, 같은 데이터에서 지름길만 끄고 켠 비교입니다.

| 구조 | Vm MAE | Va MAE | ΔP [pu] |
|---|---|---|---|
| 지름길 없음 | 5.39e-05 | 3.50e-04 | 0.0648 |
| **지름길 있음** | **4.78e-05** | **3.37e-04** | **0.0369** |

물리 잔차가 **1.8배** 좋아집니다. 전압 오차 개선(1.1배)보다 물리 개선이 훨씬 큰데,
이것도 §2.2와 같은 이야기입니다 — 지름길이 오차의 *위치*를 개선합니다.

### 6.1 지름길을 선형 해로 출발시키면? — 학습이 오히려 망칩니다

**먼저 말이 안 맞는 곳이 하나 있었습니다.** `models.py` 는 지름길의 목적을
이렇게 적어 두었습니다.

> 입력에서 출력으로 가는 선형 층을 하나 더해 두면 신경망은 **잔차만** 배우면 된다.

그런데 지름길은 **0 으로 초기화되어 본체와 함께 학습**됩니다. 즉 그 분업은
**구조가 아니라 희망**입니다. 신경망은 여전히 선형 부분을 처음부터 다시 배웁니다.
그런데 우리는 그 선형 해를 **이미 닫힌 형태로 갖고 있습니다** (2.05%).

그래서 거기서 출발시켜 봤습니다 (`--skip-init lstsq`).

핵심은 **모델 자신의 출력 공간에서** 최소제곱을 푸는 것입니다. 지름길은 헤드
**직전** 값을 내놓으므로, 목표도 그 자리로 옮겨야 합니다.

$$
t^{vm} = \mathrm{logit}\!\left(\frac{|V| - V^{lo}}{V^{hi}-V^{lo}}\right),
\qquad
t^{va} = \frac{\theta - \bar\theta}{\sigma_\theta}
$$

시그모이드를 거꾸로 통과시키는 것입니다. 상자에 5% 여유가 있어(`vm_margin`)
라벨이 항상 안쪽이므로 로짓이 발산하지 않습니다. 본체 마지막 층도 0 으로
눌러야 출발점이 **정확히** 선형 해가 됩니다.

**첫 결과 — case30 · 6,000 표본 · 미지 N-1 · 400 epoch.**

| 초기화 | 학습 **전** | 학습 **후** | 고른 epoch |
|---|---|---|---|
| 선형 기준선 (참고) | — | **2.243** | — |
| `zero` (지금까지의 기본값) | 117.9 | 4.732 | 398 |
| **`lstsq`** | **2.257** | 2.601 | **11** |
| **`lstsq` + 얼림** | 2.257 | **2.265** | 4 |

> [!CAUTION] 완벽한 출발점을 줘도 학습이 나빠집니다
> `lstsq` 초기화 모델은 **학습 전에 이미 2.257%** 입니다 — 선형 기준선과
> 사실상 같습니다. 그런데 400 epoch 을 학습하면 **2.601% 로 나빠집니다.**
> 고른 epoch 이 **11** 이라는 게 결정적입니다 — 11 epoch 만에 최고점을 찍고
> 그 뒤로는 계속 나빠지기만 합니다.
>
> **이건 최적화 문제가 아닙니다.** 초기화가 나빠서도, 학습이 부족해서도
> 아닙니다. 완벽한 출발점에서 경사하강을 시작했더니 **목적함수가 모델을 미지
> N-1 물리에서 멀어지는 쪽으로 끌고 갔습니다.**
>
> 지름길을 얼리면(`--skip-freeze`) 2.265% 로 선형 기준선 자리에 머뭅니다.
> 본체가 400 epoch 동안 배운 것의 순 기여가 **거의 0** 이라는 뜻입니다.

<br>

**무엇이 달라졌나.** 지금까지 우리는 "신경망이 선형을 못 이긴다" 를 **모델이
부족해서** 라고 읽어 왔습니다. §5.1 에서 표본을 늘려 보고, §7.7 에서 층을
늘려 보고, §6.2 에서 손실을 가중해 봤습니다. 이 실험은 다른 것을 말합니다 —
**정답에서 출발해도 학습이 그걸 망칩니다.**

즉 문제는 **일반화**이지 표현력이나 최적화가 아닙니다. 학습 분할에서 본
고장들에 맞추는 방향이, 못 본 고장에서는 틀린 방향입니다. 그리고 선형 모델은
애초에 그렇게 맞출 자유도가 없어서 살아남습니다.

> [!NOTE] 아직 작은 실험입니다
> 6,000 표본 · 400 epoch 입니다. §5.1 이 보여주듯 case30 은 8,000 근처가
> 교차점이라 이 크기는 **아래쪽**입니다. 30,000 표본 · 1,500 epoch 으로
> 다시 재야 합니다 (작업 30·31). 그때 결론이 달라질 수 있습니다.

#### 다시 쟀더니 결론이 뒤집혔습니다 — 그리고 선형을 이겼습니다

바로 위 [!NOTE] 가 걱정한 그대로였습니다. 30,000 표본 · 1,500 epoch 으로
다시 재니 **정반대 결과**가 나왔습니다.

| 초기화 | 진짜 학습 **전** | **1 epoch 후** | 학습 **후** | 고른 epoch | 시간 |
|---|---|---|---|---|---|
| 선형 기준선 (참고) | 2.047 | — | 2.047 | — | — |
| `zero` (기본값) | 118.06 | 15.10 | 4.000 | 960 | 4분 |
| **`lstsq`** | **2.072** | 3.21 | **1.455** | 925 | 13분 |
| **`lstsq` + 얼림** | **2.072** | 2.158 | **1.458** | 1,215 | 15분 |

> [!CAUTION] 가운데 열은 "학습 전"이 아닙니다 — 처음에 그렇게 적었다가 고쳤습니다
> 학습 루프는 한 epoch 안에서 **학습을 먼저 하고 그다음에 검증**합니다.
> 그래서 이력의 첫 줄은 초기화 직후가 아니라 **1 epoch 을 이미 돌린 뒤**입니다.
> 초기화 품질은 이력에 아예 기록되지 않습니다.
>
> 그래서 **따로 쟀습니다.** 학습을 한 걸음도 시키지 않고, 초기화만 한
> 모델을 바로 시험 집합에 넣었습니다 (첫 열). 실제 실험과 **똑같은 크기**
> — case30 30,000 표본, case118 60,000 표본, 둘 다 미지 N-1 입니다.
>
> | 진짜 학습 전 | case30 (30,000) | case118 (60,000) |
> |---|---|---|
> | 선형 기준선 | 2.047 | 1.010 |
> | **`lstsq` 초기화 직후** | **2.072** | **1.020** |
> | `zero` 초기화 직후 | 118.06 | 266.87 |
>
> `lstsq` 초기화는 **선형 기준선과 사실상 같은 자리**에서 출발합니다
> (차이 1% 이내). 당연합니다 — 지름길 가중치를 선형 최소제곱 해로
> 채워 넣었으니, 본체가 아직 아무 말도 안 하는 상태에서는 모델이
> 곧 선형 모델입니다.
>
> 그러니 위 표의 3.21 은 **첫 epoch 이 좋은 출발점을 망가뜨린 결과**입니다.
> lr 2e-3 이 한 epoch 만에 2.07% 짜리 해를 3.21% 로 밀어냈고, 그걸 되찾는 데
> 900 epoch 이 걸렸습니다.
>
> 반대쪽도 보세요. `zero` 는 **118%** 에서 출발합니다 — 전압을 통째로
> 틀리게 내놓는 상태입니다. 같은 1,500 epoch 이 하나는 118% 를 4.0% 로
> 끌어내리는 데 다 쓰이고, 다른 하나는 2.07% 에서 1.46% 로 다듬는 데
> 쓰입니다. **출발점이 학습 예산을 어디에 쓸지를 정합니다.**

> [!TIP] 네 칸 중 하나가 뒤집혔습니다 — 미지 N-1 에서 처음으로 선형을 이겼습니다
> **1.455% vs 선형 2.047% — 신경망이 1.41배 이깁니다.**
> 지금까지 이 칸의 최고는 GAT 12층의 2.605%(선형에 1.27배 짐)였습니다.
>
> 그리고 **모든 지표에서 이깁니다.**
>
> | | 선형 | MLP + `lstsq` | |
> |---|---|---|---|
> | P/부하 % | 2.047 | **1.455** | 1.41배 |
> | Vm MAE | 4.945e-04 | **4.814e-04** | 1.03배 |
> | Va MAE | 1.527e-03 | **1.307e-03** | 1.17배 |
> | ΔP [pu] | 0.0653 | **0.0465** | 1.41배 |
> | V 한계 위반 | 0.00% | 0.00% | 같음 |
>
> **13분 걸렸습니다.** GAT 8층이 54분, 12층이 71분입니다.

**같은 모델, 같은 데이터, 같은 epoch 수입니다. 출발점만 다릅니다.**
`zero` 에서 출발하면 4.000%, 최소제곱 해에서 출발하면 1.455% —
**2.75배 차이**가 오직 초기화에서 나옵니다.

**6,000 에서는 왜 반대였나.** 학습 이력을 나란히 놓으면 보입니다
(얼린 쪽 = 본체만 학습한 순수 기여).

| 표본 | 학습 전 | 학습 후 | 방향 |
|---|---|---|---|
| 6,000 | 2.257 | 2.265 | 제자리 (본체 기여 ≈ 0) |
| **30,000** | **2.158** | **1.465** | **개선 (본체가 실제로 배움)** |

6,000 표본에서는 본체가 배울 것이 없었습니다 — 못 본 고장에 대해 뭔가를
배우기에는 본 고장이 너무 적었습니다. 30,000 에서는 배울 것이 생겼고,
**좋은 출발점 위에 그걸 얹으니** 선형을 넘었습니다.

> [!IMPORTANT] 그래서 §6.1 의 첫 결론은 철회합니다
> 위 [!CAUTION] 에 "완벽한 출발점을 줘도 학습이 나빠진다", "문제는 일반화이지
> 표현력이나 최적화가 아니다" 라고 적었습니다. **6,000 표본에서만 맞는
> 말이었습니다.**
>
> 표본이 충분하면 학습은 출발점을 망치지 않고 **개선합니다.**
> 남는 것은 원래 결론의 절반뿐입니다 — 지름길을 얼려도(1.458%) 안 얼려도
> (1.455%) 거의 같으니, **지름길을 더 학습시키는 것은 여전히 무의미합니다.**
> 좋은 출발점을 주고 본체에게 보정만 맡기면 됩니다.

> [!CAUTION] 이 결과가 §7.7 의 이야기를 뒤집지는 않습니다
> "MLP 가 GAT 를 이겼으니 그래프 신경망이 필요 없다" 로 읽으면 안 됩니다.
> 이번에 이긴 것은 **`lstsq` 초기화를 받은 MLP** 이고, GAT 에는 아직 그걸
> 적용해 보지 않았습니다. `GATSpec` 에도 같은 `skip_init` 옵션이 있습니다.
>
> 공정한 비교는 **GAT + `lstsq`** 대 **MLP + `lstsq`** 입니다. 그전까지는
> "초기화가 구조보다 크게 기여했다" 까지만 말할 수 있습니다.

#### case118 에도 걸어 봤습니다 — 4.1배 좋아졌지만 아깝게 졌습니다

같은 장치를 가장 크게 지던 칸에 걸었습니다 (case118 · 60,000 · 미지 N-1).

| | P/부하 % | Vm MAE | Va MAE | ΔP [pu] |
|---|---|---|---|---|
| MLP 기준선 (`zero`) | 4.483 | 9.732e-05 | — | 2.0496 |
| **MLP + `lstsq`** | **1.097** | **7.560e-05** | **1.587e-03** | 0.5017 |
| 선형 최소제곱 | **1.010** | 8.640e-05 | 1.827e-03 | **0.4617** |

**4.483% → 1.097%, 4.1배 좋아졌습니다.** 7분 걸렸습니다.
그런데 선형(1.010%)에 **1.09배 집니다** — 아깝게 못 넘었습니다.

> [!IMPORTANT] 전압은 이기는데 물리 잔차가 집니다 — 이 패턴이 **네 번째**입니다
> | | 선형 | MLP + `lstsq` | |
> |---|---|---|---|
> | Vm MAE | 8.640e-05 | **7.560e-05** | 신경망 **1.14배 승** |
> | Va MAE | 1.827e-03 | **1.587e-03** | 신경망 **1.15배 승** |
> | ΔP [pu] | **0.4617** | 0.5017 | 선형 1.09배 승 |
>
> **전압 두 지표를 다 이기고도 물리 잔차에서 집니다.** §2.2(MLP), §7.7.1(게이팅),
> §7.8.1(GAT) 에 이어 같은 모양이 네 번째로 나왔습니다.
>
> §6.2 에서 이 진단을 받아 손실을 야코비안 민감도로 가중해 봤지만 **효과가
> 없었습니다.** 진단은 반복해서 재현되는데 처방이 아직 없습니다.

**다음 수는 학습률입니다.** 위 [!CAUTION] 이 보여주듯 첫 epoch 이 좋은 출발점을
망가뜨립니다. case118 도 실제로 재 봤습니다 — 초기화 직후는 **1.020%**
(선형 1.010% 와 사실상 같음)였습니다. 그런데 1 epoch 뒤에 **6.08%**,
**6배로 튕겨 나갔습니다.** 597 epoch 을 써서 겨우 0.93%(검증)까지
기어 돌아왔고, 시험 집합에서는 1.097% 로 끝났습니다.

> [!NOTE] 그러니까 이 실험은 사실 **제자리걸음**이었습니다
> 초기화 1.020% → 학습 후 1.097%. 1,500 epoch 과 7분을 쓰고
> **오히려 조금 나빠졌습니다.** 4.483% → 1.097% 라는 4.1배 개선은
> 학습이 만든 것이 아니라 **초기화가 만든 것**입니다.
>
> 학습이 한 일은 첫 epoch 에 6배로 망가뜨린 뒤 596 epoch 동안
> 그걸 되돌린 것뿐입니다. case30 에서는 되돌린 뒤에 더 나아갔지만
> (2.072 → 1.455), case118 에서는 되돌리기만 하고 끝났습니다.

lr 을 낮추거나 워밍업을 두면 **출발점을 지킨 채** 보정만 얹을 수 있지
않을까 — 그렇게 예상했습니다. **바로 다음 절에서 그 예상이 틀렸음을
확인합니다.**

#### 학습률을 10분의 1 로 낮춰 봤습니다 — 가설은 맞았고, 처방은 틀렸습니다

바로 위 문단이 세운 예상을 그대로 시험했습니다. **학습률만** 2e-3 → 2e-4 로
바꾸고 나머지는 전부 같게 두었습니다 (작업 36·37).

**가설은 정확히 맞았습니다.** 낮은 학습률은 좋은 출발점을 지켜 냅니다.

| case118 · 60,000 | 1 epoch 후 (검증) | 최고 검증 | 시험 P/부하 % | Vm MAE | ΔP [pu] |
|---|---|---|---|---|---|
| lr 2e-3 (32번) | 6.083 | 0.93 | 1.097 | 7.560e-05 | 0.5017 |

첫 epoch 의 폭주가 **6.08% → 1.40%** 로 사라졌습니다. 예측한 그대로입니다.

**그런데 최종 성적은 오히려 나빠졌습니다.** 1.097% → 1.125%.
597 epoch 을 들여 폭주를 되돌리던 쪽이, 폭주가 아예 없던 쪽보다 낫습니다.

> [!CAUTION] case30 에서는 그냥 망했습니다 — 이쪽이 더 결정적입니다
> 같은 변경을 case30 에 걸었더니(37번) 이렇게 됐습니다.
>
> | case30 · 30,000 | 1 epoch 후 | 고른 epoch | 시간 | 시험 P/부하 % |

> | lr 2e-3 (30번) | 3.21 | 925 | 13분 | **1.455** |

> 200 epoch 을 기다리다 포기했고, 전체가 1분 만에 끝났습니다.
>
> 즉 lr 2e-4 에서 case30 모델은 **아무것도 배우지 못했습니다.** 초기화 자리

> 선형(2.047%)한테도 집니다 — **1.455% 라는 승리를 통째로 잃었습니다.**

> [!IMPORTANT] 그래서 결론을 뒤집습니다 — **첫 epoch 의 폭주는 낭비가 아니었습니다**
> 앞 절에서 "첫 epoch 이 좋은 출발점을 망가뜨린다, lr 을 낮춰 지켜야 한다" 고
> 적었습니다. **진단은 맞았지만 처방이 틀렸습니다.**
>
> 두 실험을 나란히 놓으면 그림이 분명합니다.
>
> | | 출발점을 지켰나 | 본체가 배웠나 | 최종 |
> |---|---|---|---|
> | case30 lr 2e-3 | ✗ (2.07 → 3.21) | **✓ (925 epoch)** | **1.455** |

>

> 초기 해에서 튕겨 나가야 본체가 비선형 보정을 배울 수 있는 자리까지
> 갑니다. 걸음을 줄이면 초기 해 근처의 좁은 골짜기를 못 벗어나고,
> 그러면 **선형 모델 그 자체 이상은 될 수 없습니다.**
>
> 최종 성적을 정하는 것은 "출발점이 살아남았나" 가 아니라
> **"본체가 얼마나 배웠나"** 입니다.

> [!NOTE] 그래도 §7.7.0 의 교훈은 살아 있습니다 — 방향만 반대입니다
> §7.7.0 에서 "깊은 GAT 는 lr 을 낮춰야 한다" 를 배웠고, 여기서는
> "`lstsq` 초기화는 lr 을 **낮추면 안 된다**" 를 배웠습니다. 서로 반대지만
> 같은 말입니다 — **학습률에 기본값이란 없고, 구조와 초기화가 바뀌면
> 매번 다시 재야 합니다.**
>
> 값싸게 재는 법도 배웠습니다. 37번은 **1분** 만에 끝났습니다.
> 조기 종료가 "이 학습률로는 안 배운다" 를 스스로 알려 줍니다.

**전압은 여전히, 그리고 더 크게 이깁니다.** case118 lr 2e-4 는 Vm MAE 에서
선형을 **1.23배** 이깁니다 — 지금까지 중 가장 큰 격차입니다(32번은 1.14배).
그런데 같은 변경이 ΔP 는 0.5017 → 0.5145 로 **더 나쁘게** 만들었습니다.

> [!IMPORTANT] 다섯 번째이자, 처음으로 **방향까지** 확인된 관찰입니다
> §2.2, §6.1, §7.7.1, §7.8.1 에서 "전압은 이기는데 물리 잔차는 진다" 를
> 네 번 봤습니다. 지금까지는 서로 다른 실험을 비교한 것이라
> **우연히 그런 모델들이었을 가능성**이 남아 있었습니다.
>
> 이번엔 다릅니다. **같은 모델·같은 데이터에서 학습률 하나만 바꿨는데**
> 전압이 좋아진 만큼 물리가 나빠졌습니다.
>
> | lr | Vm MAE | ΔP [pu] |
> |---|---|---|
> | 2e-3 | 7.560e-05 | 0.5017 |
> | 2e-4 | **7.014e-05** (7.2% 개선) | 0.5145 (2.6% 악화) |
>
> 상관이 아니라 **맞바꿈(trade-off)** 이라는 뜻입니다. 그리고 이건
> §2.2 의 야코비안 분석이 예측한 바로 그 모양입니다 — 전압 MSE 를 더
> 줄이려 들수록, 손실이 모르는 "환율 높은 모선" 을 더 희생하게 됩니다.
>
> **처방은 여전히 없습니다.** §6.2 의 야코비안 가중은 효과가 없었습니다.
> 다만 진단이 이제 우연이 아님은 확실합니다.

**학습률 손잡이는 여기서 닫습니다.** case118 은 양쪽 방향을 다 돌려 봤고
둘 다 선형을 못 넘었습니다. 남은 것은 §6.1 이 스스로 열어 둔 질문입니다 —
**GAT 에 `lstsq` 를 걸면 어떻게 되나.** 아직 아무도 안 해 봤습니다 (작업 38).

### 6.2 야코비안 가중 손실 — 세 번 가리킨 방향이었는데, 효과가 없었습니다

**무엇을 의심했나.** 지금 손실은 모든 모선의 전압 오차를 **똑같이** 벌합니다.
그런데 같은 크기의 오차라도 어느 모선에 있느냐에 따라 전력 잔차 기여가 달라집니다.
서로 다른 세 실험이 정확히 그 모양을 보여 줬습니다.

| 어디서 | 무엇이 보였나 |
|---|---|
| §2.2 (MLP) | 위상은 2.7배 정확한데 ΔQ 기여는 오히려 큼 |
| §7.8.1 (GAT) | 전압이 가장 정확한데 물리 잔차는 가장 나쁨 |
| §7.7.1 (게이팅) | 게이팅을 끄면 위상은 더 정확한데 물리 잔차는 1.6배 나쁨 |

**무엇을 했나.** 각 예측 변수의 **민감도**를 재서 손실 가중치에 곱했습니다.
변수 $x_j$ 를 조금 움직였을 때 잔차 벡터가 얼마나 움직이는가 — 잔차 야코비안의
$j$ 번째 열 크기입니다.

$$
s_j = \left\| \frac{\partial r}{\partial x_j} \right\|_2,
\qquad r = [\Delta P_{\text{비슬랙}};\ \Delta Q_{PQ}]
$$

`--jac-alpha α` 로 세기를 조절합니다. **α=0 이면 곱수가 전부 정확히 1** 이라
기존 손실과 같습니다 — 한 변수 실험이 되도록 만든 대조군입니다. 곱수의
제곱평균을 1 로 맞춰 손실 크기가 변하지 않게 했습니다 (§7.2 의 함정 재발 방지).

**결과.** case30 · 30,000 표본 · 미지 N-1 · `--select phys` · 1,500 epoch.
세 조건이 이 값 하나만 다릅니다.

| α | P/부하 % | Vm MAE | ΔP [pu] | ΔQ [pu] | 고른 epoch |
|---|---|---|---|---|---|
| **0** (대조군) | 4.000 | 4.949e-04 | 0.1277 | 0.0677 | 960 |
| **0.5** | **3.960** | **4.936e-04** | **0.1264** | 0.0677 | 1,194 |
| **1.0** | 4.187 | 5.193e-04 | 0.1337 | 0.0725 | 741 |

> [!CAUTION] 가설이 확인되지 않았습니다
> α=0.5 는 **1.0% 좋아졌습니다.** 단일 실행에서 이 정도는 잡음과 구분되지
> 않습니다. 그리고 세기를 끝까지 올린 α=1.0 은 오히려 **4.7% 나빠집니다** —
> 효과가 있었다면 α 를 키울수록 좋아져야 합니다.
>
> **관찰이 틀린 것이 아니라 처방이 틀렸습니다.** "오차의 위치가 크기보다
> 중요하다" 는 세 실험이 일관되게 보여 준 사실이고 그건 그대로 남습니다.
> 다만 **야코비안 열 크기로 손실을 가중하는 것**은 그 문제를 풀지 못합니다.

왜 안 됐는지는 두 가지로 짐작합니다. 둘 다 확인은 안 했습니다.

1. **대각 근사의 한계.** $\|J\Delta x\|^2$ 를 $\sum_j \|J_{:,j}\|^2 \Delta x_j^2$ 로
   바꾼 것은 **열끼리 직교할 때만** 맞습니다. 실제 조류 야코비안의 열은 강하게
   상관돼 있어서, 교차항을 버리면 정작 중요한 구조가 사라질 수 있습니다.
2. **이미 절반은 들어 있었습니다.** 기존 가중치 $1/\sigma_j$ 와 민감도
   $s_j$ 의 상관을 재 보니 로그 공간에서 **+0.11 \~ +0.51** 이었습니다.
   뻣뻣한 모선은 전압이 덜 움직여서 $\sigma$ 가 작고, 그래서 $1/\sigma$ 가
   이미 크게 잡혀 있습니다. 곱하면 일부가 이중계산됩니다.

**남기는 이유.** `--jac-alpha` 는 코드에 남겨 둡니다. 기본값 0 이라 아무 영향이
없고, 유한차분 대조로 구현이 맞는 것은 확인했습니다(테스트 2개). 나중에 다른
가중 방식을 시험할 때 비교 대상이 됩니다.

## 7. 학습을 망가뜨렸던 함정 여덟

여덟 다 **조용히** 성능을 깎거나 자원을 놀리던 것들이라, 테스트로 고정해
두었습니다. §7.4와 §7.6은 각각 결과를 통째로 잘못 읽게 만들 뻔했고, §7.6은
실제로 **이 문서의 결론 여러 개를 틀리게 만들었습니다.** §7.7·§7.8은 M4 의 첫
그래프 신경망이 왜 나빴는지입니다 — 하나는 모델 형태, 하나는 실험 설계였습니다.

### 7.1 정규화 폭주 — 가장 위험했던 것

입력을 학습 분할의 평균·표준편차로 표준화하는데, **어떤 선로가 학습 분할에서
한 번도 고장 나지 않으면 그 열의 표준편차가 0**입니다. 하한 $10^{-6}$ 을 씌워
나누면, 그 선로가 고장 난 시험 표본에서 정규화 입력이 $10^{6}$ 으로 폭주합니다.

> [!CAUTION] 이건 드문 사고가 아닙니다
> **미지 N-1 분할은 정의상 시험용 고장이 학습에 한 번도 안 나오게 만듭니다**
> ([05 문서](05_dataset_generator.md) §9). 즉 P2의 핵심 일반화 실험이 통째로
> 망가집니다.
>
> 실측: case30 · 400 표본에서 41개 선로 중 **12개가 학습 분할에서 상수**였고,
> 그중 4개가 시험 분할에서 값이 변해 정규화 입력이 정확히 1e6까지 튀었습니다.

**해결**: 선로상태 열은 **정규화하지 않습니다.** 이미 0/1이라 스케일이 맞습니다.
물리량 열도 상수인 경우 나누지 않고 중심화만 합니다.

```python
# src/nnopf/train.py
def input_stats(X: np.ndarray, tr: np.ndarray, n_phys: int):
    """입력 정규화 통계. **선로상태 열은 정규화하지 않는다.**

    n_phys = 4 * nb  (Pd|Qd|p_ren|p_gen 까지가 물리량, 그 뒤가 선로상태)
    tr     = 학습 분할의 인덱스 — 검증/시험은 절대 보지 않는다
    """
    mean = X[tr].mean(0)
    std = X[tr].std(0)

    std = np.where(std > 1e-8, std, 1.0)   # 상수 열: 중심화만, 확대 금지
    mean[n_phys:] = 0.0                    # 선로상태: 손대지 않는다
    std[n_phys:] = 1.0

    return mean.astype(np.float32), std.astype(np.float32)
```

**세 줄이 고친 전부입니다.**

| 줄 | 막는 사고 |
|---|---|
| `np.where(std > 1e-8, std, 1.0)` | 상수 열을 $10^{-6}$ 같은 하한으로 나눠서 $10^{6}$ 으로 터뜨리는 것 |
| `mean[n_phys:] = 0.0` | 0/1 상태를 중심화해서 "고장 아님"이 음수가 되는 것 |
| `std[n_phys:] = 1.0` | 학습에서 한 번도 안 끊긴 선로의 std=0 을 나눗셈에 쓰는 것 |

`1e-6` 이 아니라 `1.0` 으로 대체하는 것이 핵심입니다. 하한을 씌우는 흔한 처방
(`std = max(std, eps)`)이 바로 이 버그를 만듭니다.

### 7.2 weight decay가 학습을 죽임

라벨 분산이 Vm 8.1e-05, Va 8.1e-04라 원단위 MSE 손실은 $10^{-4}$ 규모이고
기울기도 그 규모입니다. PyTorch `Adam(weight_decay=)` 는 L2를 **기울기에 더하는**
방식이라, `1e-5 × |w|` 가 과제 기울기와 맞먹어 버립니다. 그러면 Adam이 사실상
가중치 축소만 하고 학습이 멈춥니다.

| lr | weight decay | train MSE |
|---|---|---|
| 5e-4 | 0 | 9.3e-06 |
| 5e-4 | 1e-5 | **1.0e-04** ← 갇힘 |
| 2e-3 | 0 | 2.2e-06 |
| 2e-3 | 1e-5 | **1.0e-04** ← 갇힘 (lr과 무관) |

> [!NOTE] 진단이 한 번 틀렸던 기록
> 처음엔 학습률 탓으로 결론냈습니다. 스윕에서 lr과 weight decay를 **같이** 바꿔
> 놓고 lr 쪽으로 귀인한 것입니다. 2×2로 분리해 보니 weight decay 단독 원인이었고,
> lr은 부차적이었습니다(2e-3이 5e-4보다 4배 낫긴 합니다).
>
> 교훈은 단순합니다 — **한 번에 한 변수만 바꾼다.**

**해결**: 지도 손실을 **표준화 공간**에서 계산합니다. 손실이 $O(1)$ 이 되어 정규화가
의도대로 동작하고, 덤으로 Vm과 Va가 대등하게 반영됩니다(원단위로는 분산이 10배
차이라 Va가 손실을 지배했습니다). 최적화기도 분리형 감쇠 `AdamW` 로 바꿨습니다.

이 수정 뒤에는 weight decay를 0에서 1e-3까지 100배 키워도 결과가 거의 같습니다.

### 7.3 조기 종료가 너무 빡빡함

검증 표본이 900개뿐이라 검증 손실이 잡음을 탑니다. `patience=60` 이면 개선이
이어지는 중에도 끊깁니다 — case30에서 epoch 184에 끊겨 **Vm MAE가 1.8배** 나빴습니다.
최고 검증 시점 가중치를 되돌리므로 끝까지 돌려도 과적합 위험은 없어서,
`patience=200` 으로 늘렸습니다.

### 7.4 슬랙 기준위상을 0이라고 가정함 — case118을 통째로 오염시킨 버그

가장 오래 못 잡았고, 가장 비쌌던 버그입니다.

대체모델은 **아는 값은 예측하지 않고 그대로 채웁니다** — PQ 모선이 아닌 곳의
전압 크기는 발전기 설정값, 슬랙 모선의 위상은 기준값입니다
([01 문서](01_power_flow_and_opf.md) §7.2). 그런데 그 "기준값"을 코드에서
`torch.zeros(...)` 로 채우고 있었습니다. **슬랙 위상은 0이다**라고 가정한 것입니다.

case30에서는 실제로 0이라 아무 일도 없었습니다. 그런데 pandapower `case118`은
**슬랙(모선 68)의 기준위상이 30°** 입니다.

> [!CAUTION] 증상이 버그를 그대로 가리키고 있었는데 못 알아봤습니다
> 결과 JSON의 `va_max`(최대 위상 오차)가 선형 기준선과 MLP **양쪽 모두**
> `0.5235987901687622` 였습니다. 이건 $\pi/6$ = 30°의 float32 표현입니다.
>
> 서로 완전히 다른 두 모델이 15자리까지 똑같은 최대 오차를 낸다면, 그건
> 모델의 오차가 아니라 **모든 표본에서 같은 자리에 박혀 있는 상수 오차**입니다.

**왜 이게 물리 잔차를 통째로 망가뜨리나.** 슬랙 모선에는 애초에 $\Delta P$를
걸지 않습니다(마스킹). 그래서 "슬랙 위상이 틀려도 잔차와 무관하지 않나" 싶지만,
정반대입니다. 주입전력은 $S = V \odot \overline{(Y_{bus}V)}$ 이므로 **슬랙의
전압이 $Y_{bus}$를 타고 이웃 모선 전부의 $\Delta P$에 들어갑니다.** 30°짜리
위상 오차 하나가 계통 전체로 번집니다.

**수정 전후** (case118, 20,000 표본, 무작위 분할):

| 지표 | 선형 수정 전 | 선형 수정 후 | MLP 수정 전 | MLP 수정 후 |
|---|---|---|---|---|
| Va MAE [rad] | 7.253e-03 | **2.816e-03** | 5.361e-03 | **9.238e-04** |
| ΔP [pu] | 44.77 | **14.08** | 32.18 | **0.712** |
| ΔQ [pu] | 5.85 | **1.56** | 4.45 | **0.120** |
| P/부하 [%] | 97.93 | **30.80** | 70.39 | **1.56** |

MLP 쪽 개선폭이 훨씬 큰 것(45배)이 핵심입니다. 상수 오차 하나가 두 모델을
**똑같이** 망가뜨려서, 실제 성능 차이를 통째로 가리고 있었습니다.

> [!NOTE] 이 표의 "선형 수정 후" 30.80% 도 아직 틀린 값입니다
> 여기서 고친 것은 슬랙 기준위상 하나뿐입니다. 선형 기준선에는 **또 다른
> 버그**가 남아 있었고(§7.6), 그것까지 고치면 30.80% 가 **0.90%** 가 됩니다.
> 버그를 하나 잡았다고 그 숫자가 옳다는 보장은 없습니다.

> [!NOTE] 재학습은 하지 않았습니다 — 할 필요가 없어서입니다
> λ=0 학습의 손실은 비슬랙 모선의 전압만 봅니다. 슬랙을 어떻게 채우든
> **학습 궤적은 비트 단위로 같습니다.** 실제로 재학습을 걸어 보니 epoch 25까지
> 손실이 소수점까지 동일했습니다. 그래서 기존 체크포인트를 그대로 불러
> **평가만** 다시 했습니다 (30분 절약).
>
> 반대로 물리손실을 켠 학습(λ>0)은 슬랙 전압이 손실에 직접 들어가므로
> **반드시 다시 돌려야 합니다.**

Va MAE 차이는 손으로 검산해도 정확히 맞습니다. 슬랙 하나가 $\pi/6$ 만큼 틀렸으니
모선 118개 평균에 $(\pi/6)/118 = 4.437\times10^{-3}$ 이 그대로 얹혀 있었던 것입니다 —
$7.253\times10^{-3}$ 에서 그만큼 빼면 $2.816\times10^{-3}$, 수정 후 실측값과 같습니다.

**해결**: `IOLayout.va_ref` 를 두고 슬랙 자리에 `sys.Va0` 를 넣습니다. 뉴턴-랩슨
쪽은 원래부터 `flat_start()` 에서 이 값을 제대로 쓰고 있었습니다 — 대체모델만
빠뜨렸습니다.

> [!TIP] 일반화할 수 있는 교훈
> **"계통마다 다를 수 있는 값"을 상수로 박지 않는다.** 여기서는 슬랙 기준위상이
> 그랬습니다. 다음 후보들도 같은 위험이 있습니다 — 기준 용량(`baseMVA`),
> 변압기 탭·위상 이동, 모선 번호와 인덱스의 대응.
>
> 그리고 **한 계통에서만 검증하지 않는다.** case30만 봤다면 이 버그는 5단계까지
> 살아남았을 것입니다.

### 7.5 GPU를 달아 놓고 CPU로 돌림

RTX 5060을 도입하고 환경 점검까지 통과시킨 다음, case30 학습을 돌렸더니
34초가 나왔습니다. 클라우드 CPU(4코어)에서 116초였으니 3.4배입니다.

**GPU면 수십 배가 나와야 합니다.** 3.4배는 그냥 데스크톱 CPU가 컨테이너
CPU보다 빠른 정도입니다. 코드를 뒤져 보니 이유가 명확했습니다.

```
$ grep -rc "cuda" src/nnopf/*.py
src/nnopf/train.py:0
src/nnopf/models.py:0
src/nnopf/physics_torch.py:0
...
```

**`cuda` 라는 단어가 한 번도 안 나옵니다.** PyTorch는 아무 말 없이 CPU에서
돕니다. GPU가 없어서 실패하는 게 아니라, 있는데도 안 쓰는 것이라 **에러도
경고도 나지 않습니다.**

> [!CAUTION] 이건 속도만의 문제가 아닙니다
> §8의 속도 비교표가 논문의 주장 중 하나입니다. 만약 이 상태를 모르고
> "GPU에서 잰 값"이라고 적었다면 **측정 조건이 틀린 수치를 논문에 싣게
> 됩니다.** 환경이 준비됐다는 것과 코드가 그걸 쓴다는 것은 별개입니다.

**해결**: `prepare(device=...)` 로 입력·라벨·물리모듈·모델을 함께 옮깁니다.
데이터셋을 통째로 VRAM에 올리므로(case118 20,000표본 = 60 MB) 배치마다
전송하지 않습니다. 8 GB로 충분합니다.

> [!IMPORTANT] 배정밀도 잔차 측정만은 CPU에 남겼습니다
> 소비자용 지포스는 **배정밀도(float64) 처리율이 단정밀도의 1/64**입니다.
> 게임용이라 그 회로를 최소한만 넣기 때문입니다.
>
> 우리 잔차는 반드시 float64로 재야 합니다 — 전압 오차가 $`Y_{bus}`$를 거치며
> $`\max|Y|`$배로 증폭되기 때문입니다([05 문서](05_dataset_generator.md) §6.1).
> 그걸 GPU에서 재면 오히려 느려집니다.
>
> 그래서 **학습(float32)은 GPU, 최종 측정(float64)은 CPU** 로 나눴습니다.

그리고 `resolve_device("auto")` 는 `torch.cuda.is_available()` 만 믿지 않고
**실제로 곱셈을 한 번 시켜 봅니다.** 빌드가 그 GPU의 계산 능력을 지원하지
않으면 available은 `True` 인데 첫 커널에서 터지기 때문입니다 — RTX 50
시리즈(`sm_120`)에 cu126 이하 빌드를 물리면 정확히 그렇게 됩니다.

### 7.6 비교 대상이 망가져 있었음 — 결론을 뒤집은 버그

가장 값비싼 실수였습니다. **틀린 것은 우리 모델이 아니라 비교 상대였습니다.**

선형 기준선은 닫힌 해입니다 — 시드도 epoch도 학습률도 없습니다. 그래서
"재현은 당연하다"고 믿고 검증하지 않았습니다. 그런데 다른 컴퓨터에서
같은 데이터·같은 코드로 돌렸더니 P/부하가 **30.80%** 와 **22.99%** 로 갈렸습니다.

**원인은 설계행렬이었습니다.** 입력에는 정보가 0인 열이 많습니다.

| 블록 | 열 수 | 상수열 | 왜 |
|---|---|---|---|
| Pd | 118 | 19 | 부하가 없는 모선 |
| Qd | 118 | 28 | 무효부하가 없는 모선 |
| p_ren | 118 | 86 | 재생에너지가 없는 모선 |
| p_gen | 118 | 97 | 발전기가 없는 모선 |
| status | 186 | 9 | 끊으면 계통이 갈라져 상정사고에서 제외한 선로 |
| **합계** | **658** | **239** | |

658개 중 239개가 상수입니다. 그대로 최소제곱에 넣으면 **조건수**가
$`2.7\times10^{58}`$ 이 됩니다.

> [!NOTE] 조건수와 특이값 — 처음 보는 말이라면
> **최소제곱**은 "점들을 가장 잘 지나가는 직선(고차원에서는 평면)"을 찾는
> 것입니다 ([03 문서](03_neural_networks.md) §1.1의 선형회귀가 그것입니다). 우리 선형 기준선이
> 바로 이겁니다 — 입력 658개로 전압을 맞히는 가장 좋은 **직선**.
>
> **특이값(singular value)** 은 그 계산에서 나오는 숫자들로, **입력의 각 방향이
> 얼마나 뚜렷한가**를 나타냅니다. 큰 특이값 = 데이터가 그 방향으로 넓게
> 퍼져 있다(정보가 많다). 0에 가까운 특이값 = 그 방향으로는 데이터가 거의
> 안 움직인다(정보가 없다).
>
> 상수열은 특이값이 **정확히 0** 입니다. "부하가 없는 모선의 Pd" 는 모든
> 표본에서 같은 값이니 아무 정보가 없습니다.
>
> **조건수**는 `가장 큰 특이값 / 가장 작은 특이값` 입니다. 이게 크다는 건
> "어떤 방향은 뚜렷한데 어떤 방향은 거의 없다"는 뜻이고, 그러면 **정보가 없는
> 방향의 계수를 정할 수가 없습니다.** 0으로 나누는 것에 가까워지니까요.
>
> $`2.7\times10^{58}`$ 은 감이 안 잡히는 수준입니다 — float64 가 구분할 수
> 있는 한계가 $`10^{16}`$ 쯤입니다. 즉 **계산이 성립하지 않는 상태**입니다.

그래서 numpy는 너무 작은 특이값을 자동으로 버립니다(그 방향은 없는 셈 친다).
문제는 **어디서 자를 것인가**입니다. 그 기본 절단선($`6.2\times10^{-9}`$)이
**하필 답이 갈리는 경계 한가운데**에 놓입니다.

| 남은 성분 | 검증 지도손실 | 시험 P/부하 |
|---|---|---|
| 420 | 1.0128e-02 | **33.76%** |
| 419 | 1.0123e-02 | **0.90%** |

**성분 하나 차이로 37배입니다. 그러면서 검증 손실은 거의 같습니다.**
전압 정확도에는 거의 기여하지 않으면서 물리 잔차만 키우는 방향이 하나
있습니다. LAPACK 구현이 조금만 달라도 그 방향이 살아남거나 잘려나갑니다.

> [!CAUTION] 이 버그가 만든 잘못된 결론들
> 아래는 전부 **망가진 기준선과 비교한 결과**였습니다. 지금은 정정됐습니다.
>
> | 잘못 적었던 것 | 실제 |
> |---|---|
> | case118에서 신경망이 선형을 20배 이김 | 선형 0.90% vs MLP 1.56% — **선형이 낫다** |
> | 미지 N-1에서 선형이 완전히 무너짐 (95.91%) | **1.30%** — 무너지지 않는다 |
> | 선형은 전압 한계를 23.59% 위반 | **0.00%** — 위반하지 않는다 |
> | 스케일링 인자 헤드가 신경망만의 장점 | 선형도 이 데이터에서는 위반 없음 |
>
> 신경망을 쓸 근거로 내세웠던 것이 대부분 여기서 나왔습니다.

**해결**: 상수열을 빼고, 특이값 절단선을 **검증 분할로 고릅니다.** 신경망이
조기 종료에 쓰는 것과 같은 표준화 지도손실을 기준으로 삼아야 두 모델의 선택
기준이 같아집니다.

수정 후 기준선 — case30 무작위를 뺀 셋이 크게 좋아집니다. case30 무작위는
상수열이 적어 원래 절단선의 영향을 받지 않았습니다:

| 실험 | 수정 전 | 수정 후 |
|---|---|---|
| case30 무작위 | 1.33% | 1.33% |
| case30 미지 N-1 | 41.90% | **2.24%** |
| case118 무작위 | 30.80% | **0.90%** |
| case118 미지 N-1 | 95.91% | **1.30%** |

> [!TIP] 일반화할 수 있는 교훈 셋
> **① 비교 대상도 검증한다.** 우리 모델은 테스트로 감쌌지만 기준선은
> "닫힌 해니까 맞겠지" 하고 넘어갔습니다. 기준선이 틀리면 모든 비교가 틀립니다.
>
> **② 재현성은 시드 고정으로 끝나지 않는다.** 시드를 박아도 컴퓨터가 다르면
> 갈릴 수 있습니다. 배열 지문을 찍어 맞춰 보는 것(`s06_data_fingerprint.py`)이
> 유일하게 확실한 방법입니다.
>
> **③ 결과가 너무 좋으면 의심한다.** "신경망이 선형을 95배 이겼다"는 그
> 자체로 경보였어야 합니다. 조류계산은 운전점 근처에서 거의 선형이라
> (§2.1) 그런 격차가 나올 수 없습니다.

### 7.7 그래프 신경망의 층 수를 계통 지름보다 작게 잡음

M4 의 첫 GAT 가 MLP 보다 **11배 나빴습니다** (case30 무작위, P/부하 4.02% vs
0.35%). 학습 손실도 460배 나빴으니 일반화가 아니라 **학습 자체가 안 되고**
있었습니다.

가설이 둘 있었습니다.

- **(a) 소프트맥스가 크기 정보를 죽인다.** 어텐션은 이웃 가중치를 합이 1 이
  되게 정규화합니다. 그런데 조류방정식의 $Y_{bus}V$ 는 **평균이 아니라 합**입니다.
  이웃이 몇이든 합을 1로 만들면 크기 정보가 사라집니다.
- **(b) 시야가 좁다.** L 층이면 L-hop 까지만 봅니다. 그런데 전압은
  $Y_{bus}^{-1}$ 을 타고 **계통 전체**에 걸립니다.

둘을 가르려고 **절제 실험** 셋을 돌렸습니다 (case30, 30,000 표본, 1,500 epoch).

> [!NOTE] 절제 실험(ablation)이 무엇인가
> **한 번에 하나씩만 빼 보고 결과가 얼마나 나빠지는지 재는 것**입니다.
> 의학에서 장기를 하나 떼어 내 그 기능을 알아보던 데서 온 말입니다.
>
> "이 요소가 정말 기여했는가"를 아는 유일한 방법입니다. 전체를 다 켜고
> 좋은 결과가 나왔다고 해서 각 요소가 다 필요했다는 뜻은 아니니까요.
>
> **한 번에 하나만** 바꾸는 것이 핵심입니다. 둘을 같이 바꾸면 어느 쪽 때문인지
> 알 수 없습니다 — 이 문서에서 §7.2(학습률 + weight decay)와 §7.7.0(층 수 +
> 학습률)에서 두 번이나 그 실수를 했습니다.

| 실험 | 집계 | 층 | P/부하 % | 학습 종료 | 시간 |
|---|---|---|---|---|---|
| 기존 | softmax | 3 | 4.02 | 조기종료 ep454 (최고 254) | 409초 |
| 진단 A | **sum** | 3 | 3.71 | 조기종료 ep616 (최고 416) | 471초 |
| 진단 B | softmax | **8** | **1.10** | ep1500 완주 (최고 1,492) | 2,987초 |
| 진단 C | sum | 8 | 3.25 | 조기종료 ep264 (**최고 64**) | 487초 |

> [!CAUTION] 이 표의 층 수를 처음에 4로 적었습니다 — 실제로는 3입니다
> `--layers` 를 주지 않으면 `PRESET["case30"]["layers"]` 가 적용되는데, 그 값이
> **MLP 용 3층**입니다. `GATSpec` 의 기본값 4를 보고 4층이라고 적었지만
> 결과 JSON 의 `spec.layers` 는 3이었습니다.
>
> 결론은 바뀌지 않고 **오히려 강해집니다** — 3층이 보는 범위는 4층의 82.2%가
> 아니라 **56.4%** 입니다. 다만 "4층"이라고 적은 것은 틀렸습니다.

**(a) 는 기각됐습니다.** 합산으로 바꿔도 4.02% → 3.71%, 거의 움직이지 않습니다.
오히려 깊이와 합치면 **최고 epoch 이 1,500 중 64** 입니다 — 시작하자마자 나쁜
골짜기에 빠졌다는 뜻입니다. 정규화 없는 합산은 층마다 크기가 누적되니 깊어질수록
불안정합니다. 소프트맥스는 범인이 아니라 **깊이를 가능하게 해 주던 장치**였습니다.

**(b) 가 원인이었습니다.** 3층 → 8층에서 **3.7배** 개선입니다.

#### 지름을 재는 코드

층 수를 정하려고 쓴 스크립트 전체입니다. BFS 세 개면 끝납니다.

```python
# scripts/s07_graph_diameter.py
def _adjacency(f_bus, t_bus, drop=None):
    """무향 인접 리스트. drop 은 빼고 볼 선로 인덱스 (N-1 을 이걸로 만든다)."""
    n = int(max(f_bus.max(), t_bus.max())) + 1
    adj = [[] for _ in range(n)]
    for k, (a, b) in enumerate(zip(f_bus, t_bus)):
        if k == drop:                 # 이 선로만 없는 것처럼 그래프를 만든다
            continue
        adj[a].append(b)
        adj[b].append(a)
    return adj


def _bfs(adj, s):
    """모선 s 에서 각 모선까지의 hop 수. 도달 못 하면 -1."""
    d = [-1] * len(adj)
    d[s] = 0
    q = collections.deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if d[v] < 0:
                d[v] = d[u] + 1
                q.append(v)
    return d


def diameter(adj):
    """(지름, 반지름, 평균 최단거리). 그래프가 갈라져 있으면 지름은 inf."""
    n = len(adj)
    ecc, total, pairs = [], 0, 0
    for s in range(n):                # 모든 모선을 출발점으로 BFS
        d = _bfs(adj, s)
        if min(d) < 0:                # 도달 못 하는 모선이 있다 -> 계통이 갈라졌다
            return float("inf"), float("inf"), float("inf")
        ecc.append(max(d))            # 이 모선의 이심률 = 가장 먼 모선까지 hop
        total += sum(d)
        pairs += n
    return max(ecc), min(ecc), total / pairs   # 지름 = 이심률의 최댓값


def hop_coverage(adj, k):
    """k-hop 안에 들어오는 모선 수의 평균 (자기 자신 포함)."""
    return float(np.mean([sum(1 for x in _bfs(adj, s) if 0 <= x <= k)
                          for s in range(len(adj))]))
```

**N-1 최악 지름은 `drop` 하나로 구합니다.** 선로 개수만큼 반복해서 최댓값을 취합니다.

```python
worst = max(diameter(_adjacency(sys.f_bus, sys.t_bus, drop=k))[0]
            for k in range(len(sys.f_bus)))
```

끊긴 선로가 계통을 둘로 가르면 `diameter` 가 `inf` 를 돌려주므로, 그런 상정사고는
자연히 걸러집니다.


> [!IMPORTANT] 층 수는 취향이 아니라 계통이 정해 주는 값입니다
> 위 스크립트로 재 보면 숫자가 정확히 맞습니다.
>
> | 계통 | 정상 지름 | **N-1 최악 지름** | 3층 | 4층 | 8층 | 12층 |
> |---|---|---|---|---|---|---|
> | case30 | 6 | **8** | 56.4% | 82.2% | **100%** | 100% |
> | case118 | 14 | **18** | 18.1% | 29.5% | 77.8% | 98.3% |
>
> 3층 GAT 는 case30 모선의 **56% 만** 보고 있었습니다. 층 수가 지름보다 작으면
> 모델은 **물리적으로 볼 수 없는 것**을 예측하라는 요구를 받습니다. 데이터를
> 더 주거나 오래 돌려서 메울 수 있는 종류의 부족이 아닙니다.
>
> 8층이 case30 에서 잘 된 것도 우연이 아닙니다 — **N-1 최악 지름이 정확히 8**
> 입니다. 선로가 하나 끊기면 우회 경로가 길어져 지름이 6 에서 8 로 늘어납니다.
> 미지 N-1 을 다루려면 정상 지름이 아니라 **이쪽**을 맞춰야 합니다.

**해결**: 층 수를 계통의 N-1 최악 지름 이상으로 잡습니다. case30 은 8층,
case118 은 **18층** 이 필요합니다. `EdgeGAT` 은 층마다 잔차연결 + `LayerNorm`
을 두고 있어(`gnn.py`) 그 깊이가 학습 가능합니다 — 진단 B 가 1,500 epoch 을
발산 없이 완주한 것이 그 증거입니다.

#### GAT 한 층의 코드

세 절제 실험(`--agg`, `--gat-layers`, `--no-gate`)이 건드리는 자리가 전부
이 함수 안에 있습니다.

```python
# src/nnopf/gnn.py — EdgeGAT.forward
def forward(self, x, ei, ea, alive):
    """x (B,N,dim) · ei (2,E) 정적 간선 · ea (B,E,edge_dim) · alive (B,E) 0/1"""
    B, N, _ = x.shape
    s, d = ei[0], ei[1]          # s = 보내는 노드, d = 받는 노드
    H, D = self.h, self.d        # 헤드 수, 헤드당 차원

    # ① 간선마다 (보내는 쪽, 받는 쪽, 간선 자체) 세 정보를 섞어 점수를 만든다
    hs = self.src(x)[:, s].view(B, -1, H, D)
    hd = self.dst(x)[:, d].view(B, -1, H, D)
    he = self.edge(ea).view(B, -1, H, D)          # 간선 특징 = R, X, B, 탭 ...
    logit = (F.leaky_relu(hs + hd + he, 0.2) * self.att).sum(-1)   # (B, E, H)

    # ② 끊긴 선로를 막는다. 학습에 맡기지 않고 구조로 보장한다
    if self.gate:
        logit = logit + (1.0 - alive).unsqueeze(-1) * NEG   # NEG = -1e9

    # ③ 이웃 가중치를 정하는 방식 — 여기가 진단 A 가 바꾼 자리다
    if self.agg == "sum":
        # 소프트맥스를 쓰지 않는다. 조류방정식 YV 는 이웃 기여의 **합**이지
        # 평균이 아니다. 대신 게이트를 0~1 로만 눌러 두고 크기는 살린다.
        alpha = torch.sigmoid(logit) * alive.unsqueeze(-1)
    else:
        alpha = softmax_by_dst(logit, d, N)       # 받는 노드별 소프트맥스

    # ④ 메시지를 만들어 받는 노드로 모은다 (scatter_add = 이웃 합산)
    msg = (self.val(x)[:, s].view(B, -1, H, D)
           + self.val_e(ea).view(B, -1, H, D)) * alpha.unsqueeze(-1)
    agg = torch.zeros(B, N, H, D, device=x.device, dtype=msg.dtype).scatter_add(
        1, d.view(1, -1, 1, 1).expand(B, -1, H, D), msg
    )

    # ⑤ 잔차연결 + LayerNorm. 이 한 줄 덕분에 8층·18층이 학습된다
    return self.norm(x + self.out(agg.reshape(B, N, H * D)))
```

**②가 이 모델의 존재 이유입니다.** MLP 에게 선로 상태는 입력 벡터 끝에 붙은
0/1 비트일 뿐이지만(§4.1), 여기서는 **끊긴 선로가 메시지 경로 자체를 잃습니다.**
`NEG` 를 더하면 소프트맥스를 지난 가중치가 정확히 0 이 되고, `sum` 집계에서는
`* alive` 가 같은 일을 합니다. 못 본 고장이어도 구조가 자동으로 반영됩니다.

**⑤가 깊이를 가능하게 합니다.** `x +` 가 잔차연결이라 층이 늘어도 신호가
그대로 통과할 수 있고, `LayerNorm` 이 층마다 크기를 되돌립니다. 진단 C(`sum` +
8층)가 epoch 64 에서 멈춘 것은 `sum` 이 ③에서 정규화를 없애 이 균형을 깬
탓입니다 — 소프트맥스는 범인이 아니라 **깊이를 떠받치던 장치**였습니다.

세 절제 실험이 코드의 어디를 껐다 켰는지 정리하면 이렇습니다.

| 실험 | 바뀌는 곳 | 결과 |
|---|---|---|
| 진단 A `--agg sum` | ③ | 4.02% → 3.71% (거의 무변화 → 가설 기각) |
| 진단 B `--gat-layers 8` | 층 수 | 4.02% → **1.10%** (3.7배 → 원인 확정) |
| 진단 C 둘 다 | ③ + 층 수 | 3.25%, 최고 epoch 64 (발산에 가까움) |
| 게이팅 절제 `--no-gate` | ② | 4.90% → 7.82% (**1.6배 나빠짐** → §7.7.1) |

§7.7.1 이 ②의 절제 결과입니다.

> [!WARNING] 게이팅 절제는 §7.7.1 에서 돌렸습니다
> 이 표의 마지막 줄(`--no-gate`)은 나중에 채워진 값입니다. 상세한 해석은
> §7.7.1 에 있고, 그 절의 끝에 지금까지의 GAT 결과를 모은 요약이 있습니다.
>
> 비교할 때 §5.3 의 규칙을 지켜야 합니다 — 지금 case30 미지 N-1 기준선
> (선형 2.24% / MLP 6.75%)은 **6,000 표본**에서 잰 값이라, 30,000 표본 GAT 와
> 나란히 놓으면 안 됩니다. 같은 표본 수의 기준선부터 다시 만들어야 합니다.

### 7.7.0 지름을 **넘겨서** 쌓으면? — 좋아집니다. 단, 학습률을 같이 낮춰야 합니다

> 남은 격차는 전부 물리 잔차 쪽입니다 (ΔP 0.0832 vs 0.0653).
>
> 학습 이력도 깨끗합니다. val_phys 가 33.3 → 2.68 로 **단조 하강**하고,
> 최고 시점이 1,470 / 1,500 입니다 — **아직 수렴하지 않았습니다.**

> [!IMPORTANT] 대조군이 답을 줬습니다 — 원인은 **학습률**이었습니다
> 8층은 lr 2e-3, 12층은 lr 5e-4 로 돌렸으니 **변수가 둘 바뀐** 상태였습니다.
> §7.2 에서 학습률과 weight decay 를 같이 바꿔 놓고 잘못 귀인했던 것과 같은
> 구조라, 8층을 lr 5e-4 로만 다시 돌렸습니다 (작업 33).
>
> | 무엇을 바꿨나 | 비교 | 배수 |
> |---|---|---|
> | **학습률** (8층 고정, 2e-3 → 5e-4) | 4.90 → **2.69** | **1.82배** |
> | 깊이 (lr 5e-4 고정, 8층 → 12층) | 2.69 → 2.61 | **1.03배** |
>
> **거의 전부 학습률이었습니다.** 8층과 12층은 같은 학습률에서 3% 차이 —
> 실험 잡음 수준입니다.
>
> 실무적으로는 **8층을 쓰면 됩니다.** 54분 대 71분이고 성능이 같습니다.
> §7.7 의 "층 수 = N-1 최악 지름(=8)" 규칙은 그대로 유효하고, **그 위로 더
> 쌓는 것은 이득이 없습니다.**

> [!NOTE] 두 번 연속으로 "깊이 때문" 이라고 착각할 뻔했습니다
> §7.7 에서는 진짜로 깊이가 원인이었습니다 (3층 → 8층, 3.7배). 그 성공이
> 강렬해서 §7.7.0 에서도 "더 쌓으면 더 좋아진다" 로 읽을 뻔했습니다.
> **같은 종류의 설명이 두 번 통할 거라고 가정하면 안 됩니다.**
>
> 대조군 하나(54분)가 그걸 갈랐습니다.

**어디서 온 문제인가.** 기본 학습률 2e-3 은 §7.2 에서 **MLP 에 맞춰** 올린
값입니다. 거기서는 5e-4 가 너무 작아 학습이 MSE 1e-4 에서 멈췄습니다. 그런데
같은 값이 12층 GAT 에서는 **너무 커서** 발산합니다. 잔차연결 + `LayerNorm` 이
8층까지는 2e-3 을 받쳐 주지만 12층에서는 못 버팁니다.

**한 하이퍼파라미터가 모델 구조에 따라 정반대로 작동합니다.** 그래서 구조를
바꿀 때 학습률을 함께 재조정하지 않으면, 구조의 효과를 최적화 실패로 착각하게
됩니다 — 실제로 이 절에서 그럴 뻔했습니다.

### 7.7.1 게이팅 절제 — 이 모델의 존재 이유가 확인됐습니다

`gnn.py` 는 끊긴 선로를 막는 것(②)을 "이 모델의 존재 이유"라고 적어 두었지만,
그동안 **확인된 적이 없었습니다.** case30 · 30,000 표본 · 미지 N-1 ·
`--select phys` · 8층 · 1,500 epoch 에서 `gate` 하나만 껐습니다.

| 지표 | 게이팅 켬 | 게이팅 끔 | 배수 |
|---|---|---|---|
| **P/부하 %** | **4.90** | 7.82 | **1.60** |
| Vm MAE | **4.479e-04** | 5.354e-04 | 1.20 |
| Va MAE | 2.205e-03 | **1.879e-03** | 0.85 ← 끔이 낫다 |
| ΔP [pu] | **0.1564** | 0.2496 | 1.60 |
| ΔQ [pu] | **0.0723** | 0.1290 | 1.78 |
| **ΔP 최대** | **0.324** | 1.241 | **3.83** |
| V위반 % | **0.064** | 0.127 | 2.00 |
| 마지막 학습손실 | 3.960e-05 | **3.244e-05** | 0.82 ← 끔이 낫다 |

세 가지가 나옵니다.

**① 값어치가 평균이 아니라 꼬리에 있습니다.** 평균 잔차는 1.6배 차이인데
**최대 잔차는 3.8배**입니다. 게이팅이 없으면 끊긴 선로로 메시지가 계속 흘러
특정 표본이 크게 무너집니다. 구조적 보장이 지키는 것은 평균 성능이 아니라
**최악의 경우**입니다 — 그리고 5단계에서 대체모델이 OPF 안에 들어가면
최악의 경우가 곧 실행불가능한 해가 됩니다.

**② 게이팅은 물리에서 유도한 정규화로 작동합니다.** 게이팅을 끈 쪽이 학습
손실은 **더 낮은데**(3.244e-05 vs 3.960e-05) 일반화는 1.6배 못 합니다.
"끊긴 선로는 볼 수 없다"는 제약이 자유도를 줄여 외삽을 돕는다는 뜻입니다.
손실 항을 더한 것이 아니라 **자료구조로 넣은 정규화**입니다.

<br>

이 점이 P2 와 갈리는 지점입니다. P2 는 고장 선로를 `status=0` 이라는 **특징**
으로만 표시합니다. 그러면 "이 값이 0 이면 무시하라"는 것까지 학습으로 배워야
하고, 학습에서 본 고장에 대해서만 배웁니다. 우리는 로짓을 직접 눌러
**구조로 보장**했고, 그 차이가 미지 N-1 에서 1.6배로 나타났습니다.

**③ 위상은 게이팅을 끈 쪽이 더 정확한데(0.85배) 물리 잔차는 1.6배 나쁩니다.**
이 패턴이 이번이 **세 번째**입니다 — §2.2(MLP), §7.8.1(GAT), 그리고 여기.
오차의 *크기*와 그 오차가 전력으로 증폭되는 *정도*가 정렬돼 있지 않다는 신호가
서로 다른 세 실험에서 같은 방향을 가리킵니다.

> [!IMPORTANT] GAT 를 살린 세 가지 결정 — 구조 둘, 학습 하나
> | 결정 | 근거가 된 절제 | 기여 | 어느 분할 |
> |---|---|---|---|
> | 층 수 = N-1 최악 지름 (§7.7) | 3층 → 8층 | **3.7배** | 무작위 |
> | 끊긴 선로 게이팅 (§7.7.1) | 켬 vs 끔 | **1.6배** | 미지 N-1 |
> | 구조에 맞춘 학습률 (§7.7.0) | 12층에서 2e-3 → 5e-4 | **2.5배** | 미지 N-1 |
>
> 앞의 둘은 **구조**의 승리이고 셋째는 **구조가 아니라 학습**의 문제였습니다.
> 셋을 다 적용한 12층 GAT 가 미지 N-1 에서 **2.61%** 이고, 선형(2.05%)과의
> 격차가 처음 만났을 때의 2.4배에서 **1.27배**까지 좁혀졌습니다.
>
> 위 ③ 이 가리킨 "손실함수가 범인" 이라는 처방은 **실제로 시험해 봤고 틀렸습니다**
> — 손실을 야코비안 민감도로 가중해도 4.00% → 3.96% 로 사실상 변화가 없었습니다
> (§6.2). 남은 격차를 메운 것은 손실이 아니라 **깊이 + 맞는 학습률**이었습니다.
> ③ 이 말해 주는 것은 "손실을 고치면 된다" 가 아니라 **"MAE 로 모델을 고르지
> 말라"** 였고, 그 교훈은 §7.8 의 `--select phys` 로 이어집니다.

> [!WARNING] 여기까지가 "구조를 고치는" 이야기입니다 — 아직 이기지는 못했습니다
> 정리하면 이렇습니다. **무작위 분할**에서 8층 GAT 는 1.10% 로 3층(4.02%)보다
> 3.7배 낫지만 여전히 MLP(0.35%)에 3.1배, 선형(1.00%)에도 집니다.
> **미지 N-1** 에서는 12층 GAT 가 2.61% 로 MLP(4.80%)를 1.8배 이기지만
> 선형(2.05%)에는 1.27배 집니다.
>
> 즉 **GAT 는 자기가 만들어진 목적(토폴로지 외삽)에서만 MLP 를 이깁니다.**
> 무작위 분할에서는 MLP 가 훨씬 낫습니다. 이건 실패가 아니라 §4.1 이 예고한
> 그대로입니다 — 두 모델은 서로 다른 시험을 위한 것입니다.
>
> 남은 두 가지 미확인 사항을 §7.7.0 이 이미 적어 뒀습니다. ① 8층을 lr 5e-4 로
> 다시 돌리기 전까지는 12층의 이득이 **깊이 때문인지 학습률 때문인지** 가를 수
> 없습니다(작업 33). ② 12층은 1,470 / 1,500 에서 최고를 찍었습니다 —
> **아직 수렴하지 않았습니다**(작업 34).
>
> 비교할 때 §5.3 의 규칙도 계속 유효합니다 — 표본 수가 다른 값끼리 나란히
> 놓지 마세요. 위의 미지 N-1 숫자는 전부 **30,000 표본** 기준입니다.

### 7.8 미지 N-1 에서 검증 손실로 모델을 고름 — 거의 학습 안 된 모델이 뽑혔다

§7.7 대로 8층으로 올린 GAT 를 미지 N-1 에서 재 봤더니 **11.52%** 가 나왔습니다.
MLP(4.80%)보다 2.4배, 선형(2.05%)보다 5.6배 나쁩니다. 토폴로지 외삽을 하라고
붙인 모델이 정작 그 시험에서 제일 나빴습니다.

그런데 결과 JSON 의 `best_epoch` 가 **34** 였습니다. 1,500 중 34 입니다.

| 학습 | 검증 손실 바닥 | 최고 epoch | 그때 학습 손실 | 마지막 학습 손실 |
|---|---|---|---|---|
| MLP · 미지 N-1 | 6.04e-01 | 132 / 333 | 1.50e-03 | 7.5e-05 |
| **GAT 8층 · 미지 N-1** | 5.77e-01 | **34 / 235** | 1.90e-01 | **8.5e-04** |
| GAT 8층 · 무작위 | 1.44e-03 | 1,492 / 1,500 | 4.34e-04 | 4.3e-04 |

`train()` 은 **최고 검증 시점의 가중치로 되돌립니다.** 그러니 우리가 평가한
GAT 는 epoch 34 짜리, 거의 학습되지 않은 모델입니다. epoch 234 까지 가면 학습
손실이 **222배** 좋아지는데(1.90e-01 → 8.5e-04) 검증은 **7.6%** 나빠질 뿐입니다
— 그 7.6% 를 아끼려고 222배를 버린 셈입니다.

> [!CAUTION] 검증 분할에도 못 본 고장이 들어 있습니다
> `split_unseen_n1` 은 고장 *유형* 을 train/val/test 로 나눕니다
> ([05 문서](05_dataset_generator.md) §9). 즉 **검증 분할도 외삽 시험**입니다.
> 그런데 어느 모델도 외삽을 못 하니, 검증 손실은 몇 epoch 만에 바닥에 닿고
> 그 뒤로 움직이지 않습니다. 두 모델의 바닥이 6.04e-01 과 5.77e-01 로 거의
> 같은 것이 그 증거입니다 — **모델의 차이가 아니라 분할의 성질**입니다.
>
> 그 평평한 바닥 위에서 "최고 검증 시점" 은 사실상 **잡음이 고릅니다.** MLP 는
> 132 를, GAT 는 34 를 뽑았습니다.
>
> 무작위 분할에서는 멀쩡합니다. 같은 GAT 가 epoch 1,492 까지 갱신을 이어갔고
> 검증/학습 비도 3.3 배에서 안정적입니다.

§4.1 에서 **"검증 손실은 성능을 읽는 지표로 쓰면 안 된다"** 고 적었습니다.
이번에 하나 더 알았습니다 — 미지 N-1 에서는 **학습을 멈출 시점을 정하는
지표로도** 못 씁니다.

**해결**: 되돌릴 가중치를 고르는 기준을 고를 수 있게 했습니다.

```bash
--select loss   # 표준화 지도손실 (기본, 무작위 분할용)
--select phys   # 검증 분할의 P/부하 % — 우리가 실제로 보고하는 값
```

#### 코드 — 학습 루프에서 바뀐 것은 세 줄뿐입니다

```python
# src/nnopf/train.py — train() 안, 매 epoch 끝에서
val_load = b.p_spec[va].abs().sum(-1).mean().clamp(min=1e-9)   # 루프 전에 한 번만

# ... epoch 루프 안 ...

    # 검증은 항상 순수 지도손실로 — λ 가 바뀌어도 비교 가능해야 한다
    model.eval()
    with torch.no_grad():
        Vm, Va = model(b.X[va])
        vloss = supervised_loss(model, Vm, Va, b.Vm[va], b.Va[va]).item()

        # select="phys" 면 고르는 기준만 바꾼다. 기록에는 둘 다 남긴다.
        vphys = float("nan")
        if cfg.select == "phys":
            rp, _ = b.physics.residual(
                Vm, Va, b.p_spec[va], b.q_spec[va], b.outage[va]
            )
            vphys = (rp.abs().sum(-1).mean() / val_load).item() * 100.0

    crit = vphys if cfg.select == "phys" else vloss   # <- 여기가 규칙이다
    sched.step(crit)                                  # LR 스케줄러도 같은 기준으로
    hist.append({"epoch": ep, "train": tot / n_seen,
                 "val": vloss, "val_phys": vphys,     # 기록에는 둘 다
                 "lam": lam, "lr": opt.param_groups[0]["lr"]})

    if crit < best * (1 - 1e-5):        # 되돌릴 가중치를 고르는 것도 같은 기준
        best, best_epoch = crit, ep
        best_state = {k: v.detach().clone() for k, v in model.state_dict().items()}
```

**`crit` 한 줄이 GAT 를 11.52% 에서 4.90% 로 바꿨습니다.** 모델은 그대로입니다 —
`best_state` 를 언제 저장할지만 달라졌고, 그 결과 epoch 34 대신 1,219 짜리
가중치가 평가됩니다.

`va` 는 검증 분할의 인덱스이므로 시험 분할은 이 계산에 들어오지 않습니다.
`sched.step(crit)` 까지 같은 기준으로 바꾼 것도 의도적입니다 — 학습률을 깎는
판단과 가중치를 되돌리는 판단이 서로 다른 지표를 보면 §7.8 의 악순환이
그대로 남습니다.

`phys` 는 검증 분할에서만 재므로 시험 분할이 새어 들어가지 않습니다. 학습
중에는 float32 로(GPU 위에서) 재고, 최종 보고 수치는 §7.5 그대로 float64 · CPU
입니다. 기록에는 `val` 과 `val_phys` 를 **둘 다** 남겨서 나중에 어느 쪽으로
골랐는지 되짚을 수 있게 했습니다.

> [!IMPORTANT] §7.6 이 "비교 대상이 망가져 있었다" 였다면, 이번은 "비교 규칙"입니다
> 둘 다 모델이 아니라 **실험 설계** 쪽 문제였습니다. 그래서 §5.3 의 규칙에
> 한 줄을 더합니다 — 비교는 같은 표본 수·같은 분할·같은 평가 코드,
> 그리고 **같은 선택 규칙**으로만 성립합니다.

### 7.8.1 다시 잰 결과 — 규칙만 고쳤는데 GAT 가 2.4배 좋아졌습니다

>
> 다만 방향이 하나 보입니다. **GAT 는 전압이 가장 정확한데(4.479e-04) 물리
> 잔차는 가장 나쁩니다.** §2.2 에서 야코비안으로 분해했던 그 패턴입니다 —
> 오차의 *크기*보다 *위치*가 중요한데, 균등 가중 MSE 는 그 오차가 전력으로
> 얼마나 증폭되는지를 모릅니다.
>
> 즉 다음 수는 모델을 더 키우는 것이 아니라 **손실을 야코비안 민감도로
> 가중하는 것**입니다. §2.2 가 가리키던 방향이 여기서 다시 나왔습니다.
>
> (이 처방은 §6.2 에서 실제로 시험했고 — **효과가 없었습니다.**
> 격차를 메운 것은 §7.7.0 의 깊이 + 학습률이었습니다.
> 그리고 case118 미지 N-1 도 §7.8.2 에서 `--select phys` 로 다시 쟀습니다.)

> [!WARNING] §4·§4.1 의 case118 수치는 옛 규칙 값입니다 — 대체본이 §7.8.2 에 있습니다
> §4·§4.1 의 case118 수치(선형 1.30% / MLP 5.16%, 분해 0.84%·2.62% vs
> 1.26%·16.38%)는 20,000 표본 · `--select loss` 아래에서 나온 값입니다.
> 그 뒤 60,000 표본 · `--select phys` 로 다시 재서 **선형 1.01% / MLP 4.48%**
> 를 얻었습니다 (§7.8.2). case30 결과와 나란히 놓을 때는 **그쪽 수치**를 쓰세요.

## 8. 추론 속도

**단건과 배치를 반드시 나눠 잽니다.** 그래프가 작으면 단건에서 가속 효과가 크게
줄어든다는 P2의 관찰([04 문서](04_paper_review.md) §2.8) 때문입니다.

| 계통 | 뉴턴-랩슨 | MLP 단건 | MLP 배치 64 |
|---|---|---|---|
| case30 | 9.04 ms | 0.195 ms (**46배**) | 0.0104 ms (**871배**) |
| case118 | 12.80 ms | 0.236 ms (**54배**) | 0.0135 ms (**946배**) |

> [!NOTE] 이 배속을 논문 수치와 나란히 놓을 때 주의할 점
> 우리 뉴턴-랩슨 시간(9.0 / 12.8 ms)이 P2의 10.8 / 12.2 ms와 같은 자릿수라
> **분모는 비교 가능합니다.**
>
> 하지만 분자가 다릅니다. P2는 GAT(16.9배 / 8.7배 단건)이고 우리는 훨씬 가벼운
> MLP입니다. 게다가 P2의 배치 수치는 GPU이고 우리는 **전부 CPU**입니다.
> "우리가 P2보다 빠르다"는 주장은 성립하지 않습니다 — 모델이 다르니까요.
> 비교표에는 반드시 **모델 종류와 장치를 같이** 적어야 합니다.

### 8.1 학습 속도 — GPU가 항상 빠르지는 않습니다

RTX 5060을 붙이고 case30을 돌렸더니 **CPU보다 느렸습니다** (40.0초 vs 31.6초).
배치를 바꿔 가며 다시 쟀습니다 (epoch 당 밀리초, 낮을수록 좋음).

독립 실행 2회입니다. 개별 숫자는 흔들리지만 결론은 같습니다.

| 배치 | case30 CPU | case30 GPU | case118 CPU | case118 GPU |
|---|---|---|---|---|
| 64 | **84.8 / 95.3** | 100.6 / 133.3 | 515.7 / 540.7 | **395.9 / 470.2** |
| 256 | 38.7 / 42.1 | **27.2 / 32.4** | 271.7 / 278.8 | **147.6 / 139.1** |
| 1,024 | 28.1 / 30.7 | **7.7 / 9.3** | 206.7 / 223.8 | **29.3 / 31.6** |
| 4,096 | 25.7 / 27.7 | **3.6 / 4.4** | 214.3 / 250.5 | **10.6 / 9.7** |

case30 배치 64에서만 CPU가 이기고, 나머지는 전부 GPU입니다. case118 배치
4,096에서는 **20~26배** 차이가 납니다.

> [!WARNING] 이 숫자를 그대로 논문에 쓰면 안 됩니다
> 재실행하면 항목에 따라 **최대 33%** 까지 달라집니다 (case30·배치 64 GPU:
> 100.6 → 133.3 ms). 백그라운드 작업, 클럭 변동, 캐시 상태가 섞여 들어갑니다.
>
> 반면 **결론은 두 번 다 같습니다** — 갱신당 시간의 변동폭이 1.2배 이내,
> 역전점이 case30 배치 64~256 사이. 결론은 튼튼하고 개별 숫자만 거칩니다.
>
> 논문용 수치가 필요해지면 반복 횟수를 늘리고 중앙값과 사분위를 보고해야
> 합니다. 지금은 "어느 쪽이 언제 빠른가"를 판단하는 용도로 충분합니다.

> [!IMPORTANT] 진짜 정보는 "갱신 한 번당 시간"에 있습니다
> epoch당 시간에는 두 가지가 섞여 있습니다 — 한 번이 얼마나 걸리는지, 그리고
> 몇 번 하는지. 배치를 키우면 후자가 줄어드니 당연히 빨라 보입니다.
> 갱신 횟수로 나눠서 봐야 합니다.
>
> | 배치 | 갱신/epoch | case30 GPU | case30 CPU | case118 GPU | case118 CPU |
> |---|---|---|---|---|---|
> | 64 | 66 / 219 | 2.02 ms | 1.44 ms | 2.15 ms | 2.47 ms |
> | 256 | 17 / 55 | 1.91 ms | 2.48 ms | 2.53 ms | 5.07 ms |
> | 1,024 | 5 / 14 | 1.86 ms | 6.13 ms | 2.26 ms | 15.99 ms |
> | 4,096 | 2 / 4 | 2.21 ms | 13.83 ms | 2.41 ms | 62.62 ms |
>
> **GPU는 배치를 64배로 키워도 갱신 한 번 시간이 거의 그대로입니다** —
> 변동폭이 case30 1.19배, case118 1.18배 안입니다. CPU는 정직하게 배치에
> 비례해 늘어납니다 (9.6배 / 25.4배).
>
> 이 비교는 재실행에도 안정적입니다. 절대 시간은 흔들려도 **두 장치의
> 기울기 차이**는 그대로이기 때문입니다.

이게 뜻하는 바는 하나입니다 — **5060은 배치 4,096에서도 놀고 있습니다.**
시간을 쓰는 곳이 계산이 아니라 커널 호출 준비이기 때문입니다.

> [!TIP] M4에 직접 이어지는 결론입니다
> 지금 모델(hidden 256)이 GPU에게 너무 작습니다. 즉 **모델을 키우는 비용이
> 거의 0**입니다. M4에서 붙일 그래프 어텐션 신경망은 MLP보다 무거운데,
> 그 여유가 이미 확보돼 있다는 뜻입니다.
>
> 반대로 지금 규모에서 "GPU를 써서 몇 배 빨라졌다"를 자랑하면 안 됩니다.
> 배치 64에서는 오히려 손해입니다.

> [!CAUTION] 배치를 키우는 것이 공짜는 아닙니다
> 같은 epoch 수라도 **가중치 갱신 횟수가 배치에 반비례해 줄어듭니다.**
> case118 배치 4,096이면 epoch당 갱신이 4번뿐입니다. 시간은 20배 빨라지지만
> 학습이 그만큼 덜 됩니다.
>
> 속도표만 보고 배치를 올리면 안 되고, **정확도를 따로 확인**해야 합니다.
> 보통 배치를 키우면 학습률도 같이 올려야 합니다.

측정: `python scripts/s05_device_benchmark.py --case case118`

### 8.2 case118 GAT 18층은 3일짜리입니다 — 계획을 바꾼 측정

§7.7 이 case118 에 필요한 층 수를 **18** 로 정해 줬습니다. 그 설정을 실제로
돌리기 전에 30 epoch 만 재 봤습니다 (`--no-save`).

```bash
scripts/s03_train_surrogate.py --case case118 --model gat -n 60000 \
    --epochs 30 --layers 18 --no-save
```

| | case30 GAT 8층 | **case118 GAT 18층** |
|---|---|---|
| 학습 표본 | 21,000 | 42,000 |
| 방향 간선 (자기 루프 포함) | 112 | 490 |
| 측정 | 2,989초 / 1,500 epoch | **5,663.8초 / 30 epoch** |
| **epoch 당** | 1.99초 | **188.8초** |
| 1,500 epoch 환산 | 50분 | **78.7시간 (3.3일)** |

> [!CAUTION] 예상보다 4~5배 느렸습니다 — 표본·간선·층만 곱하면 안 됩니다
> 처음에는 표본 2배 × 간선 4.4배 × 층 2.25배 = **20배**, epoch 당 40초로
> 봤습니다. 실제는 **95배**였습니다.
>
> 원인은 VRAM 으로 보입니다. 역전파용으로 붙들고 있어야 하는 간선 텐서
> `(B, E, H, D)` 가 한 개에 **61.3 MB** 이고(case30 은 14.0 MB), 18층이면
> 활성값만 **5.3~7.4 GB** 입니다. 여기에 층당 93 MB 짜리 scatter 인덱스,
> 데이터셋, 옵티마이저 상태가 얹힙니다. RTX 5060 은 **8 GB** 입니다.
> 할당기가 한계선에서 캐시를 비웠다 다시 잡기를 반복하면 이 정도 감속이 납니다.
>
> **연산량으로는 설명이 안 됩니다.** 대략 재 보면 epoch 당 39 TFLOP 인데
> 5060 의 fp32 최대가 19 TFLOPS 이므로, 189초는 **최대 성능의 3 %** 입니다.

**§8.1 의 결론이 여기서는 뒤집힙니다.** 거기서 "GPU 는 배치를 키워도 갱신
한 번 시간이 거의 같으니 배치를 키우면 이득"이라고 적었습니다. 그건 hidden 256
MLP 처럼 **GPU 에게 너무 작은 모델**일 때의 이야기입니다. case118 GAT 18층은
반대로 메모리에 붙어 있으므로, 배치를 1,024 로 올리면 메모리가 4배 필요해
**아예 올라가지 않습니다.**

<br>

**그래서 이 실험을 보류했습니다.** 당시 판단은 "손실을 야코비안 민감도로
가중하는 것을 먼저 해 보고, 되면 그때 case118 로 간다" 였습니다.

> [!CAUTION] 그 판단의 근거는 그 뒤에 무너졌습니다
> 야코비안 가중은 §6.2 에서 실제로 시험했고 **효과가 없었습니다** (4.00% →
> 3.96%). 반대로 §7.7.0 에서 **학습률만 낮췄더니 12층이 2.61%** 로 갔습니다.
>
> 즉 "case118 GAT 를 돌릴 근거가 약하다" 던 전제가 뒤집혔습니다. GAT 는
> 미지 N-1 에서 MLP 를 1.8배 이기는 유일한 모델이고, case118 미지 N-1 은
> 네 칸 중 가장 크게 지는 칸(선형 1.01% vs MLP 4.48%)입니다.
> **거기에 GAT 를 못 붙여 본 것이 지금 M4 의 가장 큰 빈칸입니다.**

> [!NOTE] 20분을 써서 3일을 아꼈습니다
> 30 epoch 측정에 20분이 들었습니다. 이걸 안 했으면 3일을 태우고 나서 같은
> 사실을 알았을 것입니다. **긴 학습을 걸기 전에 몇 epoch 만 재 보는 것**이
> 이 규모에서는 필수입니다.

### 8.3 검증을 한 방에 넣고 있었습니다 — 그리고 그걸 고쳤습니다

§8.2 는 감속의 원인을 "활성값을 8 GB 카드에 밀어 넣어서" 로 봤습니다.
코드를 다시 읽어 보니 **학습보다 검증이 훨씬 컸습니다.**

학습 루프는 매 epoch 끝에 검증 분할로 손실을 잽니다. 그런데 그걸 **한 번에
전부** 넣고 있었습니다.

```python
# 예전 — train() 안
with torch.no_grad():
    Vm, Va = model(b.X[va])        # va = 검증 분할 전체
```

MLP 에서는 아무 문제가 없습니다. 출력이 (B, 53) 이라 9,000 표본이어도 2 MB
입니다. GAT 는 층 안에서 **간선 텐서** `(B, E, H, D)` 를 만듭니다 — case118 은
E = 490(자기 루프 포함), H = 4, D = 32(hidden 128 / 헤드 4)입니다.

**얼마나 큰지 실제로 쟀습니다.** case118 GAT 18층으로 `no_grad` 순전파를 돌리며
배치를 키워 RSS 증가분을 봤습니다.

| 배치 | 64 | 128 | 256 | 512 |
|---|---|---|---|---|
| 표본당 | 2.2 MB | 2.1 MB | 2.2 MB | 2.1 MB |

배치에 **정확히 비례**합니다. 표본당 2.1 MB 이므로:

| B | 순전파 한 번 |
|---|---|
| 256 (학습 배치) | **0.54 GB** |
| **9,000 (검증 분할 전체)** | **18.9 GB** |

> [!CAUTION] 여기서 앞뒤가 안 맞는 것이 하나 있습니다
> 위 실측대로면 검증 한 번에 18.9 GB 가 필요하고, RTX 5060 은 8 GB 입니다.
> 그런데 §8.2 의 30 epoch 측정은 **끝까지 돌았습니다.** 셋 중 하나입니다.
>
> - 그 실행이 실제로는 더 작은 데이터셋(캐시된 20,000 표본)을 집어서
>   검증 분할이 3,000 이었다 → 6.3 GB, 8 GB 에 겨우 들어감
> - RSS 측정이 CUDA 할당기의 실제 최고치보다 크게 나왔다
> - 어딘가에서 조용히 되돌아갔다
>
> **아직 못 가렸습니다.** 확실한 것은 검증이 학습 배치의 **35배**라는 것과,
> 그게 8 GB 에 들어갈 이유가 없다는 것뿐입니다. 작업 35 번이 가려 줍니다.

원인이 무엇이든 **검증을 한 방에 넣을 이유가 없습니다.** 학습 배치가 들어가는
크기면 검증도 들어갑니다.

> [!NOTE] "반정밀도(bf16)" 가 무엇인가
> 컴퓨터가 소수를 저장하는 방식에는 자릿수가 다른 여러 규격이 있습니다.
> 자릿수를 줄이면 같은 메모리에 두 배를 담을 수 있고 계산도 빨라집니다.
>
> | 이름 | 한 개당 | 유효숫자 | 표현 범위 |
> |---|---|---|---|
> | float64 (배정밀도) | 8 바이트 | 약 16자리 | 매우 넓음 |
> | float32 (단정밀도) | 4 바이트 | 약 7자리 | 넓음 |
> | **bf16** (반정밀도) | **2 바이트** | 약 **3자리** | float32 와 **같음** |
> | fp16 (반정밀도) | 2 바이트 | 약 3자리 | **좁음** |
>
> bf16 과 fp16 은 크기가 같은데 **범위**가 다릅니다. bf16 은 자릿수만 줄이고
> 범위는 float32 그대로라, 아주 작은 값이 0으로 사라지지 않습니다. fp16 은
> 범위까지 좁아서 작은 기울기가 조용히 0이 됩니다 — 그래서 fp16 을 쓰려면
> 손실을 인위적으로 키워 주는 장치(`GradScaler`)가 필요합니다.
>
> 우리는 **bf16 만** 씁니다. 아래 [!WARNING] 에 이유를 적었습니다.

> [!IMPORTANT] 세 가지를 고쳤습니다 — 셋 다 결과를 바꾸지 않습니다
> | 고친 것 | 무엇이 | 켜는 법 |
> |---|---|---|
> | **검증 청크** | 검증도 학습 배치 크기로 나눠서 잰다 | 기본 동작 (`--val-chunk` 로 조정) |
> | **그래디언트 체크포인팅** | 층 활성값을 안 들고 역전파 때 다시 계산 | `--grad-checkpoint` |
> | **bf16 혼합정밀** | 순전파를 반정밀도로. 손실은 float32 로 되돌려 계산 | `--amp bf16` |
>
> ```
> case118 · GAT 18층 · hidden 128 · batch 256      (실측 2.1 MB/표본 기준)
>                                       지금       고친 뒤
>   검증 한 번                         18.9 GB      0.54 GB
>   학습 활성값 (18층 역전파용)         9.7 GB
>     + 체크포인팅 (층 입력 + 한 층)                 0.82 GB
>     + bf16 까지                                   0.41 GB
> ```

**왜 결과가 안 바뀌는가**, 그리고 그걸 어떻게 못박았는가.

- **검증 청크** — 지도손실은 청크 크기로 가중평균하고, 물리 잔차는 표본별 합을
  누적한 뒤 마지막에 한 번만 나눕니다. 수학적으로 동일합니다. 청크
  7/16/64/전체가 모두 같은 값을 냈고(상대차 1.2e-7 = **float32 엡실론**),
  실제 학습에서 `best_epoch` 37 → 37, 시험 P/부하 15.847289% → 15.847289%
  로 그대로였습니다.
- **체크포인팅** — 역전파에서 순전파를 한 번 더 도는 것뿐이라 기울기가 같아야
  합니다. 켠 모델과 끈 모델의 **모든 파라미터 기울기**를 대조합니다.
- **bf16** — CPU 에서는 무동작입니다(bf16 커널이 다 있지도 않고 이득도 없음).
  CPU 로 낸 기존 결과와 GPU 결과를 나란히 놓을 수 있어야 하므로, `--amp bf16`
  을 줘도 CPU 학습 결과가 **비트 단위로 같은지** 확인합니다.

테스트 4개로 고정했습니다 (`tests/test_gnn.py`).

> [!WARNING] 물리 잔차는 절대 반정밀도로 재지 않습니다
> bf16 은 유효숫자가 약 3자리입니다. 그런데 전압 오차는 $`Y_{bus}`$ 를 거치며
> $`\max|Y|`$ 배(case118 은 389배)로 증폭됩니다 — [05 문서](05_dataset_generator.md) §6.1 에서
> **float32 로도** 겪은 문제입니다. 그래서 `--amp` 는 모델 순전파에만 걸고,
> 손실과 잔차는 언제나 float32 로 되돌린 뒤 계산합니다.
> 최종 보고 수치는 지금도 CPU float64 입니다 (§7.5).
>
> **fp16 은 일부러 넣지 않았습니다.** 지수부가 좁아 기울기가 조용히
> 언더플로하므로 `GradScaler` 가 필수인데, 스케일러는 손실 스케일을 자동
> 조정하다 가끔 배치를 통째로 건너뜁니다 — 재현성이 깨집니다. bf16 은
> 지수부가 float32 와 같아서 스케일러 없이 그냥 됩니다.

**속도는 아직 안 재 봤습니다.** 위 표는 메모리 이야기일 뿐이고, 189초/epoch 가
얼마나 줄어드는지는 작업 35 번(30 epoch 측정)이 알려 줍니다. 체크포인팅은
계산을 1/3 늘리므로 **오히려 느려질 수도 있습니다** — 지금 느린 원인이 정말로
메모리 압박이었을 때만 이깁니다. §8.2 의 교훈 그대로, 긴 학습을 걸기 전에
짧게 재 봅니다.
