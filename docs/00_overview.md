# 00 · 프로젝트 전체 그림 — 무엇을, 왜, 어떻게

> 이 문서는 **가장 먼저 읽는 페이지**입니다. 전력공학도 신경망도 몰라도 읽을 수
> 있게 썼습니다. 여기서 프로젝트 전체 그림을 잡고, 그다음부터 하나씩 깊이 들어갑니다.

---

## 1. 이 프로젝트를 한 문장으로

> **전력망을 가장 싸게 운전하는 방법을 계산하는 프로그램(OPF)이 있는데, 그 안에서
> 제일 오래 걸리는 부분을 신경망으로 바꿔치기하고, 그렇게 나온 답이 실제 전력망에서도
> 진짜로 통하는지 증명한다.**

이 한 문장에 낯선 단어가 두 개 있습니다. 하나씩 풀어 보겠습니다.

### 1.1 전력망은 매 순간 "계산"으로 굴러갑니다

집에 오는 전기는 발전소에서 출발해 송전선을 타고 옵니다. 그런데 전기에는
다른 상품에 없는 성질이 하나 있습니다.

> [!IMPORTANT] 전기는 저장이 안 됩니다
> 생산량과 소비량이 **매 순간 정확히 같아야** 합니다. 조금이라도 어긋나면
> 주파수가 흔들리고, 심하면 정전이 납니다. 창고에 쌓아 뒀다 파는 게 불가능합니다.

그래서 전력망 운영자는 몇 분 간격으로 이런 결정을 내려야 합니다.

- 지금 전국 수요가 60 GW다. **어느 발전소에 얼마씩 시킬 것인가?**
- 발전소마다 연료비가 다르다. **가장 싸게 맞추는 조합은?**
- 싼 발전소에 몰아주면 그쪽 송전선이 터진다. **선로 용량은 지킬 수 있나?**
- 각 지역 전압이 정상 범위(보통 0.95~1.05배)에 들어오나?

이 네 질문을 **동시에** 푸는 계산이 바로 **최적조류계산(OPF, Optimal Power Flow)**
입니다. 이름이 어렵지, 하는 일은 "제약을 지키면서 가장 싼 발전 조합 찾기"입니다.

### 1.2 그 안에서 제일 오래 걸리는 부분

OPF는 두 덩어리로 되어 있습니다.

| 덩어리 | 하는 일 | 성격 |
|---|---|---|
| **조류계산 (Power Flow)** | 발전량과 부하가 정해졌을 때 **각 지점의 전압과 선로 조류가 얼마가 되는지** 계산 | 물리 법칙. 답이 하나로 정해짐 |
| **최적화 (Optimization)** | 여러 후보 중 **가장 싼 것을 고름** | 경제적 선택. 위 계산을 수없이 반복 |

문제는 조류계산이 **비선형 연립방정식**이라 한 번에 못 푼다는 점입니다. 반복법으로
4~5번 돌려야 답이 나옵니다. 그런데 최적화는 그 조류계산을 **수백 번 다시 호출**합니다.

> [!NOTE] 그래서 이런 아이디어가 나옵니다
> 조류계산은 "입력을 넣으면 출력이 나오는 함수"입니다. 그리고 우리는 이 함수의
> 정답을 **원하는 만큼 만들어 낼 수 있습니다** (뉴턴-랩슨법으로 풀면 되니까).
> 그렇다면 정답 쌍을 잔뜩 만들어 **신경망에게 이 함수를 흉내내도록 학습시키면**
> 어떨까요? 학습이 끝나면 반복 없이 한 번의 계산으로 답이 나옵니다.

이걸 **대체모델(surrogate model)** 이라고 부릅니다. "진짜 계산 대신 쓰는 가짜"라는 뜻입니다.

### 1.3 그런데 여기에 함정이 있습니다

신경망은 근사값을 냅니다. 아주 정확해도 완벽하지는 않습니다. 그러면 이런 일이 생깁니다.

```
신경망 OPF 가 답을 냈다 → "전압 다 정상, 제약 다 만족!"
                            ↓
그 답을 진짜 전력망(정확한 조류방정식)에 넣어 보면
                            ↓
"어? 3번 모선 전압이 한계 밖인데?"
```

가짜 계산기 기준으로는 합격인데 진짜 물리에서는 불합격인 답. 이게 이 분야의
**진짜 미해결 문제**이고, 우리 연구가 겨냥하는 지점입니다.

> [!WARNING] 그래서 "빨라졌다"만으로는 논문이 안 됩니다
> 속도 논문은 이미 포화 상태입니다. 배경 논문만 봐도 260배(P4), 배치추론 399배(P2)가
> 이미 보고되어 있습니다. **속도는 결과표의 한 열**일 뿐이고, 주장은
> **"그 답이 진짜 물리에서도 통한다"** 쪽이어야 합니다.

## 2. 왜 지금 이 주제인가

이 문제가 옛날부터 있었는데 왜 지금 뜨거울까요? 이유는 **재생에너지**입니다.

| | 예전 전력망 | 지금 전력망 |
|---|---|---|
| 발전원 | 석탄·원자력·가스 — 출력을 **우리가 정함** | 태양광·풍력이 대량 — 출력이 **날씨가 정함** |
| 변동성 | 부하만 변함, 그것도 예측 가능한 패턴 | 발전도 같이 변함, 구름 하나에 출력이 급변 |
| 계산 주기 | 시간 단위로 충분 | **분·초 단위로 다시 풀어야 함** |

재생에너지가 늘수록 OPF를 더 자주, 더 많은 시나리오에 대해 풀어야 합니다.
계산이 병목이 되는 것입니다. 그래서 "OPF를 빠르게" 연구가 최근 폭발했습니다.

## 3. 우리가 밟을 5단계

처음에 세우신 5단계 계획이 문헌 구조와 정확히 맞아떨어집니다. 그대로 갑니다.

| 단계 | 무엇을 | 왜 이 순서인가 | 상태 |
|---|---|---|---|
| **1** | OPF 기본 개념 학습 + 직접 구현 | 남의 라이브러리를 쓰면 내부를 못 바꿈. 대체할 부분을 갈아끼우려면 내가 만들어야 함 | ✅ 완료 |
| **2** | pandapower와 비교해 정합성 검증 | 내 계산기가 틀리면 **정답 데이터도 틀림**. 여기서 안 잡으면 나중에 전부 무너짐 | ✅ 완료 |
| **3** | 신경망 스터디 + 학습 데이터 생성 | 학습에 쓸 (문제, 정답) 쌍을 우리 계산기로 대량 생산 | ✅ 완료 |
| **4** | 신경망으로 조류계산 대체 | 3단계 데이터로 대체모델을 학습 | 🔄 진행 중 |
| **5** | 대체모델을 넣은 OPF 완성 | 학습된 신경망을 최적화 문제 안에 삽입 | ⬜ 대기 |

> [!TIP] 이 순서의 핵심은 2단계입니다
> 신경망 프로젝트에서 가장 흔한 실패는 "데이터가 틀렸는데 모르고 학습시키는 것"입니다.
> 우리는 정답을 스스로 만들기 때문에, **정답 생성기를 먼저 기계정밀도로 검증**해
> 두면 이후 모든 실험의 신뢰도가 확보됩니다. 2단계를 건너뛰면 안 됩니다.

### 4.2 검증 결과

| 검증 항목 | 대상 | 결과 |
|---|---|---|
| 어드미턴스 행렬 | 6개 계통 (IEEE 9/14/30/57/118/300) | pandapower 와 오차 **정확히 0.0** |
| 조류계산 전압 | 6개 계통 | 최대 오차 **1e-9 ~ 1e-16 pu**, 4~5회 반복 수렴 |
| AC-OPF 발전비용 | 4개 계통 | 상대오차 **1.8e-9 ~ 1.3e-7** |
| 회귀 테스트 | 전체 | **90개 전부 통과** (1\~2단계 22 · 3단계 22 · 4단계 32 · GAT 14) |

"오차 0.0"은 반올림한 값이 아니라 **비트 단위로 같다**는 뜻입니다. 자세한 과정과
그 과정에서 잡은 버그 이야기는 [02 검증 문서](02_validation.md)에 있습니다.

### 4.3 학습 데이터

| 계통 | 표본 | 발산 | N-1 상정사고 | 생성 시간 (CPU 4코어) | 조류방정식 잔차 |
|---|---|---|---|---|---|
| case30 | 6,000 | 0% | 25.5% (38종) | 13초 | 9.8e-09 pu |
| case118 | 20,000 | 0% | 25.5% (177종) | 66초 | 2.2e-09 pu |

이 표본 수는 배경 논문 P2의 설정을 그대로 복제한 것인데, **우리 모델에는
부족했습니다.** 학습곡선을 실측해 보니 case30은 21,000, case118은 42,000에서도
아직 포화하지 않습니다. 지금은 **30,000 / 60,000** 으로 늘려 쓰고, 그러자
case30에서 MLP가 선형을 2.4배 이겼습니다 ([06 문서](06_surrogate_training.md) §5).

## 5. 흔한 오해 하나 — 이건 강화학습이 아닙니다

처음에 "강화학습을 시킬 예정"이라고 하셨는데, 4단계에서 하려는 일은 강화학습이 아니라
**지도학습(supervised learning)** 입니다. 이 구분이 중요한 이유는 난이도가 하늘과
땅 차이이기 때문입니다.

| | 지도학습 | 강화학습 |
|---|---|---|
| 필요한 것 | **(문제, 정답) 쌍** | 환경, 보상 설계, 시행착오 |
| 우리 상황 | 뉴턴-랩슨이 정답을 **무한정 만들어 줌** | 해당 없음 |
| 학습 안정성 | 높음. 대체로 잘 굴러감 | 낮음. 하이퍼파라미터에 극도로 민감 |
| 논문 난이도 | 결과가 안정적으로 나옴 | 재현조차 어려운 경우가 흔함 |

> [!IMPORTANT] 정답을 만들 수 있으면 강화학습을 쓰지 않습니다
> 강화학습은 "정답을 모르는데 시행착오로 배워야 할 때" 쓰는 도구입니다.
> 우리는 정답(뉴턴-랩슨 해)을 원하는 만큼 찍어낼 수 있으므로 지도학습이 정답입니다.
> 강화학습이 의미 있는 경우는 따로 있습니다 — 여러 시간대에 걸친 순차 의사결정
> (저장장치 운영, 발전기 기동정지 계획)입니다. **M6 이후 확장 주제로 남깁니다.**

## 6. 12개월 마일스톤

5단계를 실제 일정으로 펼치면 이렇게 됩니다.

### M1 (1개월차) — OPF 직접 구현 ✅ 완료

| 산출물 | 상태 |
|---|---|
| 계통 데이터 구조 (`case.py`) | ✅ |
| 어드미턴스 행렬 (`ybus.py`) | ✅ pandapower 와 오차 0.0 |
| 뉴턴-랩슨 조류계산 (`powerflow.py`) | ✅ 해석적 야코비안 |
| AC-OPF (`opf.py`) | ✅ 해석적 그래디언트 |

**학습한 것**: per-unit 환산, 모선 분류(슬랙/PV/PQ), 조류방정식, 뉴턴-랩슨,
KKT 조건, 라그랑주 승수 = 한계가격(LMP) → [01 문서](01_power_flow_and_opf.md)

### M2 (2개월차) — 정합성 검증 ✅ 완료

| 산출물 | 상태 |
|---|---|
| 대조 검증 프레임 (`compare.py`) | ✅ |
| 회귀 테스트 22개 | ✅ 전부 통과 |
| 검증 리포트 | ✅ [02 문서](02_validation.md) |

### M3 (3~4개월차) — 신경망 기초 + 데이터 생성 ✅ 완료

| 주 | 내용 | 상태 |
|---|---|---|
| 1–2 | 신경망 기초: 순전파/역전파, 손실함수, 최적화기, 정규화 | ✅ |
| 3–4 | PyTorch 실습: Dataset/DataLoader, 학습 루프, 재현성 | ✅ |
| 5–6 | **데이터 생성기 구현** | ✅ 완료 |
| 7–8 | **첫 MLP 대체모델 학습, 오차 분포 분석** | ✅ 완료 |

M3이 끝날 때까지 확정해야 할 설계 결정들:

- ✅ **입출력 표현**: 극좌표 $(|V|, \theta)$ 로 확정 — 배경 논문 P2와 동일하고,
  물리 잔차식을 그대로 쓸 수 있습니다
- ✅ **데이터 분포**: P2 §4.1을 그대로 복제 — 부하 P 0.80~1.20배 / Q 0.85~1.15배,
  재생에너지 0.65~1.35배, N-1 25%
- ✅ **저장 형식**: 입력 float32 / 라벨 float64
  ([05 문서](05_dataset_generator.md)에 그 이유가 있습니다)
- ✅ **정규화 방식**: 입력은 표준화, 단 **선로상태 열은 건드리지 않습니다**.
  0/1이라 이미 스케일이 맞고, 나눴다가 크게 데었습니다
  ([06 문서](06_surrogate_training.md) §7.1)
- ✅ **데이터 규모**: 학습곡선을 실측했습니다 — case30 기준 6,000표본으로는
  **부족**하고 아직 포화하지 않았습니다 ([06 문서](06_surrogate_training.md) §5)

### M4 (5~6개월차) — 대체모델 고도화 + 기준선 비교 🔄 진행 중

넘어야 할 선이 숫자로 정해져 있습니다. 네 칸을 **같은 규칙·같은 표본 수**로
다시 채운 표가 [06 문서](06_surrogate_training.md) §7.8.2 에 있습니다.

| 시험 | 선형 | 신경망 최고 | 승자 |
|---|---|---|---|
| case30 무작위 (21,000) | 1.00% | MLP **0.35%** | **신경망 2.9배** |
| case30 미지 N-1 (30,000) | 2.05% | MLP + `lstsq` **1.46%** | **신경망 1.41배** |
| case118 무작위 (60,000) | 0.608% | MLP + `lstsq` + λ **0.592%** | **신경망 1.03배** |
| case118 미지 N-1 (60,000) | **1.010%** | MLP + `lstsq` + λ 1.020% | 선형 **1.0%** |

**네 칸 중 세 칸을 이깁니다.** 남은 한 칸은 **case118 미지 N-1** 이고, 격차가
**4.1%** 까지 좁혀졌습니다.

> [!TIP] case118 무작위를 넘었습니다 — 다섯 지표를 **전부** 이깁니다
> | | 선형 | MLP + `lstsq` + λ=5e-3 | |
> |---|---|---|---|
> | Vm MAE | 3.481e-05 | **1.988e-05** | 신경망 **1.75배 승** |
> | Va MAE | 8.755e-04 | **6.247e-04** | 신경망 **1.40배 승** |
> | ΔQ [pu] | 0.0787 | **0.0683** | 신경망 **1.15배 승** |
> | **ΔP [pu]** | 0.2777 | **0.2706** | 신경망 **1.03배 승** |
> | **P/부하 %** | 0.6076 | **0.5920** | 신경망 **1.03배 승** |
>
> **ΔP 를 이긴 것이 처음입니다.** §2.2 부터 여섯 번 반복해서 "전압은 이기는데
> 유효전력 불일치에서 진다" 를 봤는데, 그 마지막 하나가 넘어갔습니다.
>
> 넘긴 방법이 정확히 진단대로였습니다 — **지는 지표를 손실에 직접 넣었습니다**
> (물리손실 λ). 모델도, 데이터도, 표본 수도 바꾸지 않았습니다.

> [!IMPORTANT] 이 칸은 **세 걸음**으로 1.14% → 0.59% 가 됐습니다
> | 걸음 | 왜 | 결과 |
> |---|---|---|
> | 초기화 `lstsq` | 이 칸에 한 번도 안 걸어 봤음 | 0.669% |
> | 선택 `phys` | 고르는 잣대 ≠ 채점 잣대 | 0.649% |
> | 물리손실 λ=5e-4 | 지는 지표가 ΔP 하나뿐 | 0.618% |
> | **λ=5e-3** | 곡선의 꼭짓점 (작업 48·50) | **0.592%** ✅ |
>
> 어느 걸음도 "모델을 키우거나 더 오래 돌린" 것이 아닙니다. 전부 진단에서
> 나왔습니다 ([06](06_surrogate_training.md) §6.1).

> [!NOTE] 남은 한 칸 — case118 미지 N-1, 격차 **1.0%** 로 닫혔습니다
> 1.020% vs 선형 1.010%. 절대값으로 **0.0098%p** 차이입니다
> (4.483% → 1.020% 로 4.4배 좁혔습니다).
>
> 여기서도 **지는 것은 ΔP 하나**이고 Vm·Va·ΔQ 는 이깁니다. 무작위 칸도
> 마지막에 넘어간 것이 ΔP 였고, 그걸 넘긴 것이 λ 였습니다.
>
> **그래서 λ 를 더 올려 봤고(작업 50), 안 됐습니다.** 7e-3·1e-2·1.5e-2 가
> 차례로 1.030 → 1.048 → 1.089 로 나빠졌습니다. 최적 λ 는 두 칸 모두
> 5e-3 이고, 곡선은 이미 돌아 있었습니다. **λ 손잡이는 끝났습니다**
> ([06](06_surrogate_training.md) §6.1).
>
> 남은 수단은 **표본 수**(§5.2 에서 case118 은 아직 포화 전),
> **case118 GAT 18층**(§8.3 에서 돌릴 수 있게 만들어 둠), **PI-GAT** 입니다.

> [!NOTE] GAT 쪽 질문도 닫혔습니다 — `lstsq` 의 덕을 거의 못 봅니다
> "GAT 에 `lstsq` 를 걸면?" 이 §6.1 의 마지막 미시도였습니다. 걸어 보니
> 2.688% → 2.527%, **1.06배**뿐입니다 (MLP 는 2.75배를 받았습니다).
> MLP + `lstsq`(1.455%)에 **1.74배 집니다.**
>
> 고른 epoch 이 **1** 입니다 — 602 epoch 을 돌렸는데 첫 한 걸음 말고는
> 쓸모가 없었습니다. GAT 는 학습률을 올리면 불안정하고(§7.7.0) 내리면
> 좋은 출발점을 못 벗어나는 사이에 끼여 있습니다.

> [!CAUTION] 모델을 고르는 잣대가 **학습 자체를 죽일 수 있습니다**
> "채점이 물리 잔차니 고르는 것도 물리로" 가 맞는 줄 알았습니다. case118 은
> 맞았고(0.669 → **0.649%**), case30 은 **0.347% → 1.681%** 로 망했습니다.
>
> 원인은 코드 한 줄입니다 — `crit` 하나가 **모델 선택·조기 종료·학습률
> 스케줄러 셋을** 다 몹니다. case30 의 물리 잔차는 epoch 마다 3% 씩 튀는데,
> 스케줄러가 그걸 "개선 없음" 으로 읽고 학습률을 **125배** 깎은 뒤
> epoch 237 에 멈춰 세웠습니다. 그 순간까지 지도손실은 계속 내려가는
> 중이었습니다 ([06](06_surrogate_training.md) §6.1).
>
> **교훈: 선택 지표는 남은 개선폭보다 조용해야 합니다.** 계통이 작을수록
> 물리 잔차가 시끄럽습니다 — case118 은 흔들림 0.22%, case30 은 3.07%.

> [!CAUTION] 학습률을 낮춰 좋은 출발점을 지키려던 시도는 실패했습니다
> `lstsq` 초기화가 첫 epoch 에 망가지는 것을 보고 lr 을 2e-3 → 2e-4 로
> 낮췄습니다. **출발점은 지켜졌지만(case118 6.08% → 1.40%) 최종 성적은
> 네 번 중 네 번 다 나빠졌습니다.** case30 은 epoch 2 에서 멈춰
> 1.455% 라는 승리를 통째로 잃었습니다 ([06](06_surrogate_training.md) §6.1).
>
> 첫 epoch 의 폭주는 낭비가 아니라 **탐색 비용**이었습니다. 최종 성적을
> 정하는 것은 "출발점이 살아남았나" 가 아니라 **"본체가 얼마나 배웠나"** 입니다.

> [!TIP] 두 번째 칸을 이긴 것은 GAT 가 아니었습니다
> 오래 매달린 그래프 신경망(최고 2.61%)이 아니라, **선형 최소제곱 해에서
> 출발시킨 MLP** 가 **1.46%** 로 선형(2.05%)을 이겼습니다 ([06](06_surrogate_training.md) §6.1).
>
> 모델도 데이터도 epoch 수도 그대로이고 **출발점만** 바꿨는데 4.00% → 1.46%
> 입니다. "모델을 더 좋게" 보다 "좋은 데서 출발" 이 크게 이긴 사례입니다.
> 게다가 13분 걸렸습니다 — GAT 는 54\~71분입니다.

> [!NOTE] 두 가지 "미지 N-1 수치" 를 혼동하지 마세요
> 위 표의 **1.01% / 4.48%** 는 시험 분할 **전체 평균**입니다. [06](06_surrogate_training.md) §4.1 에 나오는
> **2.62% / 16.38%** 는 같은 시험 분할을 토폴로지로 쪼갠 뒤 **미지 N-1 표본만**
> 골라 잰 값이고, 20,000 표본 · 옛 선택 규칙에서 나왔습니다. 통계 자체가
> 다르므로(전체 평균 vs 부분집합, 게다가 §4.1 은 표본별로 나눈 뒤 평균)
> 나란히 놓으면 안 됩니다.

그래프 어텐션(GAT) 첫 시도는 실패했고, 원인을 둘 찾았습니다. 둘 다 모델이 아니라
**우리가 실험을 세운 방식** 쪽이었습니다.

- **층 수가 계통 지름보다 작았습니다** (§7.7). 3층 GAT는 case30 모선의 56%만
  봅니다. 8층으로 올리자 4.02% → 1.10%. 필요한 층 수는 그래프의 **N-1 최악
  지름**이 정해 줍니다 — case30은 8, case118은 18입니다.
- **미지 N-1에서 모델 선택 규칙이 망가져 있었습니다** (§7.8). 검증 분할에도
  못 본 고장이 들어 있어 검증 손실이 몇 epoch 만에 바닥에 닿는데, 거기서
  "최고 검증 시점"을 고르니 1,500 중 **34**번째 모델이 뽑혔습니다.
- **학습률이 구조에 안 맞았습니다** (§7.7.0). GAT 는 lr 2e-3 에서 깊어지면
  발산했는데 5e-4 로 낮추자 4.90% → **2.69%** 가 됐습니다. 대조군을 돌려 보니
  이득의 **거의 전부가 학습률**이었고 깊이(8층→12층)는 1.03배뿐이었습니다.
  같은 lr 2e-3 은 MLP 에서는 반대로 **꼭 필요한** 값입니다 — **한 하이퍼파라미터가
  모델 구조에 따라 정반대로 작동합니다.**

| 항목 | 내용 |
|---|---|
| 기준선 구현 | DC 조류계산, 고정점 선형화 |
| 모델 비교 | ~~MLP / 잔차연결 MLP~~ (M3에서 완료) / **GNN(그래프 신경망)** |
| 물리 정보 결합 | 손실함수에 조류방정식 잔차 항 추가 (PINN 계열) |
| 합격선 | 위 표의 선형을 넘을 것 — **case118 무작위 0.61%, case118 미지 N-1 1.01%** |

> [!NOTE] 기준선을 먼저 재는 이유
> 신경망이 단순한 선형근사보다 못하면 쓸 이유가 없습니다. 기준선 숫자를 먼저
> 확보해 두면, 신경망이 그보다 못할 때 **일찍** 알아챌 수 있습니다.
>
> 실제로 그렇게 됐습니다. 선형 최소제곱 기준선을 먼저 재 보니 case30에서
> $R^2 = 0.987$ 이 나왔고, 순수 MLP가 거기에 거의 못 미쳤습니다. 그래서
> M4로 미뤄 뒀던 **잔차연결(선형 지름길)을 앞당겨** 기본값으로 넣었습니다.
> 기준선을 나중에 쟀다면 이 설계 변경을 몇 달 늦게 알았을 것입니다.

### M5 (7~8개월차) — 대체모델을 넣은 OPF

여기가 진짜 어려운 지점입니다. 방법이 세 가지 있고, **전부 시도해서 비교하는 것
자체가 논문의 실험 섹션**이 됩니다.

| 방식 | 구조 | 장점 | 단점 |
|---|---|---|---|
| **(a) 제약 대체** | 신경망을 미분가능한 제약식으로 OPF에 삽입 | 개념적으로 가장 깔끔 | 신경망이 비볼록 → 수렴 불안정 |
| **(b) 종단간 예측** | 부하 → OPF 해를 직접 예측 | 가장 빠름 | 제약 위반을 통제할 수 없음 |
| **(c) 웜스타트** | 신경망 예측을 기존 솔버의 초기값으로 사용 | **항상 정확한 해** 보장 | 속도 향상 폭이 작음 |

> [!TIP] (c)부터 하세요
> 구현이 가장 쉽고, 반드시 동작하며, **최악의 경우에도 논문에 쓸 결과가 남는**
> 안전장치입니다. 우리 `solve_acopf(warm_start=True)` 가 이미 이 구조라서,
> 지금 뉴턴-랩슨이 하는 자리에 신경망을 넣기만 하면 됩니다.
> 그다음 (a) → (b) 순으로 확장합니다.

### M6 (9~10개월차) — 실행가능성 보장 + 일반화

- **실행가능성 복원**: 신경망 OPF 해를 물리적으로 실행가능하게 사영·보정
- **일반화 실험**: 부하 분포가 바뀌면? 선로 하나가 고장 나면(N-1)? 계통이 커지면?
- **불확실성 정량화**: 예측 신뢰구간, **언제 신경망을 믿으면 안 되는가**

## 7. 논문으로 무엇을 주장할 것인가

배경 논문 4편을 정독한 뒤 방향을 확정했습니다. 논거는 [04 문서](04_paper_review.md) §5에
자세히 있고, 여기서는 결론만 옮깁니다.

> [!IMPORTANT] 확정된 방향
> **A(통합 벤치마크)를 기반으로 깔고, B(입력볼록 그래프 신경망)를 목표로 삼는다.**
>
> - **A는 반드시 나옵니다.** 기존 세 방식을 같은 계통·같은 데이터·같은 지표로
>   비교한 연구가 아직 없습니다. 구현과 비교표만으로도 한 편이 됩니다. 안전망입니다.
> - **B가 성공하면 주 논문이 됩니다.** "그래프 구조 + 물리정보 + 볼록성"을
>   동시에 만족하는 대체모델은 아직 아무도 만들지 못했습니다.
> - **A를 먼저 하는 게 중요합니다.** A를 구현하면서 B의 난점이 무엇인지 몸으로
>   알게 됩니다. 이론부터 시작하면 헤맵니다.

## 8. 계산 자원 — RTX 5060 도입

현재 개발 환경은 **RTX 5060**(sm_120, 8GB) + CUDA 12.8 스택입니다 (2026-08 도입 완료).
학습은 GPU(float32), 최종 잔차 측정은 CPU(float64)로 나눠 돕니다 — 소비자용
지포스는 배정밀도가 단정밀도의 1/64 속도이기 때문입니다
([06 문서](06_surrogate_training.md) §7.5). 클라우드 쪽 보조 환경은 CPU 4코어입니다.

> [!WARNING] PyTorch 설치할 때 반드시 확인할 것
> **RTX 5060** — Blackwell GB206, 3,840 CUDA 코어, 8 GB GDDR7,
> compute capability **sm_120**.
>
> sm_120은 최신 아키텍처라 **CUDA 12.8 이상으로 빌드된 PyTorch**가 필요합니다.
> 구버전 휠에는 sm_120용 커널이 아예 없어서
> `CUDA error: no kernel image is available for execution on the device` 로 죽습니다.
>
> `pip install torch --index-url https://download.pytorch.org/whl/cu128`
>
> 배경 논문 P2가 RTX 5090(같은 sm_120) + CUDA 12.8 + PyTorch 2.9.1+cu128로 돌렸으므로
> **동일 스택이 그대로 적용**됩니다. 논문 재현 시 환경 불일치 걱정이 없습니다.

### 8.1 8 GB VRAM으로 충분한가 — case30 은 충분, case118 GAT 는 아닙니다

P2가 쓴 가장 큰 모델이 hidden 256 / GAT 4층 / 헤드 4 / batch 64 / 118노드입니다.
이 규모면 VRAM 1 GB도 쓰지 않습니다. case30 은 12층까지 올려도 여유가 있습니다.

> [!WARNING] case118 GAT 18층은 8 GB 에 안 들어갑니다
> 처음에는 "8 GB 면 남는다"고 적었지만, 실제로 재 보니 아니었습니다
> ([06 문서](06_surrogate_training.md) §8.2). 역전파용으로 붙들고 있어야 하는
> 간선 텐서가 층당 **61.3 MB** 이라 18층이면 활성값만 **5.3~7.4 GB** 이고,
> 여기에 데이터셋과 옵티마이저 상태가 얹힙니다. 실측 결과 epoch 당 **189초**,
> 1,500 epoch 완주에 **78.7시간**이 나와 보류했습니다.
>
> case118 GAT 를 돌리려면 bf16 혼합정밀이나 층 수를 12로 낮추는 등
> **메모리를 줄이는 수단이 먼저** 필요합니다.

| 작업 | CPU로 가능? | 실측 |
|---|---|---|
| 데이터 생성 (조류계산 수만 건) | ✅ | case118 20,000건에 66초 (4코어) |
| MLP 학습 | ✅ | case30 30,000표본·1,500 epoch 이 5분 |
| GAT 학습 (case30) | ⚠️ | 8층이 GPU로 50분. CPU면 하루 단위 |
| GAT 학습 (case118 18층) | ❌ | GPU로도 epoch 당 189초 — 완주 78.7시간 (§8.2) |
| 대규모 하이퍼파라미터 탐색 | ❌ | GPU 필요 |

> [!NOTE] 진짜 병목은 GPU가 아니라 데이터 생성입니다
> 조류계산 1건(case118)이 15~28 ms이고, 이 계산은 **GPU를 쓸 수 없습니다**.
> 그래서 데이터 생성기를 처음부터 `multiprocessing` 으로 병렬화해 만들었고,
> 지금 4코어로 20,000건에 66초가 나옵니다.
> **GPU가 필요해지는 지점은 4단계 모델 학습, 특히 GAT부터입니다.**

### 8.2 속도를 측정할 때 반드시 나눠 잴 것

P2가 관찰한 중요한 사실 하나: **단건 추론은 GPU가 CPU보다 느립니다.**
그래프가 작아서 GPU 커널을 띄우는 오버헤드가 실제 연산보다 크기 때문입니다.

그래서 속도표를 만들 때는 **CPU 단건 / GPU 단건 / GPU 배치** 세 가지를 나눠
재야 합니다. 하나로 뭉뚱그리면 리뷰어가 바로 지적합니다.

실제로 재 봤더니 그대로였습니다 ([06 문서](06_surrogate_training.md) §8.1) —
학습에서도 **배치 64면 GPU가 CPU에 집니다.** 갱신 한 번에 걸리는 시간이 GPU는
배치를 64배 키워도 거의 그대로인데(1.2배 안), CPU는 배치에 정직하게 비례해
늘어납니다(9.6\~25배). 지금 모델이 GPU에게 너무 작다는 뜻이고, 뒤집으면
**모델을 키우는 비용이 거의 0**이라는 뜻이기도 합니다.

## 10. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 신경망 정확도가 단순 선형근사보다 못함 | **실제로 일어났습니다** — case118에서 선형 0.61% vs MLP 1.14%. M3에서 기준선을 먼저 잰 덕분에 M4 전에 발견 ([06](06_surrogate_training.md) §5.3). 이후 `lstsq` 초기화·선택규칙·물리손실(λ=5e-3)로 **0.592%** 가 되어 다섯 지표 전부에서 넘었습니다 ([06](06_surrogate_training.md) §6.1). 다만 야코비안 선형화라는 더 센 기준선이 case30 에서는 우리를 10배 이깁니다 ([06](06_surrogate_training.md) §7.9) |
| 신경망 OPF가 수렴하지 않음 | 방식 (c) 웜스타트를 안전장치로 확보 |
| 데이터 분포가 비현실적이라는 지적 | 배경 논문 P2의 샘플링 설정을 그대로 복제 → 인용 가능 |
| 큰 계통에서 우리 최적화 솔버가 느림 | IPOPT(`cyipopt`) 도입 검토 — 현재 SLSQP는 case118에서 ~44초 |
| 논문 기여점이 약함 | M3 끝에 방향 재확정 (§7) |
| **실험 설계가 틀려 결론이 뒤집힘** | 지금까지 가장 자주 일어난 실패입니다. 기준선이 수치적으로 망가졌고([06](06_surrogate_training.md) §7.6), 모델 선택 규칙이 미지 N-1에서 망가졌습니다(§7.8). 둘 다 모델이 아니라 비교 방식 쪽이었습니다. 대응 — **비교 대상과 비교 규칙도 테스트로 고정**하고, 결과가 너무 좋으면 의심합니다 |
