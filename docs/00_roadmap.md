# NN-OPF 프로젝트 로드맵 (12개월, 논문 작성 목표)

## 0. 한 줄 정의

> **최적조류계산(OPF) 안에서 가장 비싼 부분인 조류방정식 풀이를 신경망 대체모델로
> 바꿔, 정확도를 유지하면서 계산시간을 줄이고, 그 해가 실제 물리계통에서도
> 실행가능함을 보인다.**

## 1. 목표 진술을 정확히 만들기

원래 적어 주신 5단계는 방향이 맞습니다. 다만 논문이 되려면 **"무엇을 새로
주장할 것인가"** 가 한 문장으로 나와야 합니다. 다음 셋 중 하나를 고르세요.

| 후보 | 주장 | 난이도 | 논문성 |
|---|---|---|---|
| **A. 속도** | NN 대체모델로 OPF 계산시간을 N배 줄였다 | 낮음 | 약함 (이미 많음) |
| **B. 실행가능성** | NN-OPF 해가 **물리 제약을 지키도록** 보정/보장하는 구조를 제안 | 중간 | **강함** |
| **C. 일반화** | 부하/토폴로지가 바뀌어도 재학습 없이 동작하는 대체모델 | 높음 | 매우 강함 |

**권장: B → (여유되면) C.**
이유는 참고 사이트 정리 문서(§3.2)에 적어 둔 그 경고 때문입니다 — 근사모델
OPF 의 해는 진짜 조류방정식에서 제약을 위반할 수 있고, **그걸 어떻게 다룰
것인가가 이 분야의 실제 미해결 지점**입니다. 속도만으로는 리뷰어를 설득하기
어렵습니다.

> ※ 이건 지금 확정하지 않아도 됩니다. M3 끝(4개월차)에 실측 데이터를 보고
> 정하는 게 정확합니다. 다만 **"속도만"은 피한다**는 것만 미리 정해 둡시다.

## 2. 용어 정리 — 지도학습 vs 강화학습

처음에 "강화학습을 시킬 예정"이라고 하셨는데, 적어 주신 4단계
(*"NN을 활용하여 OPF 내의 조류계산 부분을 대체(학습)"*)는 **강화학습이 아니라
지도학습(supervised learning)** 입니다.

| | 지도학습 | 강화학습 |
|---|---|---|
| 데이터 | (입력, 정답) 쌍 — 뉴턴-랩슨이 정답을 무한정 만들어 줌 | 환경과 상호작용하며 보상 수집 |
| 우리 4단계 | **여기에 해당** — 조류계산 결과가 곧 정답 라벨 | 해당 없음 |
| 학습 난이도 | 낮음, 안정적 | 높음, 불안정 |

**조류계산 대체는 100% 지도학습 문제입니다.** 정답을 우리가 원하는 만큼
생성할 수 있는데 굳이 강화학습을 쓸 이유가 없습니다.

강화학습이 의미 있는 경우는 따로 있습니다:
- 다시간대 순차 의사결정 (저장장치 운영, 기동정지 계획)
- 명시적 모델이 없는 환경

**결론: 4단계는 지도학습으로 갑니다.** 강화학습은 M6 이후 확장 주제로 남깁니다.

### M3 (3~4개월차) — NN 기초 스터디 + 데이터 생성 파이프라인

| 주 | 내용 |
|---|---|
| 1–2 | 신경망 기초: 순전파/역전파, 손실함수, 최적화기(SGD/Adam), 정규화 |
| 3–4 | PyTorch 실습: Dataset/DataLoader, 학습 루프, 체크포인트, 재현성 |
| 5–6 | **데이터 생성기 구현** — 부하 샘플링 → 뉴턴-랩슨 → (입력, 라벨) 쌍 저장 |
| 7–8 | 첫 MLP 대체모델 학습, 오차 분포 분석 |

**핵심 결정 사항** (M3 끝까지 확정)
- 입력/출력 표현: 극좌표 $(|V|, \theta)$ vs 직교좌표 $(e, f)$
- 정규화 방식: 표준화 vs min-max vs per-unit 그대로
- 데이터 분포: 부하를 어떻게 샘플링할 것인가 (균등? 실측 프로파일?)
- 데이터 규모: 계통 크기별 필요 샘플 수 (수렴 곡선으로 결정)

### M4 (5~6개월차) — 대체모델 고도화 + 기준선 비교

| 항목 | 내용 |
|---|---|
| 기준선 구현 | DC 조류계산, 고정점 선형화 (Bolognani 2015 형태) |
| 모델 비교 | MLP / 잔차연결 MLP / GNN |
| 물리 정보 결합 | 손실함수에 조류방정식 잔차 항 추가 (PINN 계열) |
| 평가 | 참고자료 기준선 대비: 전압 0.2%, 전력 1.5% 를 넘을 것 |

### M5 (7~8개월차) — 대체모델을 포함한 OPF (5단계)

여기가 진짜 어려운 지점입니다. 세 가지 방식이 있고, **전부 시도해서 비교하는
것 자체가 논문의 실험 섹션**이 됩니다.

| 방식 | 구조 | 장점 | 단점 |
|---|---|---|---|
| **(a) 제약 대체** | NN 을 미분가능 제약식으로 OPF 에 삽입 | 기존 NLP 솔버 재사용 | NN 이 비볼록 → 수렴 불안정 |
| **(b) 종단간 예측** | 부하 → OPF 해를 직접 예측 | 가장 빠름 | 제약 위반 통제 어려움 |
| **(c) 웜스타트** | NN 예측을 NLP 초기치로 사용 | **항상 정확한 해** 보장 | 속도 향상 폭이 작음 |

> **실전 조언**: (c) 부터 하세요. 구현이 가장 쉽고, 반드시 동작하며,
> "최악의 경우에도 논문에 쓸 결과가 남는" 안전장치가 됩니다.
> 그 다음 (a) → (b) 순으로 확장하세요.

### M6 (9~10개월차) — 실행가능성 보장 + 일반화

- **실행가능성 복원**: NN-OPF 해를 물리적으로 실행가능하게 사영(projection)/보정
- **일반화 실험**: 부하 분포 이동, N-1 상정사고, 계통 크기 확장
- **불확실성 정량화**: 예측 신뢰구간, 언제 NN 을 믿으면 안 되는가
