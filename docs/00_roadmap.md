# NN-OPF 프로젝트 로드맵 (12개월, 논문 작성 목표)

## 0. 한 줄 정의

> **최적조류계산(OPF) 안에서 가장 비싼 부분인 조류방정식 풀이를 신경망 대체모델로
> 바꿔, 정확도를 유지하면서 계산시간을 줄이고, 그 해가 실제 물리계통에서도
> 실행가능함을 보인다.**

## 1. 논문 방향 — 배경 논문 4편에서 도출

배경 논문 4편을 전문 정독했습니다. 상세는 [`05_paper_review.md`](05_paper_review.md).
네 편이 하나의 이야기로 이어지고, 그 끝에 **빈칸이 세 개** 있습니다.

| 논문 | 가진 것 | 없는 것 |
|---|---|---|
| **P2 PI-GAT** (Energies 2026) | 물리 일관성, 그래프, 미지 N-1 일반화 | **비볼록 GNN → OPF 삽입 불가** |
| **P3 ICNN-OPF** (arXiv 2024) | 볼록성, 수렴·최적성 증명 | MLP 수준, 정확도 3~10배 손실, 고정 토폴로지 |
| **P4 NN-MILP** (arXiv 2026) | 정확한 인코딩, 전역최적, 사후 AC 검증 | 이진변수 폭발, 전압 제약만, 고정 토폴로지 |

<!-- 빈칸 -->
> **GAP 1** — 정확한 대체모델은 OPF에 못 넣고, OPF에 넣을 수 있는 대체모델은 부정확하다.
> "그래프 + 물리정보 + 볼록성"을 동시에 만족하는 대체모델이 **아직 없다**.
>
> **GAP 2** — N-1/토폴로지 일반화가 조류계산에서 멈추고 **OPF 단계로 이어지지 않는다**.
>
> **GAP 3** — 세 방식을 **같은 계통·같은 데이터·같은 지표**로 비교한 연구가 없다.

### 논문 후보

| 안 | 내용 | 난이도 | 실패 위험 | 기여도 |
|---|---|---|---|---|
| **A. 통합 벤치마크** | MILP / ICNN / 웜스타트를 IEEE 30·118·300에서 동일 조건 최초 비교 + 오픈소스 | 중 | **낮음** | 중 (GAP 3) |
| **B. IC-GNN** | 입력볼록 그래프 신경망 — P2의 그래프·물리정보 + P3의 볼록성 | 높음 | 중 | **높음** (GAP 1) |
| **C. 상정사고 인지 NN-OPF** | N-1 상태를 입력으로 받는 대체모델을 OPF에 삽입 | 높음 | 중 | 높음 (GAP 2) |
| **D. MILP 확장** | P4 인코딩에 선로 조류 한계 추가 (P4 자신의 한계) | 중 | 낮음 | 중 |

**확정 전략: A를 기반으로 깔고 B를 목표로 삼는다.**

* **A는 반드시 나옵니다.** 세 방식 구현 + 비교표만으로 한 편이 됩니다. 안전망.
* **B가 성공하면 주 논문**이 됩니다. 관건은 ICNN의 볼록성 조건($W^{(y)}\ge 0$,
  볼록·비감소 활성화)을 **그래프 어텐션 층에 적용할 수 있는가**입니다.
  어텐션 가중치가 입력 의존적이라 그대로는 안 되고, 바로 거기서 기여가 나옵니다.
* B가 막히면 A + C 또는 A + D로 선회합니다.

> **A를 먼저 하는 이유**: A를 만들면서 P3·P4를 직접 구현하게 되고, 그 과정에서
> B의 난점을 몸으로 알게 됩니다. 이론부터 시작하면 헤맵니다.

### 절대 하지 말 것

**"속도만" 주장하지 마세요.** P1(리뷰)이 정리한 것만 봐도 속도 논문은 이미
포화입니다. P4는 260배, P2는 배치추론 399배를 이미 보고했습니다.
속도는 **표의 한 열**이지 논문의 주장이 아닙니다.

## 2. 용어 정리 — 지도학습 vs 강화학습

처음에 "강화학습을 시킬 예정"이라고 하셨는데, 적어 주신 4단계
(*"NN을 활용하여 OPF 내의 조류계산 부분을 대체(학습)"*)는 **강화학습이 아니라
지도학습(supervised learning)** 입니다.

| | 지도학습 | 강화학습 |
|---|---|---|
| 데이터 | (입력, 정답) 쌍 — 뉴턴-랩슨이 정답을 무한정 만들어 줌 | 환경과 상호작용하며 보상 수집 |
| 우리 4단계 | **여기에 해당** — 조류계산 결과가 곧 정답 라벨 | 해당 없음 |
| 학습 난이도 | 낮음, 안정적 | 높음, 불안정 |

**조류계산 대체는 100% 지도학습 문제입니다.** 정답을 우리가 원하는 만큼
생성할 수 있는데 굳이 강화학습을 쓸 이유가 없습니다.

강화학습이 의미 있는 경우는 따로 있습니다:
- 다시간대 순차 의사결정 (저장장치 운영, 기동정지 계획)
- 명시적 모델이 없는 환경

**결론: 4단계는 지도학습으로 갑니다.** 강화학습은 M6 이후 확장 주제로 남깁니다.

### M5 (7~8개월차) — 대체모델을 포함한 OPF (5단계)

여기가 진짜 어려운 지점입니다. 세 가지 방식이 있고, **전부 시도해서 비교하는
것 자체가 논문의 실험 섹션**이 됩니다.

| 방식 | 구조 | 문제 유형 | 최적성 | 논문 |
|---|---|---|---|---|
| **(c) 웜스타트** | NN 예측을 NLP 초기치로 사용 | NLP | ✅ 원문제 그대로 | Baker 2019 |
| **(a1) MILP 인코딩** | ReLU를 Big-M으로 **정확히** 인코딩 | **MILP** | ✅ 대체문제 전역최적 | **P4** |
| **(a2) ICNN 볼록화** | Softplus ICNN → 볼록 부등식 제약 | **볼록계획** | ✅ 수렴·최적성 증명 | **P3** |
| (a3) 순진한 NN 삽입 | 일반 NN을 그대로 제약에 | 비볼록 NLP | ❌ **아무 보장 없음** | P3의 B3 |
| **(b) 종단간 예측** | 부하 → OPF 해 직접 예측 | 없음 | ❌ 사영/보정 필수 | P1 §5.1 |

<!-- 핵심 설계 결정 -->
> ### 🔑 이 프로젝트에서 가장 중요한 설계 결정 하나
>
> **"전압을 예측하지 말고, 전압 제약까지의 여유를 예측하라." (P3 §4.B)**
>
> $V = f(p,q)$ 를 그대로 등식제약으로 넣으면, $f$ 가 볼록이어도 **등식제약은 비볼록**
> 입니다(볼록함수의 등위집합은 볼록집합이 아님). 대신 전압 한계를 다시 쓰면
>
> $$V^{min}\le V\le V^{max} \iff \left|V - \tfrac{V^{min}+V^{max}}{2}\right| \le \tfrac{V^{max}-V^{min}}{2}$$
>
> 이고, NN이 학습할 대상을 **좌변 전체**로 바꾸면 제약이 $f(p,q)\le \Delta V$ 라는
> **볼록 부등식**이 됩니다. 등식을 부등식으로 바꾸는 순간 볼록성이 살아납니다.

**구현 순서**: (c) → (a1) → (a2) → (b)

* (c)는 이미 `solve_acopf(warm_start=True)` 구조가 있습니다. NN만 끼우면 끝.
* (a1)은 Gurobi 학생 라이선스가 필요합니다. 미리 신청해 두세요.
* (a2)는 **상용 솔버 없이 PyTorch autograd만으로** 원-쌍대 경사법 구현이 됩니다 (P3 §5.C).
* 출력 축소 아이디어: 전 모선 전압 대신 **최소 전압만** 예측 → 뉴런 20→5,
  속도 3~15배 (P4 §3.E "Model 2"). 대부분의 운전 결정은 전압 하한 위반이 좌우합니다.

> **실전 조언**: (c) 부터 하세요. 구현이 가장 쉽고, 반드시 동작하며,
> "최악의 경우에도 논문에 쓸 결과가 남는" 안전장치가 됩니다.
> 그 다음 (a) → (b) 순으로 확장하세요.

> 적용**됩니다. 논문 재현 시 환경 불일치 걱정이 없다는 뜻입니다.

### 8GB VRAM으로 충분한가 — 충분합니다

P2가 쓴 최대 모델이 hidden 256 / GAT 4층 / 헤드 4 / batch 64 / 118노드입니다.
이 규모면 VRAM 1 GB도 안 씁니다. 우리 계획(IEEE 30·118·300)에서 VRAM은 병목이
아닙니다.

| 작업 | RTX 5060으로 | 비고 |
|---|---|---|
| MLP 대체모델 학습 | ✅ 여유 | 분 단위 |
| GAT / PI-GAT 학습 | ✅ 여유 | P2 기준 300~500 epoch |
| ICNN 학습 | ✅ 여유 | 구조가 더 단순 |
| 하이퍼파라미터 탐색 | ✅ 가능 | λ 민감도 곡선 등 |
| **배치 추론 벤치마크** | ✅ **여기서 GPU 진가** | P2: batch-64에서 257~399배 |

### 진짜 병목은 GPU가 아니라 데이터 생성입니다

| | 시간 | 장치 |
|---|---|---|
| 조류계산 1건 (case118) | 15~28 ms | **CPU** (pandapower는 GPU 미지원) |
| 20,000 시나리오 생성 | 약 5~9분 (단일코어) | CPU |
| 미지 N-1 분할까지 포함 | 수십 분 | CPU |

> 데이터 생성은 GPU가 전혀 도와주지 못합니다. `multiprocessing` 으로 코어 수만큼
> 병렬화하는 게 유일한 가속입니다. **데이터 생성기를 처음부터 병렬로 짜세요.**

> 💡 P2가 관찰한 것 하나 더: **단건 추론은 GPU가 CPU보다 느립니다.**
> 그래프가 작아서 커널 런치 오버헤드가 연산보다 크기 때문입니다.
> 속도 표를 만들 때 반드시 **CPU 단건 / GPU 단건 / GPU 배치** 세 가지를 나눠 재세요.

## 6. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| NN 정확도가 선형근사보다 못함 | 기준선을 먼저 정확히 측정 (M4). P3 기준 ICNN은 선형화보다 100~200배 정확 |
| NN-OPF 가 수렴하지 않음 | (c) 웜스타트를 안전장치로 확보 + (a2) ICNN은 **수렴이 증명**되어 있음 |
| **B안(IC-GNN)이 이론적으로 막힘** | A안(통합 벤치마크)이 이미 논문 한 편. C/D안으로 선회 |
| 데이터 분포가 비현실적 | P2 §4.1 설정을 그대로 인용 — 문헌 근거가 확보된 샘플링 |
| 대형 계통에서 우리 NLP 솔버가 느림 | IPOPT(`cyipopt`) 도입 검토 — 현재 SLSQP 는 case118에서 ~44초 |
| **Gurobi 라이선스 미확보** | (a1) MILP 방식이 막힘. **학생 라이선스 미리 신청** (무료, 학교 이메일) |
| **PyTorch가 RTX 5060을 못 잡음** | cu128 이상 빌드 필수 (§5). 구버전 휠은 `no kernel image` 로 죽음 |
| 논문 기여점이 약함 | §1에서 이미 GAP 3개 확정. M4 끝에 B안 가능성 재판정 |
