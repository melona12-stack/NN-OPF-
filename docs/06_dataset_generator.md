## 0. 왜 GPU 오기 전에 만들었나

조류계산은 **순수 CPU 작업**입니다. pandapower도 우리 뉴턴-랩슨도 GPU를 쓰지 않으므로,
데이터 생성만큼은 RTX 5060을 기다릴 이유가 없습니다.

| 작업 | 장치 | 지금 가능? |
|---|---|---|
| **데이터 생성 (조류계산)** | **CPU 전용** | ✅ 66초 |
| MLP 학습 | CPU도 되지만 느림 | ⚠️ |
| GAT / PI-GAT 학습 | GPU | ❌ |
| 배치 추론 벤치마크 | GPU | ❌ |

게다가 데이터 생성기는 **설계 결정이 가장 많이 들어가는 부분**입니다 — 샘플링 분포,
N-1 처리, 미지 N-1 분할, 발산 기록. 이걸 검증하는 게 전부 CPU 작업이라 지금이 적기였습니다.

## 2. 입출력 규격 (P2 §3.1 그대로)

### 노드 특징 8개

| 순서 | 특징 | 설명 |
|---|---|---|
| 0–1 | `P_load`, `Q_load` | 유효/무효 부하 |
| 2 | `P_ren` | **재생에너지** 발전 (변동 큼) |
| 3 | `P_gen` | 기존 급전가능 발전 (변동 작음) |
| 4 | `V_set` | 전압 설정값 |
| 5–7 | `isPQ`, `isPV`, `isref` | 모선 종류 원-핫 |

> **슬랙 모선의 `P_gen`은 0입니다.** 슬랙 출력은 조류방정식이 결정하는 종속변수라
> 추론 시점에 알 수 없기 때문입니다. 모델은 `isref` 원-핫으로 그 모선이 슬랙임을
> 알고 스스로 추론해야 합니다.

### 엣지 특징 7개

`r`, `x`, `sh`(충전 서셉턴스), `tap`, `status`, `g`, `b`

임피던스 `r,x`와 그로부터 유도되는 어드미턴스 `g,b`를 **둘 다** 넣습니다.
비선형 변환을 모델이 따로 학습하지 않아도 되게 하려는 것입니다.

브랜치마다 `f→t`, `t→f` 양방향 엣지를 둡니다. 물리 선로는 무향이지만
메시지 패싱은 방향이 필요합니다.

### 라벨

모선별 $(V_m, \theta)$. 위상은 라디안.

### N-1 인코딩

**고장 선로를 그래프에서 제거하지 않고 `status=0` 특징으로만 표시**합니다.
그래프 구조가 고정되어 배치 추론이 가능하고, 그래프 재구성 오버헤드가 없습니다.

## 3. 물리 잔차 — 4단계 손실함수의 원형

`physics_residual()`은 지금은 "라벨이 진짜 조류해인가" 검증에 쓰지만,
**`Vm, Va` 자리에 신경망 예측을 넣으면 그대로 P2의 물리정보 손실**이 됩니다.

핵심은 **지정값이 있는 곳에만 잔차를 거는 것**입니다.

| 모선 | 잔차에 포함 | 이유 |
|---|---|---|
| **PQ** | $\Delta P$, $\Delta Q$ | P, Q 모두 지정값 |
| **PV** | $\Delta P$ **만** | Q는 조류방정식이 정하는 종속변수 |
| **슬랙** | **없음** | P, Q 모두 종속변수 |

이 구분을 놓치고 모든 모선에 잔차를 걸면 학습이 잘못된 방향으로 갑니다.

> 고정 병렬 소자(커패시터/리액터)는 $Q^{sp}$에 넣지 **않습니다**. $Y_{bus}$ 대각에
> 이미 들어 있어 계산된 $\hat Q$ 쪽에 반영되므로, 양쪽에 넣으면 이중계산입니다.
> — 2단계 검증에서 겪은 그 shunt 회계 문제와 같은 이슈입니다.

## 4. 만들면서 잡은 문제 두 가지

### 4.1 float32 저장 정밀도가 $Y_{bus}$를 거치며 증폭

전압을 float32로 저장했더니 조류방정식 잔차가 남았습니다. 원인을 재보니 정확히
$\max|Y| \times \epsilon_{\text{float32}}$ 였습니다.

| 계통 | float64 잔차 | float32 저장 후 | $\max\|Y\|$ | 예측 바닥 |
|---|---|---|---|---|
| case30 | 4.6e-09 | 3.2e-06 | 87.5 | 1.0e-05 |
| case118 | 1.3e-09 | 1.6e-05 | 388.9 | 4.6e-05 |
| case300 | 8.8e-09 | **2.5e-04** | 2438.6 | 2.9e-04 |

case300의 2.5e-04는 **측정하려는 신경망 잔차(P2 목표 ~1e-3)와 같은 자릿수**라
무시할 수 없었습니다.

**해결**: 입력을 float32로 **내린 뒤 그 값으로 풀고**, 라벨만 float64로 저장.
그러면 "저장된 입력"과 "라벨을 만든 입력"이 정확히 일치합니다. → 잔차 1e-9.

```python
# 저장 전에 내리는 게 아니라, 내린 값으로 푼다
f32 = lambda a: a.astype(np.float32).astype(np.float64)
return Scenario(Pd=f32(Pd), Qd=f32(Qd), ...)
```

### 4.2 발전 배분에서 잘린 몫이 전부 슬랙으로

비례 배분 후 `np.clip`만 하면 **상한에 걸린 만큼이 슬랙 한 모선에 떨어집니다.**

case300에서 재생E 비중을 낮춰 봤더니 **표본 100%가 발산**했습니다. 원인:

| 설정 | 재생E 41대 | 기존 27대 (Pmax 13,651) | **슬랙 부담** | 슬랙 Pmax |
|---|---|---|---|---|
| 재생E 60% | 14,637 MW | 8,178 MW | 0 MW | 2,399 MW |
| 재생E 30% | 7,536 MW | **13,651 MW (상한)** | 1,627 MW | 2,399 MW |
| 재생E 15% | 3,768 MW | **13,651 MW (상한)** | **5,395 MW** | **2,399 MW** ❌ |

슬랙 하나가 5,395 MW를 공급해야 하는데 상한이 2,399 MW — 물리적으로 불가능합니다.

**해결 두 가지**

1. **`allocate_dispatch()`** — 잘린 뒤 남은 부족/과잉을 **여유(headroom)에 비례해
   재배분**합니다. 실제 급전이 하는 일과 같고 몇 번만 돌면 수렴합니다.
2. **`check_capacity_feasible()`** — 용량이 모자란 설정은 **데이터를 만들기 전에**
   원인과 대안을 알려주며 막습니다.

```
case300: 발전 용량이 부족해 사실상 전 표본이 발산합니다 (기저 부하 23,526 MW 대비 3,947 MW 모자람).
  재생E 41대 정격 3,529 MW + 기존 27대 상한 13,651 MW + 슬랙 상한 2,399 MW
  -> ren_capacity_frac(0.15)을 올리거나, ren_bus_frac(0.6)을 낮춰 급전가능 발전기를
     남기거나, p_load_hi(1.05)를 낮추세요.
```

검사는 2단계입니다.

| 단계 | 판정 기준 | 동작 |
|---|---|---|
| **오류** | 기저 부하 · 평균 재생출력에서도 용량 부족 | 생성 전 중단 |
| **경고** | 최악 조합(최대 부하 × 최소 재생출력)에서만 부족 | 진행하되 알림 |

> **왜 2단계인가**: 처음엔 최악 조합만으로 판정했더니, 실제로 97% 수렴하는
> case300 P2 기본 설정까지 막아 버렸습니다. 두 극단이 동시에 오는 일은 드뭅니다.

## 5. 재현성 — 데이터를 옮기지 않는 이유

* 표본 `i`의 난수를 `default_rng([seed, i])`로 **독립적으로** 만듭니다.
  → **워커 수나 청크 크기를 바꿔도 표본 `i`는 항상 동일**합니다 (테스트로 고정).
* 재생에너지 모선 지정, 상정사고 선택도 전부 시드에서 결정됩니다.

그래서 **데이터 파일을 커밋하지도, 컴퓨터 간에 나르지도 않습니다.**
새 컴퓨터에서 한 줄이면 똑같은 데이터가 나옵니다.

```bash
.venv/bin/python scripts/s02_generate_dataset.py
```

`data/manifest.json`에 "무엇을 어떤 품질로 만들었는지"만 기록으로 남깁니다.

### 저장 형식

특징 대부분은 시나리오마다 바뀌지 않습니다(전압 설정값, 모선 종류, 선로 임피던스).
**바뀌는 것만 표본별로 저장**하고 나머지는 한 번만 저장합니다.
`node_features()` / `edge_attr()`가 학습 시점에 P2 형식 텐서로 조립합니다.

| | dtype | 이유 |
|---|---|---|
| 입력 (`Pd`, `Qd`, `p_ren`, `p_gen`) | float32 | 이미 float32로 내려서 푼 값이라 손실 없음 |
| 라벨 (`Vm`, `Va`) | **float64** | $Y_{bus}$를 거치며 오차가 $\max\|Y\|$배로 증폭됨 (§4.1) |

## 6. 분할 — 두 가지

| 분할 | 방식 | 목적 |
|---|---|---|
| **무작위** | 표본을 70/15/15로 섞음 | P2의 표준 분할 |
| **미지 N-1** | **고장 유형**을 먼저 나눔 | 본 적 없는 토폴로지 일반화 |

미지 N-1 분할에서는 테스트용 고장이 **학습·검증에 단 한 번도 등장하지 않습니다.**
무작위 분할보다 훨씬 엄격하며, "본 적 없는 계통 구성에서도 되는가"를 재는 유일한
방법입니다 (P2 §4.7).

겹침이 0인지는 생성할 때마다 자동 확인하고 테스트로도 고정했습니다 —
조용히 겹치면 실험 자체가 무의미해지기 때문입니다.
